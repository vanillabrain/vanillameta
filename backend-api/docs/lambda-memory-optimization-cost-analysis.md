# Lambda 메모리 최적화 비용 영향 분석 (T01_S04)

## 개요
본 문서는 Lambda 메모리를 512MB에서 1024MB로 증가시킨 T01_S04 최적화의 비용 영향을 분석합니다.

## 메모리 설정 변경사항
- **이전 설정**: 512MB
- **새로운 설정**: 1024MB (2배 증가)
- **적용 범위**: 모든 환경 (dev, prod)

## 비용 구조 분석

### AWS Lambda 요금 구조
AWS Lambda는 다음 두 요소에 따라 과금됩니다:
1. **요청 수**: 요청당 $0.0000002 (첫 100만 요청은 무료)
2. **GB-초**: 메모리 할당량 × 실행 시간

### 메모리별 GB-초 요금 (ap-northeast-2 기준)
- **512MB (0.5GB)**: $0.0000083345 per GB-second
- **1024MB (1GB)**: $0.0000166667 per GB-second

### 비용 증가 계산

#### 시나리오 1: 실행 시간이 동일한 경우
- 메모리 2배 증가 → 비용 2배 증가
- 월 1,000,000 요청, 평균 500ms 실행 시간 가정:
  - **512MB**: (0.5GB × 0.5초 × 1,000,000) × $0.0000083345 = **$2.08**
  - **1024MB**: (1GB × 0.5초 × 1,000,000) × $0.0000166667 = **$8.33**
  - **비용 증가**: 월 $6.25 (약 300% 증가)

#### 시나리오 2: 성능 향상으로 실행 시간 단축
메모리 증가로 30% 성능 향상 가정 (실행 시간 500ms → 350ms):
- **1024MB (최적화)**: (1GB × 0.35초 × 1,000,000) × $0.0000166667 = **$5.83**
- **512MB 대비 증가**: 월 $3.75 (약 180% 증가)
- **성능 향상 효과**: 월 $2.50 절약

## 예상 성능 향상 효과

### 1. 콜드 스타트 시간 단축
- **목표**: 30% 이상 개선
- **효과**: 사용자 경험 향상, API 응답 시간 개선

### 2. 처리량 증가
- CPU 성능이 메모리에 비례하여 향상
- 동시 요청 처리 능력 개선

### 3. 가비지 컬렉션 효율성
- 더 많은 메모리로 GC 압박 감소
- 전체적인 실행 성능 안정화

## 모니터링 지표

### CloudWatch 메트릭
- **MemoryUsage**: 실제 메모리 사용량 추적
- **ColdStartCount**: 콜드 스타트 빈도 모니터링
- **InitDuration**: 초기화 시간 측정
- **Duration**: 전체 실행 시간 추적

### 알람 설정
- 메모리 사용률 90% 초과 시 알람
- 빈번한 콜드 스타트 발생 시 알람
- 응답 시간 2초 초과 시 알람

## 비용 최적화 권장사항

### 1. 단계적 최적화
1. **1주차**: 1024MB로 설정하여 성능 개선 확인
2. **2주차**: 실제 메모리 사용량 분석
3. **3주차**: 필요시 메모리 크기 미세 조정 (768MB, 896MB 등)

### 2. 환경별 차등 적용
- **개발 환경**: 512MB 유지 (비용 절약)
- **프로덕션**: 1024MB 적용 (성능 우선)

### 3. 지속적인 모니터링
- 월별 비용 리포트 검토
- 성능 지표와 비용의 균형점 찾기
- 사용량이 적은 시간대의 메모리 스케일링 검토

## 투자수익률(ROI) 분석

### 비용 vs 성능 트레이드오프
- **추가 비용**: 월 $3.75 ~ $6.25
- **성능 향상**: 응답 시간 30% 개선
- **사용자 경험**: 개선된 응답성
- **개발 생산성**: 빠른 개발 사이클

### 비즈니스 가치
1. **사용자 만족도 향상**: 빠른 응답 시간
2. **시스템 안정성**: 메모리 여유도 확보
3. **확장성 준비**: 트래픽 증가 대비
