# M03: DuckDB 및 Modern ORM 전환

## 마일스톤 개요

VanillaMeta의 메타데이터 데이터베이스를 SQLite에서 DuckDB로 전환하고, TypeORM을 최신 ORM으로 교체하는 대규모 기술 스택 업그레이드입니다.

### 핵심 변경사항
- **메타데이터 DB**: SQLite → DuckDB
- **ORM**: TypeORM → Drizzle ORM (권장)
- **쿼리 빌더**: Knex.js는 고객 DB 쿼리용으로 유지

### 프로젝트 컨텍스트
- **개발 환경**: 1인 개발, 빅뱅 전환 방식
- **운영 환경**: Docker 컨테이너, AWS Lambda + EFS
- **전환 영향**: 기존 고객 서비스 영향 없음

## 목표 및 성공 지표

### 주요 목표

1. **OLAP 성능 향상**
   - 대시보드 쿼리 성능 10배 이상 향상
   - 복잡한 집계 쿼리 실행 시간 90% 단축
   - 메모리 사용량 최적화

2. **개발자 경험 개선**
   - Raw query 실행 편의성 극대화
   - TypeScript 타입 안정성 강화
   - 쿼리 빌더의 직관적인 API

3. **인프라 현대화**
   - Docker 환경 최적화
   - Lambda EFS 통합 개선
   - 배포 프로세스 간소화

### 성공 지표

| 지표 | 현재 (SQLite + TypeORM) | 목표 (DuckDB + Drizzle) |
|------|------------------------|-------------------------|
| 대시보드 로딩 시간 | 3-5초 | 0.3-0.5초 |
| 복잡한 집계 쿼리 | 10-30초 | 1-3초 |
| 메모리 사용량 | 512MB | 256MB |
| 개발 생산성 | 기준점 | 30% 향상 |
| 코드 복잡도 | 높음 | 중간 |

## 주요 변경사항

### 1. 데이터베이스 전환

**SQLite → DuckDB**
- 컬럼 지향 저장소로 OLAP 성능 극대화
- 병렬 쿼리 실행 지원
- 고급 분석 함수 네이티브 지원
- 파일 기반 → 파일 기반 (마이그레이션 용이)

### 2. ORM 전환

**TypeORM → Drizzle ORM**
- TypeScript 퍼스트 설계
- 컴파일 타임 타입 안정성
- SQL-like 쿼리 빌더
- Raw query 실행 최적화
- DuckDB 공식 지원

### 3. 아키텍처 개선

**변경 전**
```
TypeORM (메타데이터) + Knex.js (고객 DB)
↓
SQLite (메타데이터) + 다중 DB (고객)
```

**변경 후**
```
Drizzle ORM (메타데이터) + Knex.js (고객 DB)
↓
DuckDB (메타데이터) + 다중 DB (고객)
```

### 4. 주요 모듈 영향

| 모듈 | 변경 수준 | 주요 작업 |
|------|-----------|-----------|
| auth | 중간 | 엔티티 → 스키마 변환 |
| user | 중간 | 리포지토리 패턴 재구현 |
| dashboard | 높음 | 복잡한 쿼리 최적화 |
| widget | 높음 | 집계 쿼리 재작성 |
| dataset | 높음 | Raw query 실행 개선 |
| connection | 낮음 | Knex.js 유지 |
| database | 중간 | DuckDB 연결 추가 |
