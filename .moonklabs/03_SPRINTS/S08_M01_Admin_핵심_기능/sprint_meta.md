# Sprint Meta: S08 - Admin 핵심 기능 (Phase 1)

## Sprint Information
- **Sprint ID**: S08
- **Sprint Name**: Admin 핵심 기능 구현
- **Duration**: 4주
- **Status**: planned
- **Milestone**: M01 - MVP 안정화 및 핵심 기능 강화

## Sprint Goals
1. 사용자 관리 및 승인 프로세스 구현
2. 역할 기반 접근 제어(RBAC) 시스템 구축
3. 기본 감사 로그 기능 구현

## Tasks

### T01_S08: Admin 대시보드 UI 구축
- Admin 전용 레이아웃 설계
- 네비게이션 메뉴 구성
- 대시보드 홈 화면 (통계 위젯)
- 권한에 따른 메뉴 표시/숨김

### T02_S08: 사용자 관리 기능 구현
- 사용자 목록 API 및 UI
- 페이지네이션, 검색, 필터 기능
- 사용자 상세 정보 조회
- 사용자 추가/수정/삭제 기능
- 사용자 상태 관리 (활성/비활성/대기)

### T03_S08: 사용자 승인 프로세스
- 회원가입 시 승인 대기 상태 구현
- 승인 대기 사용자 별도 관리 UI
- 승인/거부 처리 로직
- 이메일 알림 연동
- 일괄 승인 기능

### T04_S08: RBAC 시스템 기초 구현
- Role 엔티티 및 기본 역할 생성
- Permission 엔티티 및 권한 정의
- User-Role 매핑 구현
- 권한 검증 미들웨어/가드 구현

### T05_S08: 역할 관리 UI
- 역할 목록 및 상세 화면
- 역할별 권한 설정 UI
- 사용자별 역할 할당
- 역할 생성/수정/삭제 (Super Admin only)

### T06_S08: 기본 감사 로그 구현
- AuditLog 엔티티 설계
- 로그인/로그아웃 추적
- 주요 CRUD 작업 로깅
- 로그 저장 및 조회 API

### T07_S08: 감사 로그 UI
- 로그 조회 화면 (테이블 뷰)
- 필터링 (날짜, 사용자, 액션 타입)
- 로그 상세 보기
- 로그 내보내기 (CSV)

### T08_S08: 권한 통합 테스트
- 모든 API 엔드포인트 권한 검증
- 프론트엔드 권한 기반 UI 제어
- E2E 권한 시나리오 테스트
- 권한 관련 문서화

## Dependencies
- 기존 인증 시스템 (JWT)
- 사용자 모델 확장
- 이메일 서비스

## Success Criteria
- [ ] 관리자가 사용자를 효율적으로 관리 가능
- [ ] 가입 승인 프로세스 정상 작동
- [ ] 5개 기본 역할이 제대로 동작
- [ ] 모든 주요 활동이 로깅됨
- [ ] 권한 없는 접근 시 적절한 차단

## Risks & Mitigations
- **Risk**: 기존 시스템과의 권한 충돌
  - **Mitigation**: 점진적 마이그레이션 전략
- **Risk**: 성능 저하 (권한 체크)
  - **Mitigation**: 권한 캐싱 전략 수립

## Notes
- 기존 사용자는 기본적으로 Editor 역할 부여
- Super Admin은 최초 1명만 수동 설정
- 모든 권한 변경은 감사 로그에 기록
