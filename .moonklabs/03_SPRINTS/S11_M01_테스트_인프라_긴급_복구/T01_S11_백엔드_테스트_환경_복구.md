# T01: 백엔드 테스트 환경 복구

## 태스크 정보
- **태스크 ID**: T01_S11
- **스프린트**: S11 - 테스트 인프라 긴급 복구
- **우선순위**: 긴급/높음
- **예상 소요 시간**: 1-2일
- **담당자**: Backend Developer

## 개요

현재 백엔드의 Jest 테스트 환경이 손상되어 있어 테스트 실행이 불가능한 상태입니다. 이를 긴급히 복구하여 안정적인 테스트 실행 환경을 구축해야 합니다.

## 목표

1. Jest 설정 파일 검토 및 수정
2. 테스트 의존성 문제 해결
3. TypeORM 테스트 환경 설정
4. 기본 테스트 실행 확인

## 기술적 세부사항

### Jest 설정 예시
```typescript
// jest.config.ts
import type { Config } from 'jest';

const config: Config = {
  moduleFileExtensions: ['js', 'json', 'ts'],
  rootDir: 'src',
  testRegex: '.*\\.spec\\.ts$',
  transform: {
    '^.+\\.(t|j)s$': 'ts-jest',
  },
  collectCoverageFrom: [
    '**/*.(t|j)s',
  ],
  coverageDirectory: '../coverage',
  testEnvironment: 'node',
  moduleNameMapping: {
    '^@/(.*)$': '<rootDir>/$1',
  },
  setupFilesAfterEnv: ['<rootDir>/test/setup.ts'],
};

export default config;
```

### TypeORM 테스트 설정
```typescript
// test/setup.ts
import { DataSource } from 'typeorm';

export const testDataSource = new DataSource({
  type: 'sqlite',
  database: ':memory:',
  entities: [__dirname + '/../src/**/*.entity{.ts,.js}'],
  synchronize: true,
  logging: false,
});
```

## 테스트 스크립트

### package.json 스크립트 추가
```json
{
  "scripts": {
    "test": "jest",
    "test:watch": "jest --watch",
    "test:cov": "jest --coverage",
    "test:debug": "node --inspect-brk -r tsconfig-paths/register -r ts-node/register node_modules/.bin/jest --runInBand",
    "test:e2e": "jest --config ./test/jest-e2e.json"
  }
}
```

## 검증 방법

1. **기본 테스트 실행**
   ```bash
   cd backend-api
   yarn test
   ```

2. **커버리지 확인**
   ```bash
   yarn test:cov
   ```

3. **Watch 모드 확인**
   ```bash
   yarn test:watch
   ```

## 리스크 및 대응 방안

### 의존성 충돌
- **리스크**: 기존 패키지들과의 버전 충돌
- **대응**: 필요시 특정 버전으로 고정하거나 resolutions 사용

### TypeORM 설정 문제
- **리스크**: 복잡한 엔티티 관계로 인한 테스트 환경 설정 어려움
- **대응**: 단순화된 테스트용 엔티티부터 시작

### 환경 변수 문제
- **리스크**: 테스트 환경의 환경 변수 누락
- **대응**: `.env.test` 파일 생성 및 테스트 설정 분리
