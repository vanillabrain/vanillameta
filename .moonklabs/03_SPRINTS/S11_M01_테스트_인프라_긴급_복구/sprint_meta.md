# S11: 테스트 인프라 긴급 복구

Sprint ID: S11
Milestone: M01
우선순위: 긴급/높음
예상 기간: 1주

## 개요

현재 프로젝트의 테스트 인프라가 손상되어 있어 긴급 복구가 필요합니다. 백엔드와 프론트엔드 모두에서 테스트 실행이 불가능한 상태이며, 이는 코드 품질과 안정성에 심각한 위험을 초래합니다.

## 목표

1. 백엔드 Jest 테스트 환경 복구
2. 프론트엔드 테스트 환경 설정
3. CI/CD 파이프라인의 테스트 단계 복구
4. 최소한의 테스트 커버리지 확보 (핵심 모듈 50%)

## 주요 작업

### T01: 백엔드 테스트 환경 복구
- Jest 설정 파일 검토 및 수정
- 테스트 의존성 문제 해결
- TypeORM 테스트 환경 설정

### T02: 프론트엔드 테스트 환경 구축
- React Testing Library 설정
- Jest 설정 추가
- 기본 컴포넌트 테스트 작성

### T03: Mock 및 Fixture 정리
- 테스트용 Mock 데이터 구조화
- Database Mock 설정
- API Mock 설정

### T04: CI/CD 테스트 단계 복구
- GitHub Actions 워크플로우 수정
- 테스트 실행 스크립트 검증
- 테스트 리포트 설정

### T05: 핵심 모듈 테스트 작성
- Auth 모듈 기본 테스트
- Dashboard 모듈 기본 테스트
- Widget 모듈 기본 테스트

## 성공 기준

1. `yarn test` 명령이 백엔드와 프론트엔드에서 정상 실행
2. CI/CD 파이프라인에서 테스트 통과
3. 핵심 모듈의 테스트 커버리지 50% 이상
4. 테스트 실행 시간 5분 이내

## 리스크 및 대응 방안

- **리스크**: 의존성 충돌로 인한 추가 지연
  - **대응**: 필요시 의존성 버전 고정 및 격리

- **리스크**: 기존 코드의 테스트 불가능한 구조
  - **대응**: 최소한의 리팩토링만 수행, 테스트 가능한 부분부터 진행

## 체크포인트

- [ ] 백엔드 테스트 실행 가능
- [ ] 프론트엔드 테스트 실행 가능
- [ ] CI/CD 파이프라인 통과
- [ ] 테스트 문서 업데이트
