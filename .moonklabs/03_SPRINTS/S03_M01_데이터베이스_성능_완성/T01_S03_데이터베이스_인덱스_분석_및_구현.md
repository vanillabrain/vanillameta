### 인덱스 구현 패턴
```typescript
// TypeORM 인덱스 데코레이터 사용
@Entity()
@Index('idx_user_email', ['email'], { unique: true })
@Index('idx_user_workspace', ['workspaceId', 'createdAt'])
export class User {
  @PrimaryGeneratedColumn('uuid')
  id: string;

  @Column()
  email: string;

  @Column()
  workspaceId: string;

  @CreateDateColumn()
  createdAt: Date;
}

// 복합 인덱스 예시
@Index('idx_query_user_workspace_created', ['userId', 'workspaceId', 'createdAt'])

  // ...
}
```

```typescript
// backend-api/src/database/utils/index-analyzer.ts
export class IndexAnalyzer {
  async analyzeTableIndexes(tableName: string): Promise<IndexRecommendation[]> {
    // 쿼리 패턴 분석
    const queryPatterns = await this.collectQueryPatterns(tableName);
    
    // 카디널리티 분석
    const cardinality = await this.analyzeCardinality(tableName);
    
    // 인덱스 추천
    return this.recommendIndexes(queryPatterns, cardinality);
  }
}
```

### 3단계: 인덱스 성능 테스트
```typescript
// backend-api/src/database/tests/index-performance.spec.ts
describe('Index Performance Tests', () => {
  it('should improve user lookup performance', async () => {
    const beforeIndex = await measureQuery('SELECT * FROM users WHERE email = ?');
    await createIndex('idx_user_email');
    const afterIndex = await measureQuery('SELECT * FROM users WHERE email = ?');
    
    expect(afterIndex.executionTime).toBeLessThan(beforeIndex.executionTime * 0.5);
  });
});
```

### 4단계: 마이그레이션 작성
```typescript
// backend-api/src/database/migrations/xxxx-add-performance-indexes.ts
export class AddPerformanceIndexes implements MigrationInterface {
  async up(queryRunner: QueryRunner): Promise<void> {
    // User 테이블 인덱스
    await queryRunner.createIndex('user', new TableIndex({
      name: 'idx_user_email',
      columnNames: ['email'],
      isUnique: true
    }));
    
    // Query 테이블 복합 인덱스
    await queryRunner.createIndex('query', new TableIndex({
      name: 'idx_query_user_workspace_created',
      columnNames: ['user_id', 'workspace_id', 'created_at']
    }));
  }
  
  async down(queryRunner: QueryRunner): Promise<void> {
    await queryRunner.dropIndex('user', 'idx_user_email');
    await queryRunner.dropIndex('query', 'idx_query_user_workspace_created');
  }
}
```

## 주의사항

### 인덱스 오버헤드
- 과도한 인덱스는 INSERT/UPDATE 성능 저하
- 인덱스 크기와 메모리 사용량 고려
- 사용하지 않는 인덱스 정기적 정리

### 데이터베이스별 고려사항
```typescript
// MySQL/MariaDB
- InnoDB 클러스터 인덱스 특성 고려
- 인덱스 힌트 사용 가능

// PostgreSQL
- 부분 인덱스(Partial Index) 활용
- BRIN 인덱스 고려 (시계열 데이터)

// SQLite (개발 환경)
- 인덱스 제한사항 확인
- PRAGMA 최적화 설정
```
