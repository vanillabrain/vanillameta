# T01_S10: 백업 시스템 설계

## 태스크 개요
- **Sprint**: S10 - Admin 운영 기능
- **Priority**: High
- **Estimated Time**: 3일
- **Dependencies**: S3 스토리지 설정, AWS IAM 권한

## 목표
VanillaMeta 시스템의 포괄적인 백업 전략을 수립하고 백업 시스템 아키텍처를 설계합니다.

## 상세 요구사항

### 1. 백업 전략 수립
- **전체 백업 (Full Backup)**
  - 데이터베이스 전체 덤프
  - 애플리케이션 설정 파일
  - 사용자 업로드 파일
  - 주기: 주 1회 (일요일 새벽 2시)

- **증분 백업 (Incremental Backup)**
  - 변경된 데이터만 백업
  - 주기: 일 1회 (매일 새벽 3시)
  
- **부분 백업 (Partial Backup)**
  - 특정 대시보드/위젯
  - 특정 사용자 데이터
  - 수동 실행 가능

### 2. 백업 스토리지 설정 (AWS S3)
- **버킷 구조**
  ```
  vanillameta-backups/
  ├── full/
  │   ├── YYYY/MM/DD/
  │   └── backup_YYYYMMDD_HHMMSS.tar.gz.enc
  ├── incremental/
  │   ├── YYYY/MM/DD/
  │   └── inc_YYYYMMDD_HHMMSS.tar.gz.enc
  └── metadata/
      └── backup_manifest.json
  ```

- **스토리지 클래스**
  - Standard: 최근 30일
  - Standard-IA: 30일-90일
  - Glacier: 90일 이상

### 3. 백업 메타데이터 관리
- **데이터베이스 스키마**
  ```sql
  CREATE TABLE backup_metadata (
    id VARCHAR(50) PRIMARY KEY,
    backup_type ENUM('full', 'incremental', 'partial'),
    status ENUM('pending', 'running', 'completed', 'failed'),
    started_at TIMESTAMP,
    completed_at TIMESTAMP,
    file_size BIGINT,
    s3_location VARCHAR(500),
    checksum VARCHAR(64),
    retention_date DATE,
    created_by VARCHAR(50),
    metadata JSON
  );
  ```

- **메타데이터 JSON 구조**
  ```json
  {
    "tables": ["table1", "table2"],
    "file_count": 150,
    "compression_ratio": 0.65,
    "encryption_algorithm": "AES-256",
    "database_version": "8.0.35",
    "app_version": "1.2.3"
  }
  ```

### 4. 백업 스케줄러 구현
- **스케줄링 방식**: AWS EventBridge + Lambda
- **백업 규칙**
  - 전체 백업: 매주 일요일 02:00 KST
  - 증분 백업: 매일 03:00 KST (월-토)
  - 보존 기간: 30일 (configurable)
  - 최대 백업 수: 100개

## 기술적 구현사항

### 1. 백엔드 API 설계

#### 백업 설정 API
```typescript
// POST /api/admin/backup/config
interface BackupConfig {
  scheduleEnabled: boolean;
  fullBackupCron: string;          // "0 2 * * 0"
  incrementalBackupCron: string;   // "0 3 * * 1-6"
  retentionDays: number;           // 30
  compressionLevel: number;        // 6 (1-9)
  encryptionEnabled: boolean;
  notificationEnabled: boolean;
  maxConcurrentBackups: number;    // 1
}
```

#### 백업 작업 관리 API
```typescript
// GET /api/admin/backup/jobs
interface BackupJob {
  id: string;
  type: 'full' | 'incremental' | 'partial';
  status: 'pending' | 'running' | 'completed' | 'failed';
  progress: number;
  startedAt: Date;
  estimatedCompletion: Date;
  errorMessage?: string;
}

// POST /api/admin/backup/trigger
interface BackupTriggerRequest {
  type: 'full' | 'incremental' | 'partial';
  options?: {
    tables?: string[];
    dashboardIds?: string[];
    userIds?: string[];
  };
}
```

### 3. AWS 리소스 설정

#### EventBridge 규칙
```json
{
  "Name": "vanillameta-full-backup",
  "ScheduleExpression": "cron(0 19 ? * SUN *)",
  "State": "ENABLED",
  "Targets": [{
    "Id": "backup-lambda",
    "Arn": "arn:aws:lambda:region:account:function:backup-executor"
  }]

```

#### S3 버킷 정책
```json
{

  "Statement": [{
    "Effect": "Allow",

    "Action": ["s3:PutObject", "s3:GetObject", "s3:DeleteObject"],
    "Resource": "arn:aws:s3:::vanillameta-backups/*"
  }]
}
```

### 4. 데이터베이스 마이그레이션

```sql
-- migration: 001_create_backup_metadata.sql
CREATE TABLE backup_metadata (
  id VARCHAR(50) PRIMARY KEY,
  backup_type ENUM('full', 'incremental', 'partial') NOT NULL,
  status ENUM('pending', 'running', 'completed', 'failed') NOT NULL,
  started_at TIMESTAMP NULL,
  completed_at TIMESTAMP NULL,
  file_size BIGINT NULL,
  s3_location VARCHAR(500) NULL,
  checksum VARCHAR(64) NULL,
  retention_date DATE NOT NULL,
  created_by VARCHAR(50) NOT NULL,
  metadata JSON NULL,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  INDEX idx_backup_type (backup_type),
  INDEX idx_status (status),
  INDEX idx_retention_date (retention_date)
);

CREATE TABLE backup_config (
  id INT PRIMARY KEY AUTO_INCREMENT,
  config_key VARCHAR(100) UNIQUE NOT NULL,
  config_value JSON NOT NULL,
  updated_by VARCHAR(50) NOT NULL,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);
```

## 보안 고려사항

### 1. 암호화
- **전송 중 암호화**: HTTPS/TLS 1.3
- **저장 시 암호화**: AES-256 (AWS KMS)
- **키 관리**: AWS KMS + 로테이션

### 2. 접근 제어
- **IAM 역할**: 최소 권한 원칙
- **API 인증**: JWT + Role-based access
- **감사 로깅**: 모든 백업 작업 로깅

### 3. 데이터 검증
- **체크섬 검증**: SHA-256
- **무결성 확인**: 백업 후 즉시 검증
- **복구 테스트**: 주기적 복구 시뮬레이션

## 성능 고려사항

### 1. 백업 성능
- **병렬 처리**: 테이블별 분할 백업
- **압축**: gzip 레벨 6 (속도/크기 균형)
- **대역폭 제한**: 업무 시간 외 실행

### 2. 모니터링
- **진행률 추적**: 실시간 진행률 표시
- **리소스 모니터링**: CPU/메모리/디스크 사용률
- **알림**: 실패/지연 시 즉시 알림
