# Task: 파일 시스템 구조 정리

## Description
프로젝트의 파일 시스템 구조를 정리하여 테스트 인프라의 안정성을 높입니다. 중복된 파일, 사용하지 않는 파일, 잘못된 위치에 있는 파일들을 정리하고, 일관된 디렉토리 구조를 확립합니다.

## Goal / Objectives
- 불필요한 파일 및 중복 파일 제거
- 테스트 파일들의 일관된 구조 확립
- 프로젝트 디렉토리 구조의 표준화
- 파일 경로 문제로 인한 테스트 실패 요인 제거

## Acceptance Criteria
- [ ] 중복된 테스트 설정 파일 정리 완료
- [ ] 사용하지 않는 테스트 파일 제거
- [ ] 테스트 관련 디렉토리 구조 표준화
- [ ] 임시 파일 및 빌드 아티팩트 정리
- [ ] .gitignore 업데이트로 불필요한 파일 추적 방지

## Subtasks
- [ ] 백엔드 테스트 디렉토리 구조 분석 및 정리
- [ ] 프론트엔드 테스트 디렉토리 구조 분석 및 정리
- [ ] 중복된 설정 파일 식별 및 제거
- [ ] 사용하지 않는 테스트 파일 식별 및 제거
- [ ] 임시 파일 및 로그 파일 정리
- [ ] .gitignore 파일 업데이트
- [ ] README 및 문서 파일 정리

## 기술 가이드

### 코드베이스 주요 구조
- **백엔드 테스트**: `/backend-api/test/` 디렉토리
- **프론트엔드 테스트**: `/frontend-web/src/**/*.test.*` 패턴
- **설정 파일**: `jest.config.*`, `tsconfig.*` 파일들
- **임시 파일**: `dist/`, `node_modules/`, `coverage/` 등

### 정리 대상 파일들
- 중복된 Jest 설정 파일 (`jest.config.js`, `jest.config.fast.js`)
- 오래된 테스트 파일 및 스냅샷
- 빌드 아티팩트 (`dist/`, `build/`)
- 로그 파일 (`*.log`, `test-results/`)
- 임시 백업 파일 (`*.backup`, `*.tmp`)

### 표준 디렉토리 구조
```
backend-api/
├── test/
│   ├── unit/          # 단위 테스트
│   ├── integration/   # 통합 테스트
│   ├── e2e/          # E2E 테스트
│   ├── helpers/      # 테스트 헬퍼
│   └── fixtures/     # 테스트 데이터
```

### 파일 이름 규칙
- 테스트 파일: `*.spec.ts`, `*.test.ts`
- Mock 파일: `*.mock.ts`
- Helper 파일: `*.helper.ts`
- Fixture 파일: `*.fixture.ts`

## 구현 노트

### 단계별 접근법
1. 현재 파일 시스템 구조 분석
2. 중복 및 불필요한 파일 식별
3. 백엔드 테스트 디렉토리 정리
4. 프론트엔드 테스트 디렉토리 정리
5. 설정 파일 통합 및 정리
6. .gitignore 업데이트

### 파일 정리 기준
- **보관**: 현재 사용 중인 테스트 파일
- **통합**: 기능이 중복되는 설정 파일
- **제거**: 6개월 이상 사용되지 않은 파일
- **백업**: 중요하지만 현재 사용하지 않는 파일

### 안전성 고려사항
- 파일 삭제 전 Git 히스토리 확인
- 중요 파일의 백업 생성
- 점진적 정리로 테스트 실행 영향 최소화
- 팀원과의 파일 사용 현황 확인

### 성능 고려사항
- 불필요한 파일 제거로 빌드 속도 향상
- 테스트 실행 시 파일 스캔 시간 단축
- IDE 인덱싱 성능 개선
