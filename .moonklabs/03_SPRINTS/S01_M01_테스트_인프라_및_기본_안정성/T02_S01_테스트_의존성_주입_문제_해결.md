# Task: 테스트 의존성 주입 문제 해결

## Description
NestJS 테스트 환경에서 발생하는 의존성 주입 관련 문제들을 해결합니다. 주로 Repository, Service, 외부 모듈의 Mock 처리 및 테스트 모듈 구성에서 발생하는 문제들을 수정하여 안정적인 테스트 실행 환경을 구축합니다.

## Goal / Objectives
- NestJS 테스트 모듈의 의존성 주입이 정상적으로 작동
- Repository 및 Service Mock이 올바르게 구성되어 테스트 격리 보장
- 외부 의존성(Redis, Database 등)이 테스트 환경에서 적절히 Mock 처리

## 기술 가이드

### 코드베이스 주요 인터페이스
- **테스트 모듈 구성**: `Test.createTestingModule()` 패턴
- **Repository Mock**: `/backend-api/test/helpers/repository.mock.ts`
- **Service 의존성**: `/backend-api/src/*/service/*.service.ts`
- **외부 모듈**: Cache, Redis, CloudWatch 관련 서비스

### 기존 패턴 분석
```typescript
// 표준 테스트 모듈 패턴
const module: TestingModule = await Test.createTestingModule({
  providers: [
    ServiceClass,
    {
      provide: RepositoryToken,
      useValue: mockRepository,
    },
  ],
}).compile();
```

### 통합 지점
- **TypeORM Repository**: `getRepositoryToken()` 사용한 Mock 주입
- **Redis 모듈**: CacheModule Mock 처리
- **CloudWatch**: AWS SDK Mock 처리
- **외부 API**: HTTP 클라이언트 Mock 처리

### Mock 패턴 표준화
- Repository Mock: 기본 CRUD 메서드 Mock 구현
- Service Mock: 필수 비즈니스 로직 Mock 구현
- External Service Mock: 외부 API 응답 Mock 구현
