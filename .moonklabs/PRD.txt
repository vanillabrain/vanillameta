# VanillaMeta Product Requirements Document (PRD) - Updated

## Overview

VanillaMeta는 기업용 비즈니스 인텔리전스(BI) 웹 애플리케이션으로, 코드 작성 없이 다양한 데이터베이스에 연결하여 데이터를 시각화하고 인사이트를 도출할 수 있는 플랫폼입니다. 스타트업부터 대기업까지 다양한 규모의 조직이 데이터 기반 의사결정을 내릴 수 있도록 지원합니다.

### 해결하고자 하는 문제
- **기술 장벽**: 비기술직 직원들이 데이터 분석을 위해 개발자나 데이터 분석가에게 의존해야 하는 문제
- **데이터 사일로**: 여러 데이터베이스에 분산된 데이터를 통합하여 볼 수 없는 문제
- **비용 문제**: 고가의 BI 솔루션 도입 비용과 유지보수 비용
- **실시간성 부족**: 정적 리포트로는 실시간 비즈니스 현황 파악이 어려운 문제

### 타겟 사용자
- **주요 사용자**: 비즈니스 분석가, 마케터, 영업팀, 경영진
- **보조 사용자**: 데이터 분석가, IT 관리자
- **기업 규모**: 스타트업(10-50명), 중견기업(50-500명), 대기업(500명+)

### 핵심 가치 제안
1. **No-Code 차트 생성**: 드래그 앤 드롭으로 50개 이상의 차트 타입 생성
2. **다중 데이터베이스 통합**: 10개 이상의 주요 데이터베이스 동시 연결
3. **실시간 대시보드**: 자동 새로고침과 실시간 데이터 반영
4. **엔터프라이즈급 보안**: 역할 기반 접근 제어, 데이터 암호화
5. **확장 가능한 아키텍처**: 서버리스 기반으로 자동 확장

## Core Features

### 1. 데이터베이스 연결 관리
**기능 설명**: 다양한 데이터베이스에 안전하게 연결하고 관리

**주요 기능**:
- 지원 데이터베이스: MySQL, PostgreSQL, Oracle, SQL Server, BigQuery, Snowflake, SQLite, CockroachDB, Redshift
- 연결 정보 암호화 저장
- 연결 테스트 기능
- SSL/TLS 보안 연결 지원
- 읽기 전용 권한 권장

**중요성**: 기업의 기존 데이터 인프라와 원활한 통합을 통해 도입 장벽 최소화

### 2. 데이터셋 관리
**기능 설명**: SQL 쿼리를 저장하고 재사용 가능한 데이터셋으로 관리

**주요 기능**:
- SQL 편집기 (구문 강조, 자동 완성)
- 쿼리 실행 및 결과 미리보기
- 파라미터화된 쿼리 지원
- 쿼리 실행 이력 관리
- 스키마 정보 캐싱

**중요성**: 복잡한 쿼리를 한 번만 작성하고 여러 차트에서 재사용

### 3. 차트 위젯 시스템
**기능 설명**: 50개 이상의 차트 타입을 드래그 앤 드롭으로 생성

**차트 카테고리**:
- **기본 차트**: Line, Bar, Pie, Scatter, Area
- **고급 차트**: Heatmap, Treemap, Sunburst, Sankey, Radar
- **특수 차트**: Gauge, Liquid Fill, Word Cloud, Candlestick
- **3D 차트**: Line3D, Bar3D, Scatter3D
- **지도 시각화**: GeoMap, HeatMap

**주요 기능**:
- 직관적인 데이터 매핑 인터페이스
- 실시간 차트 미리보기
- 세부 스타일 커스터마이징
- 인터랙티브 기능 (줌, 필터, 드릴다운)
- 차트 템플릿 저장/불러오기

### 4. 대시보드 빌더
**기능 설명**: 여러 위젯을 조합하여 맞춤형 대시보드 구성

**주요 기능**:
- 그리드 기반 레이아웃 시스템
- 드래그 앤 드롭 위젯 배치
- 반응형 디자인 (모바일, 태블릿, 데스크톱)
- 대시보드 테마 (라이트/다크 모드)
- 자동 새로고침 설정
- 전체 화면 모드

### 5. 공유 및 협업
**기능 설명**: 대시보드와 차트를 팀원들과 공유

**주요 기능**:
- 공유 링크 생성 (만료 기간 설정)
- 비밀번호 보호 옵션
- 읽기 전용/편집 권한 설정
- 이메일 리포트 예약 발송
- PDF/이미지 내보내기
- 임베드 코드 생성

### 6. 사용자 및 권한 관리
**기능 설명**: 조직 내 사용자와 접근 권한 관리

**주요 기능**:
- 사용자 초대 및 관리
- 역할 기반 접근 제어 (RBAC)
- 팀/부서별 그룹 관리
- SSO 통합 (SAML, OAuth)
- 감사 로그
- 2단계 인증

## User Experience

### 사용자 페르소나

#### 1. 마케팅 매니저 (김서연, 35세)
- **목표**: 캠페인 성과를 실시간으로 모니터링하고 ROI 분석
- **Pain Points**: SQL을 모르고, 개발팀에 데이터 요청 시 시간 지연
- **사용 시나리오**: 광고 플랫폼 데이터와 매출 데이터를 결합하여 캠페인 대시보드 생성

#### 2. 영업 팀장 (이준호, 42세)
- **목표**: 팀 성과 추적 및 매출 예측
- **Pain Points**: 엑셀로는 실시간 데이터 업데이트가 어려움
- **사용 시나리오**: CRM 데이터를 연결하여 영업 파이프라인 대시보드 구축

#### 3. CEO (박민지, 48세)
- **목표**: 전사 KPI를 한눈에 파악
- **Pain Points**: 여러 부서의 리포트를 통합하는데 시간이 오래 걸림
- **사용 시나리오**: 경영진 대시보드에서 매출, 비용, 고객 지표 통합 모니터링

### 핵심 사용자 플로우

#### 1. 첫 대시보드 생성 (Onboarding)
```
시작 → 데이터베이스 연결 → 연결 테스트 → 샘플 쿼리 실행 
→ 첫 차트 생성 → 대시보드에 추가 → 공유
```

#### 2. 일상적인 모니터링
```
로그인 → 대시보드 목록 → 대시보드 선택 → 데이터 확인 
→ 필터 조정 → 인사이트 도출
```

#### 3. 협업 플로우
```
대시보드 생성 → 팀원 초대 → 권한 설정 → 공유 링크 생성 
→ 피드백 수집 → 대시보드 개선
```

### UI/UX 고려사항

#### 디자인 원칙
1. **직관성**: 5분 내에 첫 차트를 만들 수 있을 정도로 단순
2. **일관성**: 통일된 디자인 시스템 준수
3. **반응성**: 모든 액션에 대한 즉각적인 피드백
4. **접근성**: WCAG 2.1 AA 준수

#### 주요 UI 컴포넌트
- **데이터 탐색기**: 트리 구조로 데이터베이스/테이블/컬럼 탐색
- **쿼리 빌더**: 시각적 쿼리 작성 도구 (고급 사용자용 SQL 에디터)
- **차트 갤러리**: 카테고리별 차트 템플릿 브라우징
- **실시간 미리보기**: 설정 변경 시 즉시 차트 업데이트

# Technical Architecture

## 현재 아키텍처

### 시스템 구성요소

#### Frontend (React SPA)
- **프레임워크**: React 18 + TypeScript
- **UI 라이브러리**: Material-UI v5
- **차트 엔진**: Apache ECharts 5
- **상태 관리**: Context API + React Query
- **빌드 도구**: Vite

#### Backend (Serverless API)
- **런타임**: AWS Lambda (Node.js 18)
- **프레임워크**: NestJS v9
- **API Gateway**: AWS API Gateway v2
- **인증**: JWT + Refresh Token

#### 데이터 레이어
- **메타데이터 DB**: AWS RDS MySQL / SQLite (로컬)
- **쿼리 엔진**: TypeORM + Knex.js (다중 DB 지원)
- **캐싱**: Redis (ElastiCache)
- **파일 저장**: S3

## 미래 아키텍처 (Phase 1-3)

### Phase 1 변경사항
- **UI 프레임워크**: Material-UI → Shadcn/ui + Tailwind CSS
- **프론트엔드 프레임워크**: React SPA → Next.js (App Router)
- **Admin 기능**: 사용자 관리, 권한 관리(RBAC), 공유 관리 추가
- **테스트 인프라**: Jest 단위 테스트 + Playwright E2E 테스트

### Phase 2 변경사항
- **로컬 데이터베이스**: SQLite → DuckDB (OLAP 최적화)
- **ORM**: TypeORM + Knex.js → Drizzle ORM (타입 안전성 강화)

### Phase 3 변경사항
- **AI/ML 통합**: 자연어 쿼리, 예측 분석, 이상 탐지
- **고급 시각화**: WebGL 기반 3D 시각화, 실시간 스트리밍 차트
- **엔터프라이즈 기능**: 데이터 거버넌스, 컴플라이언스, 멀티 테넌시

### 데이터 모델

#### 핵심 엔티티
1. **Users**: 사용자 정보, 인증 정보
2. **Organizations**: 조직/회사 정보
3. **Databases**: 외부 DB 연결 정보
4. **Datasets**: SQL 쿼리 및 메타데이터
5. **Widgets**: 차트 설정 및 스타일
6. **Dashboards**: 대시보드 레이아웃 및 설정
7. **Permissions**: 접근 권한 정보 (Phase 1에서 강화)
8. **Roles**: 역할 정의 (Phase 1 신규)
9. **AuditLogs**: 감사 로그 (Phase 1 신규)

### API 설계
- RESTful API 원칙 준수
- 버전 관리 (/v1, /v2)
- Rate Limiting (분당 100회)
- 페이지네이션 (Cursor 기반)

### 인프라 요구사항
- **컴퓨팅**: AWS Lambda (1GB 메모리)
- **데이터베이스**: RDS MySQL (t3.medium)
- **캐싱**: ElastiCache Redis (t3.micro)
- **CDN**: CloudFront
- **모니터링**: CloudWatch + X-Ray

# Development Roadmap

## Phase 1: 모던 스택 전환 및 Admin 기능 (4개월)

### 1.1 디자인 시스템 마이그레이션 (1개월)
**목표**: Material-UI에서 Shadcn/ui + Tailwind CSS로 전환

**작업 내용**:
- Shadcn/ui 컴포넌트 라이브러리 설정
- Tailwind CSS 구성 및 테마 설정
- 기존 컴포넌트를 새 디자인 시스템으로 마이그레이션
- 다크 모드 지원 개선
- Storybook 설정 및 컴포넌트 문서화

**기술적 이점**:
- 번들 크기 감소 (트리 쉐이킹 개선)
- 커스터마이징 용이성 증가
- 더 나은 타입 안전성
- 모던한 UI/UX

### 1.2 Next.js 마이그레이션 (1.5개월)
**목표**: React SPA에서 Next.js App Router로 전환

**작업 내용**:
- Next.js 14 프로젝트 설정
- App Router 구조로 라우팅 재구성
- Server Components 활용한 성능 최적화
- API Routes로 BFF 패턴 구현
- 정적 생성 및 ISR 활용

**기술적 이점**:
- SEO 개선
- 초기 로딩 속도 향상
- 서버 사이드 렌더링
- 내장 이미지 최적화
- 미들웨어를 통한 인증/인가

### 1.3 Admin 기능 구현 (1개월)
**목표**: 엔터프라이즈급 관리 기능 추가

**핵심 기능**:
1. **사용자 관리**
   - 사용자 CRUD
   - 계정 활성화/비활성화
   - 비밀번호 재설정
   - 세션 관리

2. **권한 관리 (RBAC)**
   - 역할 정의 (Admin, Manager, Viewer)
   - 권한 매트릭스 관리
   - 리소스별 접근 제어
   - 권한 상속 구조

3. **공유 관리**
   - 공유 링크 중앙 관리
   - 공유 권한 모니터링
   - 만료 정책 설정
   - 접근 로그 추적

### 1.4 테스트 인프라 구축 (0.5개월)
**목표**: 안정적인 테스트 커버리지 달성

**작업 내용**:
- Jest 단위 테스트 설정 (목표: 80% 커버리지)
- Playwright E2E 테스트 구현
- CI/CD 파이프라인에 테스트 통합
- 테스트 리포트 자동화

## Phase 2: 데이터 레이어 현대화 (2개월)

### 2.1 DuckDB 마이그레이션 (1개월)
**목표**: SQLite에서 DuckDB로 전환하여 분석 성능 향상

**작업 내용**:
- DuckDB 통합 및 커넥터 개발
- 데이터 마이그레이션 도구 개발
- OLAP 최적화된 스키마 재설계
- 벤치마크 및 성능 튜닝

**기술적 이점**:
- 컬럼 기반 저장소로 분석 쿼리 성능 향상
- 병렬 처리 지원
- 메모리 효율적인 처리
- Parquet 파일 네이티브 지원

### 2.2 Drizzle ORM 전환 (1개월)
**목표**: TypeORM + Knex.js에서 Drizzle ORM으로 통합

**작업 내용**:
- Drizzle 스키마 정의
- 마이그레이션 스크립트 작성
- 쿼리 빌더 재구현
- 타입 안전성 강화

**기술적 이점**:
- 완전한 타입 안전성
- 더 나은 성능
- 간결한 API
- SQL-like 구문

## Phase 3: AI/ML 및 엔터프라이즈 기능 (3개월)

### 3.1 AI/ML 통합 (1.5개월)
**목표**: 지능형 데이터 분석 기능 추가

**핵심 기능**:
1. **자연어 쿼리**
   - OpenAI GPT 통합
   - 자연어 → SQL 변환
   - 쿼리 최적화 제안

2. **예측 분석**
   - 시계열 예측
   - 트렌드 분석
   - 이상치 탐지

3. **인사이트 자동 생성**
   - 주요 지표 자동 발견
   - 상관관계 분석
   - 실행 가능한 권장사항

### 3.2 고급 시각화 (0.5개월)
**목표**: 차세대 시각화 기능 제공

**작업 내용**:
- WebGL 기반 3D 시각화
- 실시간 스트리밍 차트
- VR/AR 대시보드 지원

### 3.3 엔터프라이즈 기능 (1개월)
**목표**: 대기업 요구사항 충족

**핵심 기능**:
1. **데이터 거버넌스**
   - 데이터 계보 추적
   - 메타데이터 관리
   - 데이터 품질 모니터링
   - 컴플라이언스 리포팅

2. **멀티 테넌시**
   - 완전한 데이터 격리
   - 테넌트별 커스터마이징
   - 리소스 할당 관리
   - 비용 추적

3. **고급 보안**
   - 필드 레벨 암호화
   - 동적 데이터 마스킹
   - 상세 감사 로그
   - SIEM 통합

## Logical Dependency Chain

### Phase 1 의존성
1. **디자인 시스템 전환** (선행 필수)
   - 모든 UI 컴포넌트의 기반
   - Next.js 마이그레이션 전 완료 필요

2. **Next.js 마이그레이션**
   - 새로운 라우팅 구조 확립
   - Admin 페이지 구현의 기반

3. **Admin 기능**
   - 사용자 관리 → 권한 관리 → 공유 관리 순서
   - 각 기능은 이전 기능에 의존

4. **테스트 인프라**
   - 모든 신규 기능에 대한 테스트 작성
   - CI/CD 파이프라인 통합

### Phase 2 의존성
1. **DuckDB 마이그레이션**
   - 로컬 개발 환경 우선 적용
   - 성능 벤치마크 후 프로덕션 적용

2. **Drizzle ORM 전환**
   - DuckDB 통합 완료 후 진행
   - 점진적 마이그레이션 전략

### Phase 3 의존성
1. **AI/ML 통합**
   - 안정적인 데이터 레이어 필요 (Phase 2 완료)
   - API 할당량 및 비용 관리 시스템 구축

2. **고급 시각화**
   - 기본 차트 시스템 안정화 필요
   - WebGL 컨텍스트 관리

3. **엔터프라이즈 기능**
   - Admin 기능 완성 필요 (Phase 1)
   - 멀티 테넌시는 전체 아키텍처 영향

## Risks and Mitigations

### Phase 1 리스크

#### 1. 디자인 시스템 마이그레이션 복잡도
- **위험**: 수백 개의 컴포넌트 마이그레이션 필요
- **완화**: 
  - 점진적 마이그레이션 (공존 전략)
  - 자동화 도구 개발 (codemod)
  - 컴포넌트별 우선순위 설정

#### 2. Next.js 학습 곡선
- **위험**: 팀의 Next.js 경험 부족
- **완화**:
  - 내부 교육 세션
  - 단계적 마이그레이션
  - 외부 전문가 컨설팅

### Phase 2 리스크

#### 1. 데이터 마이그레이션 안정성
- **위험**: SQLite → DuckDB 전환 중 데이터 손실
- **완화**:
  - 완벽한 백업 시스템
  - 병렬 운영 기간
  - 자동화된 데이터 검증

#### 2. ORM 전환 영향도
- **위험**: 전체 백엔드 코드베이스 영향
- **완화**:
  - Feature flag로 점진적 활성화
  - 광범위한 통합 테스트
  - 롤백 계획 수립

### Phase 3 리스크

#### 1. AI/ML 비용 관리
- **위험**: API 사용량 폭증으로 인한 비용 증가
- **완화**:
  - 사용량 모니터링 및 알림
  - 캐싱 전략
  - 자체 모델 개발 검토

#### 2. 멀티 테넌시 복잡도
- **위험**: 데이터 격리 실패 시 보안 사고
- **완화**:
  - Row Level Security 구현
  - 정기적인 보안 감사
  - 침투 테스트

### 공통 리스크

#### 1. 하위 호환성 유지
- **위험**: 기존 사용자 경험 훼손
- **완화**:
  - API 버저닝
  - 마이그레이션 가이드 제공
  - 충분한 전환 기간

#### 2. 성능 저하
- **위험**: 새로운 기능으로 인한 성능 영향
- **완화**:
  - 지속적인 성능 모니터링
  - 부하 테스트
  - 성능 예산 설정
