# VanillaMeta Product Requirements Document (PRD) - Final Version

## Overview

VanillaMeta는 기업용 비즈니스 인텔리전스(BI) 웹 애플리케이션으로, 코드 작성 없이 다양한 데이터베이스에 연결하여 데이터를 시각화하고 인사이트를 도출할 수 있는 플랫폼입니다. 스타트업부터 대기업까지 다양한 규모의 조직이 데이터 기반 의사결정을 내릴 수 있도록 지원합니다.

### 해결하고자 하는 문제
- **기술 장벽**: 비기술직 직원들이 데이터 분석을 위해 개발자나 데이터 분석가에게 의존해야 하는 문제
- **데이터 사일로**: 여러 데이터베이스에 분산된 데이터를 통합하여 볼 수 없는 문제
- **비용 문제**: 고가의 BI 솔루션 도입 비용과 유지보수 비용
- **실시간성 부족**: 정적 리포트로는 실시간 비즈니스 현황 파악이 어려운 문제

### 타겟 사용자
- **주요 사용자**: 비즈니스 분석가, 마케터, 영업팀, 경영진
- **보조 사용자**: 데이터 분석가, IT 관리자
- **기업 규모**: 스타트업(10-50명), 중견기업(50-500명), 대기업(500명+)

### 핵심 가치 제안
1. **No-Code 차트 생성**: 드래그 앤 드롭으로 50개 이상의 차트 타입 생성
2. **다중 데이터베이스 통합**: 10개 이상의 주요 데이터베이스 동시 연결
3. **실시간 대시보드**: 자동 새로고침과 실시간 데이터 반영
4. **엔터프라이즈급 보안**: 역할 기반 접근 제어, 데이터 암호화
5. **확장 가능한 아키텍처**: 서버리스 기반으로 자동 확장

## Core Features

### 1. 데이터베이스 연결 관리
**기능 설명**: 다양한 데이터베이스에 안전하게 연결하고 관리

**주요 기능**:
- 지원 데이터베이스: MySQL, PostgreSQL, Oracle, SQL Server, BigQuery, Snowflake, SQLite, CockroachDB, Redshift
- 연결 정보 암호화 저장
- 연결 테스트 기능
- SSL/TLS 보안 연결 지원
- 읽기 전용 권한 권장

**중요성**: 기업의 기존 데이터 인프라와 원활한 통합을 통해 도입 장벽 최소화

### 2. 데이터셋 관리
**기능 설명**: SQL 쿼리를 저장하고 재사용 가능한 데이터셋으로 관리

**주요 기능**:
- SQL 편집기 (구문 강조, 자동 완성)
- 쿼리 실행 및 결과 미리보기
- 파라미터화된 쿼리 지원
- 쿼리 실행 이력 관리
- 스키마 정보 캐싱

**중요성**: 복잡한 쿼리를 한 번만 작성하고 여러 차트에서 재사용

### 3. 차트 위젯 시스템
**기능 설명**: 50개 이상의 차트 타입을 드래그 앤 드롭으로 생성

**차트 카테고리**:
- **기본 차트**: Line, Bar, Pie, Scatter, Area
- **고급 차트**: Heatmap, Treemap, Sunburst, Sankey, Radar
- **특수 차트**: Gauge, Liquid Fill, Word Cloud, Candlestick
- **3D 차트**: Line3D, Bar3D, Scatter3D
- **지도 시각화**: GeoMap, HeatMap

**주요 기능**:
- 직관적인 데이터 매핑 인터페이스
- 실시간 차트 미리보기
- 세부 스타일 커스터마이징
- 인터랙티브 기능 (줌, 필터, 드릴다운)
- 차트 템플릿 저장/불러오기

### 4. 대시보드 빌더
**기능 설명**: 여러 위젯을 조합하여 맞춤형 대시보드 구성

**주요 기능**:
- 그리드 기반 레이아웃 시스템
- 드래그 앤 드롭 위젯 배치
- 반응형 디자인 (모바일, 태블릿, 데스크톱)
- 대시보드 테마 (라이트/다크 모드)
- 자동 새로고침 설정
- 전체 화면 모드

### 5. 공유 및 협업
**기능 설명**: 대시보드와 차트를 팀원들과 공유

**주요 기능**:
- 공유 링크 생성 (만료 기간 설정)
- 비밀번호 보호 옵션
- 읽기 전용/편집 권한 설정
- 이메일 리포트 예약 발송
- PDF/이미지 내보내기
- 임베드 코드 생성

### 6. 사용자 및 권한 관리
**기능 설명**: 조직 내 사용자와 접근 권한 관리

**주요 기능**:
- 사용자 초대 및 관리
- 역할 기반 접근 제어 (RBAC)
- 팀/부서별 그룹 관리
- SSO 통합 (SAML, OAuth)
- 감사 로그
- 2단계 인증

### 7. Admin 관리 기능 (Phase 1 신규)
**기능 설명**: 시스템 전체를 관리하는 포괄적인 관리자 기능

**주요 기능**:
- **사용자 관리**: CRUD, 일괄 처리, 승인 프로세스
- **권한 관리**: RBAC 시스템, 세부 권한 설정
- **공유 관리**: 전체 공유 현황 모니터링 및 제어
- **감사 로그**: 모든 활동 추적 및 컴플라이언스 리포트
- **조직/팀 관리**: 계층 구조 설정 및 리소스 할당
- **알림/공지사항**: 시스템 전체 커뮤니케이션
- **백업/복구**: 자동화된 백업 및 복구 시스템

## User Experience

### 사용자 페르소나

#### 1. 마케팅 매니저 (김서연, 35세)
- **목표**: 캠페인 성과를 실시간으로 모니터링하고 ROI 분석
- **Pain Points**: SQL을 모르고, 개발팀에 데이터 요청 시 시간 지연
- **사용 시나리오**: 광고 플랫폼 데이터와 매출 데이터를 결합하여 캠페인 대시보드 생성

#### 2. 영업 팀장 (이준호, 42세)
- **목표**: 팀 성과 추적 및 매출 예측
- **Pain Points**: 엑셀로는 실시간 데이터 업데이트가 어려움
- **사용 시나리오**: CRM 데이터를 연결하여 영업 파이프라인 대시보드 구축

#### 3. CEO (박민지, 48세)
- **목표**: 전사 KPI를 한눈에 파악
- **Pain Points**: 여러 부서의 리포트를 통합하는데 시간이 오래 걸림
- **사용 시나리오**: 경영진 대시보드에서 매출, 비용, 고객 지표 통합 모니터링

#### 4. IT 관리자 (최준혁, 40세) - Phase 1 신규
- **목표**: 시스템 안정성 유지 및 사용자 권한 관리
- **Pain Points**: 수동으로 사용자 권한을 관리하는 번거로움
- **사용 시나리오**: Admin 대시보드에서 사용자 승인, 권한 설정, 시스템 모니터링

### 핵심 사용자 플로우

#### 1. 첫 대시보드 생성 (Onboarding)
```
시작 → 데이터베이스 연결 → 연결 테스트 → 샘플 쿼리 실행 
→ 첫 차트 생성 → 대시보드에 추가 → 공유
```

#### 2. 일상적인 모니터링
```
로그인 → 대시보드 목록 → 대시보드 선택 → 데이터 확인 
→ 필터 조정 → 인사이트 도출
```

#### 3. 협업 플로우
```
대시보드 생성 → 팀원 초대 → 권한 설정 → 공유 링크 생성 
→ 피드백 수집 → 대시보드 개선
```

#### 4. 관리자 플로우 (Phase 1 신규)
```
Admin 대시보드 → 승인 대기 사용자 확인 → 사용자 정보 검토 
→ 승인/거부 → 권한 할당 → 감사 로그 확인
```

### UI/UX 고려사항

#### 디자인 원칙
1. **직관성**: 5분 내에 첫 차트를 만들 수 있을 정도로 단순
2. **일관성**: 통일된 디자인 시스템 준수 (Phase 1: Shadcn/ui)
3. **반응성**: 모든 액션에 대한 즉각적인 피드백
4. **접근성**: WCAG 2.1 AA 준수

#### 주요 UI 컴포넌트
- **데이터 탐색기**: 트리 구조로 데이터베이스/테이블/컬럼 탐색
- **쿼리 빌더**: 시각적 쿼리 작성 도구 (고급 사용자용 SQL 에디터)
- **차트 갤러리**: 카테고리별 차트 템플릿 브라우징
- **실시간 미리보기**: 설정 변경 시 즉시 차트 업데이트
- **Admin 콘솔**: 통합 관리 인터페이스 (Phase 1 신규)

# Technical Architecture

## 현재 아키텍처

### 시스템 구성요소

#### Frontend (React SPA)
- **프레임워크**: React 18 + TypeScript
- **UI 라이브러리**: Material-UI v5
- **차트 엔진**: Apache ECharts 5
- **상태 관리**: Context API + React Query
- **빌드 도구**: Vite

#### Backend (Serverless API)
- **런타임**: AWS Lambda (Node.js 18)
- **프레임워크**: NestJS v9
- **API Gateway**: AWS API Gateway v2
- **인증**: JWT + Refresh Token

#### 데이터 레이어
- **메타데이터 DB**: AWS RDS MySQL / SQLite (로컬)
- **쿼리 엔진**: TypeORM + Knex.js (다중 DB 지원)
- **캐싱**: Redis (ElastiCache)
- **파일 저장**: S3

## 미래 아키텍처 (Phase 1-3)

### Phase 1 변경사항 (M01-M02)
- **UI 프레임워크**: Material-UI → Shadcn/ui + Tailwind CSS
- **프론트엔드 프레임워크**: React SPA → Next.js (App Router)
- **Admin 기능**: 사용자 관리, 권한 관리(RBAC), 공유 관리, 감사 로그, 조직/팀 관리, 알림 시스템, 백업/복구
- **테스트 인프라**: Jest 단위 테스트 (80% 커버리지) + Playwright E2E 테스트
- **성능 최적화**: Lambda 콜드 스타트 개선, API 압축, 쿼리 최적화

### Phase 2 변경사항 (M03)
- **로컬 데이터베이스**: SQLite → DuckDB (OLAP 최적화)
- **ORM**: TypeORM + Knex.js → Drizzle ORM (타입 안전성 강화)
- **성능 목표**: 대시보드 로딩 10배 향상, 메모리 사용량 50% 감소

### Phase 3 변경사항 (M04)
- **AI/ML 통합**: 자연어 쿼리, 예측 분석, 이상 탐지, 자동 인사이트
- **고급 시각화**: WebGL 기반 3D 시각화, 실시간 스트리밍 차트, 지리공간 분석
- **엔터프라이즈 기능**: 데이터 거버넌스, 행 수준 보안(RLS), 멀티 테넌시
- **플랫폼 생태계**: 플러그인 시스템, API 마켓플레이스, 모바일 앱

### 데이터 모델

#### 핵심 엔티티
1. **Users**: 사용자 정보, 인증 정보
2. **Organizations**: 조직/회사 정보 (Phase 1 강화)
3. **Teams**: 팀/부서 정보 (Phase 1 신규)
4. **Databases**: 외부 DB 연결 정보
5. **Datasets**: SQL 쿼리 및 메타데이터
6. **Widgets**: 차트 설정 및 스타일
7. **Dashboards**: 대시보드 레이아웃 및 설정
8. **Permissions**: 접근 권한 정보 (Phase 1 강화)
9. **Roles**: 역할 정의 (Phase 1 신규)
10. **AuditLogs**: 감사 로그 (Phase 1 신규)
11. **Notifications**: 알림/공지사항 (Phase 1 신규)
12. **Backups**: 백업 메타데이터 (Phase 1 신규)

### API 설계
- RESTful API 원칙 준수
- 버전 관리 (/v1, /v2)
- Rate Limiting (분당 100회)
- 페이지네이션 (Cursor 기반)

### 인프라 요구사항
- **컴퓨팅**: AWS Lambda (1GB → 256MB after Phase 2)
- **데이터베이스**: RDS MySQL (t3.medium) / DuckDB (Phase 2)
- **캐싱**: ElastiCache Redis (t3.micro)
- **CDN**: CloudFront
- **모니터링**: CloudWatch + X-Ray
- **백업**: S3 + EFS 스냅샷 (Phase 1)

# Development Roadmap

## Phase 1: 시스템 안정화 및 Admin 기능 (M01-M02, 6개월)

### M01: 시스템 안정성 개선 (3개월)

#### 1.1 에러 처리 및 로깅 강화 (3주)
- 전역 에러 핸들러 구현
- 구조화된 로깅 시스템 (JSON 형식)
- CloudWatch 통합 개선
- 사용자 친화적 에러 메시지

#### 1.2 성능 최적화 (4주)
- Lambda 콜드 스타트 최적화
- 데이터베이스 인덱싱 및 쿼리 최적화
- API 응답 압축 (gzip)
- 프론트엔드 번들 최적화

#### 1.3 테스트 인프라 구축 (3주)
- Jest 단위 테스트 설정 (목표: 80% 커버리지)
- Playwright E2E 테스트 구현
- 부하 테스트 및 성능 벤치마크
- CI/CD 파이프라인 통합

#### 1.4 문서화 (2주)
- API 문서 업데이트 (Swagger)
- 배포 가이드 작성
- 사용자 매뉴얼 및 FAQ

### M02: Modern Stack 전환 및 Admin 기능 (3개월)

#### 2.1 디자인 시스템 마이그레이션 (3주)
- Material-UI → Shadcn/ui + Tailwind CSS
- 컴포넌트 라이브러리 재구성
- 다크 모드 개선
- Storybook 설정

#### 2.2 Next.js 마이그레이션 (4주)
- React SPA → Next.js 14 (App Router)
- Server Components 활용
- ISR/SSG 최적화
- 미들웨어 인증 구현

#### 2.3 Admin 핵심 기능 (5주)
- **사용자 관리**: CRUD, 일괄 처리, 승인 프로세스
- **권한 관리**: RBAC 시스템, 5개 기본 역할 정의
- **공유 관리**: 중앙화된 공유 대시보드 관리
- **감사 로그**: 모든 활동 추적 및 검색
- **조직/팀 관리**: 계층 구조 및 리소스 격리
- **알림 시스템**: 공지사항 및 시스템 알림
- **백업/복구**: 자동화된 백업 스케줄링

## Phase 3: AI/ML 및 플랫폼 확장 (M04, 6개월+)

## Risks and Mitigations

### Phase 1 리스크

#### 1. 시스템 안정성 개선 중 서비스 중단
- **위험**: 핵심 시스템 변경으로 인한 장애
- **완화**: 
  - Feature flag로 점진적 롤아웃
  - 카나리 배포 전략
  - 실시간 모니터링 강화
  - 즉시 롤백 체계

#### 2. Admin 기능 보안 취약점
- **위험**: 권한 관리 시스템의 보안 허점
- **완화**:
  - 보안 감사 및 침투 테스트
  - 최소 권한 원칙 적용
  - 2단계 인증 필수화
  - 감사 로그 실시간 모니터링

### Phase 2 리스크

#### 1. DuckDB 마이그레이션 데이터 손실
- **위험**: SQLite → DuckDB 전환 중 데이터 무결성 문제
- **완화**:
  - 3중 백업 체계 (로컬, S3, EFS)
  - 체크섬 기반 검증
  - 병렬 운영 기간 (2주)
  - 단계별 마이그레이션

#### 2. Drizzle ORM 생태계 미성숙
- **위험**: 문서 부족, 커뮤니티 지원 한계
- **완화**:
  - Raw SQL 폴백 전략
  - 핵심 기능 우선 전환
  - TypeORM 부분 유지 옵션
  - 자체 래퍼 라이브러리 개발

### Phase 3 리스크

#### 1. AI/ML API 비용 폭증
- **위험**: OpenAI API 사용량 증가로 비용 급증
- **완화**:
  - 사용량 할당량 설정
  - 캐싱 전략 (Redis)
  - 자체 모델 개발 (장기)
  - 티어별 기능 제한

#### 2. 플랫폼 복잡도 증가
- **위험**: 기능 추가로 인한 유지보수 어려움
- **완화**:
  - 마이크로서비스 아키텍처
  - 모듈별 독립 배포
  - 자동화된 테스트 확대
  - 기술 부채 정기 해결

- **시스템 안정성**

  - 권한 설정 정확도 100%

  - 타입 에러 90% 감소

  - 자연어 쿼리 사용률 > 50%
  - 예측 정확도 > 85%
  - 인사이트 활용률 > 70%

- **플랫폼 생태계**

  - 월간 활성 개발자 1,000명

- **비즈니스 성장**
  - 엔터프라이즈 고객 20개
  - ARR 성장률 > 300%

### 용어 정의
- **Dataset**: SQL 쿼리와 그 메타데이터를 포함한 재사용 가능한 데이터 정의
- **Widget**: 데이터셋을 시각화한 차트 컴포넌트
- **Dashboard**: 여러 위젯을 배치한 화면
- **Organization**: 사용자들이 속한 회사/조직 단위
- **RBAC**: Role-Based Access Control (역할 기반 접근 제어)
- **DuckDB**: OLAP에 최적화된 컬럼 지향 데이터베이스
- **Drizzle ORM**: TypeScript 우선 ORM
- **SSG/ISR**: Static Site Generation / Incremental Static Regeneration
- **RLS**: Row Level Security (행 수준 보안)
