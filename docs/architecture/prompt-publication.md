# UC-019 질문 저장 → 게시 준비 설계

P3/P4, FR-007/011, Draft. 기존에는 질문에서 게시를 요청하면 확인 질문으로 끝나거나, 저장 후 읽기 화면에서 흐름이 끊겼다. 이번 변경은 저장한 버전의 게시 미리보기까지 연결한다. 기존 UC-018 API·엔티티·게시 트랜잭션은 유지한다.

## 최소 변경

분류 계획은 기존 세 필드에 선택적 `publicationRequested: true`를 추가한다. 생략은 기존 동작이며 false나 다른 값은 거절한다. true는 `saveRequested: true`인 실행 계획에서만 허용하며 clarify에는 허용하지 않는다. 단일 변경과 2~6개 batch의 기존 검증을 재사용한다. 대상 판별에는 원래 질문을 사용하고, 변경 생성기에 보내는 `editPrompt`에는 저장·게시 지시를 제거한다. 분류 LLM에는 계속 질문 문자열만 전달한다. 직접 지정 모드는 게시 의도를 처리하지 않는다.

편집 화면은 응답 flag와 auto/save 관계를 검증한다. 검증한 전체 초안을 기존 API로 저장하고, 성공 응답의 분석 ID와 revision을 확인한 뒤 `savedRevision` query로 게시 화면에 전달한다. 게시 flag가 없는 기존 이동은 유지한다. 저장 409·결과 불명확 복구 후 자동으로 게시하지 않으며 사용자가 게시 요청을 다시 명시한다.

게시 화면은 query가 중복 없이 64자리 소문자 hex인지 확인하고 현재 소유 분석의 revision과 비교한다. 빈 값·잘못된 값·중복·버전 불일치는 미리보기와 게시를 막고 저장 화면 확인을 안내한다. URL은 권한이 아니며 기존 owner API가 권한을 검사한다. 버전이 같으면 기존 abort/sequence/pending 경계에서 게시 미리보기를 한 번 실행하고 결과 revision을 다시 확인한다. 같은 버전의 미리보기 실패는 수동 재시도가 가능하다.

공개 범위는 **링크를 가진 사람**으로 고정되어 있다. 화면에서 고정 범위·전체 기간·필터 없음·UTC와 만료일을 확인한 후 기존 ‘링크 게시’를 눌러야 공개된다. 새로고침은 GET/미리보기만 반복할 수 있고 저장·게시 쓰기를 반복하지 않는다. 원문 질문은 URL이나 별도 영구 저장소에 담지 않는다.

## 검증과 종료 조건

- BE: strict flag, 잘못된 조합, 기존 계획 호환, save/content/layout/batch 전달, 취소.
- FE: 검증 초안 저장 → revision 전달, 저장 실패 이동 없음, 버전 불일치, 미리보기 실패 시 저장 보존, reload 게시 없음, 묵은 응답 무시.
- 관련 단위·타입·린트·빌드 후 Ego에서 공개 Rill 분석 12로 지정 LLM 질문 → 저장 → 게시 미리보기 → 링크 게시 → 새로고침과 익명 조회를 확인한다.
- 390/768/1440px에서 버튼·입력·폰트·정렬·넘침을 확인하고 Rill 집계 oracle과 수치를 비교한다. 임시 게시를 중지하고 분석 변경은 원복한다.

엔티티·시퀀스의 공개 계약은 UC-018을 재사용하며 DB 변경은 없다. 운영 MySQL, 실제 휴대폰, 모든 자연어 표현, 생성 화면 질문, 질문만으로 자동 공개, 전체 P4/TC-005는 이번 완료 주장에 포함하지 않는다.
