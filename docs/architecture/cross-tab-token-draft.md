# UC028 다른 탭 토큰 갱신·초안 복구 설계

P3/P4·Draft. UC025의 탭별 tokenHash→scope 별칭만으로는 다른 탭의 새 토큰을 조회할 수 없는 차이를 보완한다. 새 서버 API/DB/의존성을 추가하지 않는다.

localStorage의 기능 전용 메타데이터는 로그인 세대(epoch, 무작위 UUID)·현재 tokenHash·scope만 가진다. 초안은 기존 sessionStorage에 둔다. editorDraftKey는 같은 origin의 현재 공유 연결을 읽어 탭별 초안 key를 찾는다. 정상 refresh 성공 경로만 scope를 승계한다. 초기 기존 별칭은 공유 상태가 아직 없는 첫 바인딩에서 같은 tokenHash일 때만 승계한다. 새 로그인/로그아웃은 새로운 세대와 해당 탭 보관 정리를 실행한다. 동일 토큰 문자열 재로그인도 분리한다.

apiHelper는 refresh 시작 때 토큰·세대를 캡처하고 성공 후/해시 계산 후 재검사한다. 다른 탭이 토큰/세대를 바꿨다면 늦은 성공을 거절하고 늦은 실패도 현재 인증을 지우지 않는다. 같은 탭 요청 single-flight는 유지하고 여러 탭 서버 refresh 단일화는 추가하지 않는다. 공유 메타데이터 오류는 안전하게 연결을 포기하고 인증 자체의 오류와 구분한다. 원 토큰·질문/SQL은 공유 메타데이터에 기록하지 않는다.

검증: 독립 sessionStorage 두 개+공유 localStorage로 다른 탭 연속갱신/이벤트 미수신 후 reload·신규 로그인/동일 토큰/로그아웃·해시/refresh 중 세대 변경·공유 접근 실패를 회귀한다. Ego68 두 탭은 실제 서버201 refresh와 재요청을 사용하고 최초 만료401만 정확한1회 로컬 프록시 주입한다. 실제 시간이 지나 JWT가 만료될 때까지 기다렸다고 주장하지 않는다. 질문 보존→명시 복구→preview/save/publication/reload·원래 수치/배치·모바일 정렬을 확인하고 링크 중지/정상 프록시 복원으로 종료한다.
