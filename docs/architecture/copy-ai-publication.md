# UC-022 복사본 AI 편집·게시 통합

P3/P4/P5, FR007/011/012, Draft. UC021에서 내 소스로 만든 비공개 복사본을 UC019의 질문/저장/게시 버전 여정에 연결한다. 새 원본 접근권·복제 provenance 테이블·범용 작업 실행기를 만들지 않는다. 기존 동작을 먼저 실행하고 확인된 연결 공백만 최소 보완한다.

## 계약

복사본 소유자는 복사본 ID와 본인 sourceId의 editor를 연다. 저장 지표 링크가 없는 복제 계산 snapshot도 AI 수정 가능해야 한다. AI에 제공되는 소스 profile·활성 지표·현재 초안은 복사본 소유자 범위다. 질문은 선택/명시 대상의 내용 또는 배치만 바꾸며 비대상 정의·모든 폭 좌표·block ID·원본23을 유지한다. 원본 공유/게시가 중지돼도 이미 저장된 복사본 편집은 독립이다.

첫 질문은 변경만 요청해 전체 미리보기와 실제 수치를 검토한다. 이어 현재 초안을 저장하고 게시 미리보기로 연결하는 명시 질문을 실행한다. 저장 대상·성공 ID는 현재 복사본이며 반환 revision으로만 게시 미리보기를 연다. 공개는 범위/만료일을 확인한 뒤 기존 명시 게시 버튼을 누른다. 게시 snapshot은 저장된 복사본·새 소스 수치/정의와 일치하고 원본/다른 복사본/원본의 기존 게시 버전을 바꾸지 않는다. 편집 초안·저장본·게시본 책임은 분리한다.

다른 계정은 복사본 editor/AI/save/publication을 사용할 수 없다. 익명은 활성 게시 snapshot만 읽고 SQL·소스 ID·연결/권한·원본 행을 받지 않는다. 게시 URL은 편집권이 아니다. 새로고침은 추가 저장·게시를 실행하지 않는다. 저장 충돌/결과 불명확·취소 후 자동 게시하지 않는 UC017/019 경계는 유지한다.

## 구현·검증 범위

기존 DashboardEdit의 auto 질문→전체 preview→정확한 frozen items 저장→savedRevision 게시 handoff와 Publication의 version/CAS를 사용한다. 새 기능이 없어도 통합 증거와 회귀가 필요하다. 발견한 결함은 관련 코드/검사로 보완한다. 새 설정을 기본 선행 단계로 만들거나 별도 데모 서버로 대체하지 않는다.

Ego의 공개 Rill 파생 수신자 복사본26/source27에서 지정 Codex 모델로 질문→미리보기→저장→게시→소유/익명 reload를 실행한다. 원본23·비대상 복사본25의 정의/배치/revision/공유/게시, 복사본 target과 전체 미리보기 수치·게시 snapshot을 전후 비교한다. 새 공개 링크는 마지막에 중지한다. 390/768/1440의 질문/미리보기/게시/읽기 화면 크기·높이·정렬·폰트/넘침을 실제 확인한다.

운영 MySQL·실휴대폰·모든 자연어/복구 오류 조합·질문만으로 무확인 공개·전체 TC005 수용은 이번 범위 밖이다. LLM 요청 모델과 실제 제공자 내부 라우팅의 독립 증명은 구분한다.

## 실행과 경계

[실행 기록](../testing/copy-ai-publication.md): 기존 연결이 정상 동작해 제품 코드/DB 변경 없이 no-metric 복사본의 미리보기→명시 저장/게시 handoff 회귀를 추가했다. 첫 계산식/제목 동시 변경은 clarify, 단일 계산식 변경과 이후 별도 제목 변경은 성공했다. 제목 저장 후에도 이전 게시본이 유지되며 명시 재게시에서 같은 URL의 버전2로 갱신된다. 검증 링크는 최종 중지했다.

내용 미리보기 성공은 게시 가능성의 보장이 아니다. Publication의 안전 집계 증명/240그룹 제한을 통과하지 못하면 저장된 복사본을 보존하고 게시 준비 오류를 표시한다. 이번 SUM\*2는 통과했으나 모든 AI식 오류 복구는 미검증이다. 게시 handoff의 두 의도 플래그도 실제 질문/모델 결과를 검증한 범위이며 모든 자연어 문장을 보장하지 않는다.

## 제외 복사본 후속 검증 설계 — 2026-10-16

UC024로 평균 블록을 제외한 복사본35/source30에서 UC022 질문·미리보기·저장·게시 계약을 검증한다. 대상 요청 지표만2배, 비대상OS·블록ID·모든 폭 배치·원본27을 보존한다. 정답은 요청1,269,026,000·169점의각2배·OS28그룹불변이다. 게시 전 저장 revision과 미리보기를 확인하고 최종 임시 링크는 중지한다.

실제 질문에서 변경 없는 계산식이 성공으로 반환되는 공백을 확인했다. 편집기 내용 변경 경로는 생성기에 선택 블록의 실제 변경을 요구한다. 검증된 선택 정의가 기존과 같으면 기존 최대2회 교정 루프에 넣고, 두 번 모두 같으면 실패로 종료해 성공 미리보기/자동저장·게시를 실행하지 않는다. 일반 생성의 ‘유지’ 요청 계약은 유지한다. SQL 의미의 모든 자연어 일치를 증명하는 기능은 아니므로 실제 수치 정답도 별도 검증한다. 새DB·의존성·모델교체 없이 현재 서비스 경계에서 보완한다. 회귀→실제Ego재검증·390/태블릿/1440 UI와 원본/게시snapshot/추가쓰기0을 종료 조건으로 둔다.
