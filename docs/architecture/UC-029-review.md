# UC029 범위 리뷰

Draft. Main이 작성 후 별도 diff/명세 대조 패스로 검토했다. 독립 리뷰나 사람 승인이 아니다.

- 원 요청에 인증 헤더와 세대를 함께 기록하므로 새 로그인 뒤 도착한 옛401은 새 세대에서 재실행하지 않는다. 잠금 대기 중 동일 토큰 재로그인도 세대로 거절한다.
- 기존 탭 내부 refreshPromise는 유지하고 Web Locks 안에서 승자 토큰 재사용 또는 기존 refresh/scope승계/토큰저장을 수행한다. 잠금은 대기10초에만 제한하며 callback 진입 시 대기 timer를 해제하고 네트워크는 기존10초 timeout을 따른다.
- 잠금 거절/대기 만료는 실제 refreshStarted가 아니므로 정상 인증/초안을 지우지 않는다. 잠금 API 오류 뒤 무잠금 refresh로 우회하지 않는다. 미지원은 기존 탭 내부 경로다.
- 기존 UC028의 늦은 성공/실패 검사와 새 세대 보존을 유지하고, 같은 유효 세대에서 다른 갱신이 먼저 끝난 경우 현재 토큰을 재사용한다. 재요청 직전 세대도 확인한다.
- Ego69의 두 탭401·브라우저held/pending·실제refresh201한번·원 preview201두건·양쪽독립초안reload복구·한탭저장/게시19/reload·중지20/404를 대조했다. userinfo200 경로와 달리 이번 원 요청은 preview POST라 성공201이 맞다.

잠금 미지원의 전역 단일화·모든 다중탭 실패 조합·실휴대폰·운영/전체 수용은 미확인이다. [검증 기록](../testing/concurrent-token-renewal.md)을 따른다.
