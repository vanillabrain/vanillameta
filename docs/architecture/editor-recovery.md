# 편집 요청 복구

UC017/P3/Draft. 기존409 안내 뒤 초안을 버리는 재로드만 있던 차이를 보완한다. 새 저장 API나 자동 overwrite 없이 FE 복구 패널과 읽기 비교·제한 병합을 추가한다. GET editor 항목에 읽기 전용 savedDefinition을 반환하여 SQL snapshot을 확인한다. 기존 저장 body는 이 필드를 보내거나 신뢰하지 않는다.

오류 상태는 conflict/unknown이며 상태 확인 GET은 쓰기0이다. 최신 revision이 최초와 같아도 미리보기를 다시 수행한다. 최신 내용이 현재 초안과 같으면 저장 화면 보기만 제공한다. 다르면 최초 editor와 현재 items와 최신 editor를 세 방향 비교한다. 비교를 위한 계산/차트 정의는 kind/draft materialization을 정규화하되 SQL·prefix·설명·종류·결과 필드를 보존한다. 표시 필드와 각 폭 배치는 별도 단위다. 현재 유효 미리보기의 draft가 있으면 저장 요청의 canonical 비교에 사용한다.

읽기/병합 helper는 순수 함수로 분리한다. 동일 key 순서만 지원하고 구조 변경은 보수적으로 차단한다. 충돌 목록은 번호·제목·필드명만 보이고 SQL은 노출하지 않는다. 같은 단위가 충돌하면 명시적 내 변경 선택 후 그 단위만 로컬을 사용한다. 최신본의 비대상 변경은 유지한다. 합친 초안은 최신 editor를 기준으로 삼고 묵은 이력/preview/후보를 지우며 전체 preview가 다시 필요하다. 새 revision도 저장 시 CAS로 검사한다.

로컬 초안 편집/undo는 조회 결과를 해제한다. 확인/병합/저장 도중 연속 입력과 늦은 응답은 pending/token으로 막는다. 읽기 실패는 복구 잠금을 유지한다. 생성 취소는 기존 abort와sequence를 유지하고 새 오류/이전 성공 안내를 지운다. 저장 후 응답이 없으면 취소/rollback으로 표현하지 않는다. 실제 화면 검증은 전용 로컬 proxy의 일회성 응답 유실로 실제 commit 후 socket을 닫는 조건과 전달 전 실패를 구분한다. 제품에 fault switch를 추가하지 않는다.

패널은 기존 AnalysisUi28px버튼·32px입력·12px텍스트와 wrap를 사용한다. 390/768/1440에서 확인중/충돌/동일저장/오류/취소를 대표 검증한다. 운영DB·분산 작업 영수증·브라우저 종료 뒤 초안 영구 보관·구조 충돌 자동 병합은 범위 밖이다.
