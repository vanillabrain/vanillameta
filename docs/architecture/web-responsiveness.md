# VanillaMeta 웹 응답성

이 방침은 VanillaMeta의 브라우저 프런트엔드, Nest API, 데이터 분석 워커에 적용한다.

## 구현 경계

- 프런트엔드는 입력, 포커스, 화면 상태와 시각화를 담당한다. 서버 전용 DB·파일시스템·Node 모듈을 직접 또는 재수출을 통해 import하지 않는다. 공유 타입과 직렬화 계약은 브라우저에서도 사용할 수 있는 모듈에 둔다.
- 대량 파싱·집계는 측정으로 병목을 확인한 뒤 기존 서버·DuckDB 워커 경로를 우선 검토한다. 차트에 필요한 데이터만 전달하고, 필터를 바꾼 뒤 이전 응답이 최신 화면을 덮지 않도록 한다.
- 새 화면·컴포넌트·기능 전용 훅의 직접 `useEffect` 호출 금지와 공용 어댑터 예외 기준은 [검증 스킬](../../skills/vanillameta-verify/SKILL.md#제품-코드에서-useeffect-직접-사용-금지)을 따른다.

## 대표 흐름과 관측값

| 흐름 | 관측값과 기능 조건 |
| --- | --- |
| 로그인 상태에서 아티팩트 허브 열기 | 탐색 시작부터 검색 입력이 화면에 반영될 때까지. 차가운 캐시와 재방문을 각각 측정한다. |
| Studio AI 응답 스트리밍 중 타이핑 | 키 입력부터 화면 반영까지. 한글 조합·확정과 입력 보존을 확인한다. 고정 스트림으로 전후 비교하고 실제 AI 여정은 기능 범위로 기록한다. |
| 차트·Pivot 대시보드에서 공통 필터 연속 변경 | 입력 피드백 시간과 마지막 필터의 올바른 결과가 표시될 때까지 걸리는 시간을 구분한다. 요청 수와 이전 응답의 화면 덮어쓰기 여부를 확인한다. |

같은 빌드·브라우저·데이터·캐시 조건에서 전후 원시 표본과 중앙값, 느린 표본을 남긴다. API·집계 대기와 브라우저 렌더링을 구분한다. 화면 캡처와 영상은 기능 증빙으로, 시간 표본과 CDP 트레이스는 성능 증빙으로 사용한다.

첫 구현 단위는 대표 흐름의 기준선 수집, 확인된 병목 한 곳의 수정·재측정, 신규 `useEffect` 직접 호출의 CI 차단이다. 기존 호출은 기준 목록으로 관리하고 관련 변경에서 전환한다. 새 규칙의 차단 사례와 허용 어댑터를 실제 검사로 검증한다.
