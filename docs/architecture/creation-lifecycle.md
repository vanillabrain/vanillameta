# UC-023 생성 질문의 저장·게시 준비 연결

TC005/UC005 BR001/002/006, FR007/011, Draft. 실제 전체 Rill 생성 미리보기 뒤 ‘현재 초안을 저장하고 게시 미리보기로’ 질문이 새 제안 생성으로 처리돼400이 발생했다(`/tmp/vm-tc005/save-question-before-fix.json`). 기존 editor 저장 질문과 구분되는 생성 화면의 연결 공백이다.

## 계약과 최소 변경

- 신규 생성은 기존 구조화 제안/계산 compiler를 유지한다. 모델 응답의 선택적 saveRequested/publicationRequested true만 엄격히 분리한다. 부정·조건·인용·질문형 저장/게시는 쓰기 의도로 취급하지 않는다. 게시는 명시 저장과 함께 요청한 링크 게시 준비만 지원한다. 수신자 지정·중지·복제 요청은 저장하지 않고 확인한다.
- 유효한 생성 미리보기가 있는 후속 질문은 쓰기 없는 question API로 전달한다. 서버가 소유권·소스/지표 버전·미리보기 digest를 검증한 뒤 기존 의도 분류기를 사용한다. save-only는 기존 proposal을 다시 미리보고 같은 digest/requestId로 저장한다. 다른 생성 질문은 기존 새 제안 흐름을 유지하며, 변경+저장 혼합은 기존 초안을 임의 대체·저장하지 않고 저장 후 블록 편집을 안내한다.
- 모호한 계산은 clarification 질문으로 반환한다. 원래 질문/이전 미리보기는 보존하고 저장은 막는다. 새 소스 선택·취소·중지는 저장 의도와 이전 소스 proposal의 연결을 끊는다.
- 프런트는 검증한 preview를 표시하고 명시된 저장만 기존 영수증 API에 연결한다. 일반 저장 버튼/수정 모드는 유지한다. 새 저장 결과의 revision을 게시 준비에 전달하며 실제 링크 공개는 별도 버튼이다.
- 생성 영수증 재시도는 같은 ID를 반환한다. 기존 영수증은 과거 revision을 기록하지 않으므로 재생 결과로 자동 게시 미리보기를 열지 않는다. 저장된 분석의 게시 화면에서 범위/현재 결과를 다시 미리본 후 공개한다. 재생에 최신 revision을 과거 저장 버전처럼 붙이지 않는다. DB 변경은 없다.
- 목록 재조회 중 저장 handoff로 이동해도 목록이 띄운 전역 로딩은 unmount에서 해제한다. 새 게시 화면 컨트롤을 이전 화면의 로딩 막으로 가리지 않는다.
- 저장이 성공한 후 게시 준비 오류는 저장 성공을 취소하지 않는다. 생성/미리보기 오류·타임아웃/취소는 추가 저장을 하지 않고, 결과 불명확 저장은 같은 requestId로 재확인한다.

## 검증

서버: 명시/부정/잘못된 플래그·권한·digest 변경·취소·미리보기 전후 검증·영수증 재시도. FE: 기존 미리보기 보존·소스 변경 격리·신규 저장 revision handoff·영수증 재생의 수동 재미리보기·저장 실패/중지. Ego45 전체 canonical 파일에서 생성→후속 질문→저장/게시 준비→reload 및 기존 editor 직접/AI 편집·공개·수신자 매핑·중지까지 TC005를 연결한다. 기존 한 블록 혼합 변경 제한·게시 안전 집계 제한을 숨기지 않는다. 사람 승인·운영 배포·실휴대폰 전체 검증은 별도다.
