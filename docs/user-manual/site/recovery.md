# 초안·충돌 복구

**원칙:** 실패가 보이면 질문과 초안을 먼저 확인하고, 서버에 저장됐는지 불확실하면 결과 조회부터 진행합니다.

## AI 실패·변경 없는 응답

응답 실패나 설명만 있는 응답은 수정 성공이 아닙니다. 현재 초안을 확인하고 수정 대상·열·계산·유지할 내용을 구체적으로 적어 다시 요청합니다. 다시 질문하기 위해 기존 블록을 지울 필요는 없습니다.

## 새로고침 후 복구

1. 같은 계정·조직·화면·탭으로 돌아옵니다.
2. **블록 초안 복구 / 질문 복구** 안내를 확인합니다.
3. 복구할 내용을 읽고 선택합니다.
4. **미리보기 → 저장 → 새로고침**으로 확인합니다.

복구는 브라우저 보관 조건을 따르며 최대 24시간인 흐름이 있습니다. 모든 생성안·선택값, 다른 기기·탭에서의 복구를 보장하지 않습니다. 저장소 삭제·시크릿 창 종료 전에는 저장을 마치세요.

## 다른 탭에서 변경됨: 409

1. **최신 내용 비교**로 원격 저장본과 내 초안을 비교합니다.
2. 내 변경을 살리려면 **최신 기준으로 내 변경 재적용**을 선택합니다.
3. **최신본과 초안 비교 / 병합 미리보기**에서 겹치는 변경을 확인합니다.
4. 다시 미리보고 저장합니다.
5. 다시 409가 나면 최신 상태부터 재조회합니다.

**최신 내용 불러오기 (내 변경 버리기)**는 내 편집을 버리려는 경우에만 사용합니다. 최신 조회가 실패하면 질문·초안을 보존하고 조회를 재시도하세요. 충돌 확인이 되지 않은 상태에서 덮어쓰지 않습니다.

## 저장 응답이 끊겼을 때

화면에 성공이 안 보인다고 저장되지 않았다고 단정하지 않습니다. **저장 결과 확인** 또는 화면이 보관한 동일 요청 확인 동작을 사용합니다. 결과가 확인되기 전에 새 저장 요청을 반복 생성하지 마세요.

취소·보관 해제는 이미 서버에서 끝난 저장을 되돌리는 작업이 아닙니다. 저장 성공 후 원래 상태로 돌아가려면 별도 편집과 저장이 필요합니다.

## 로그인 상태가 달라졌을 때

재로그인이 필요하면 먼저 완료한 뒤 같은 계정·조직의 복구 안내를 확인합니다. 다른 계정으로 로그인해 이전 계정의 초안을 이어 쓸 수 있다고 가정하지 마세요. 토큰 갱신과 계정 변경은 다릅니다.

## 공유·복제 요청이 불확실할 때

조회 공유는 **최신 공유 관계 읽기**로 현재 상태를 읽고, 필요한 동의 후 **같은 공유 요청 확인**을 사용합니다. 복제 요청도 완료 사본을 먼저 확인합니다. 요청 기록이 없다는 사실만으로 서버 취소를 확정하지 않습니다.

**완료 확인:** 최신 저장본·내 초안·질문이 무엇인지 구분하고, 확인한 결과로 다시 미리보기와 저장을 마쳤습니다.
