# 기본 개념

SQL 문법보다 ‘어떤 자료에서 무엇을 어떤 기준으로 볼지’를 먼저 정하면 분석을 시작하기 쉽습니다.

## 소스 → 지표·차원 → 블록 → 대시보드

예를 들어 날짜·회사·매출이 있는 파일을 연결했다고 가정합니다.

| 개념            | 의미                         | 비용·마진 샘플 예시          |
| --------------- | ---------------------------- | ---------------------------- |
| 데이터 소스     | 분석할 자료와 연결           | 업로드한 `margin.csv`        |
| 열              | 자료의 한 항목               | `day`, `company`, `revenue`  |
| 지표(measure)   | 계산해서 볼 수치             | `revenue`의 합계             |
| 차원(dimension) | 수치를 나눌 기준             | 회사 `company`               |
| 시간 축         | 변화 흐름을 나눌 날짜 기준   | `day`를 일별로 집계          |
| 조건            | 계산에 포함할 범위           | 특정 회사, 특정 날짜         |
| 블록            | 숫자·차트 등 화면 단위       | 총매출 숫자와 날짜별 선 차트 |
| 대시보드        | 블록과 분석 기준을 묶은 결과 | 매출 분석                    |

‘회사별 매출’은 회사 이름을 합산하는 뜻이 아닙니다. `company`로 자료를 나눈 뒤 각 회사의 `revenue`를 합산합니다.

## 지표 정의와 표시 형식

`SUM(revenue)`와 `AVG(revenue)`는 같은 열을 사용해도 다른 질문에 답합니다. ‘소수점 두 자리’, ‘USD 표시’는 표시 형식이며 합계·평균 등의 계산과 구별합니다. 비율은 분자·분모·배율이 있어야 의미가 분명해집니다.

## 초안·미리보기·저장·게시

| 상태·동작 | 확인할 것                                     |
| --------- | --------------------------------------------- |
| AI 제안   | 질문에 대한 구성안. 저장 완료가 아님          |
| 미리보기  | 제안된 계산·조건으로 나온 숫자와 차트         |
| 초안      | 내 편집 내용. 아직 서버 저장본과 다를 수 있음 |
| 저장      | 편집 가능한 내 대시보드 갱신                  |
| 게시      | 저장본으로 읽기 전용 스냅샷 생성              |
| 재게시    | 새 저장본을 게시본에 반영                     |
| 독립 사본 | 원본과 별도로 저장한 내 대시보드              |

::: info 같은 화면이어도 기준이 다를 수 있습니다
오늘 편집한 초안, 어제 저장한 대시보드, 지난주 게시한 스냅샷은 서로 다른 상태일 수 있습니다. 숫자가 다르면 기간·필터·지표 버전과 저장·재게시 여부를 먼저 비교하세요.
:::
