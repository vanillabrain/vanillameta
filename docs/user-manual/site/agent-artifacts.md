# 프롬프트로 Artifact 만들기

질문에서 시작해 숫자·시계열·블록 배치를 가진 대시보드를 저장하고, 공유·재사용 가능한 분석 결과로 완성해 봅니다. 이 가이드에서 **Artifact**는 설명 문장이나 차트 이미지 한 장이 아니라 **데이터와 계산 기준에 연결된 저장 분석**을 뜻합니다.

## 어디서 질문하나요?

| 시작하는 곳                               | 현재 할 수 있는 일                                                          |
| ----------------------------------------- | --------------------------------------------------------------------------- |
| VanillaMeta 질문 화면                     | 서버의 Codex 실행으로 분석 제안 → 미리보기 → 저장                           |
| 저장 분석의 Studio AI                     | 현재 초안·선택 블록 문맥에서 질문/지원되는 수정 → 확인 → 저장               |
| 외부 Codex·Claude Code 대화               | 요청 문장을 정리한 뒤 앱으로 전달하는 아래 실습                             |
| 외부 에이전트의 VanillaMeta MCP 직접 호출 | 소스·지표 확인 → 생성·미리보기 → 승인 후 비공개 저장. [연결 실습](./mcp.md) |

외부 에이전트가 답변에서 “만들었다”고 말해도 실제 대시보드 번호·저장 상태가 없으면 VanillaMeta에 저장된 결과가 아닙니다.

## 외부 에이전트에서 바로 만들고 싶다면

[MCP 연결 실습](./mcp.md)을 먼저 진행하세요. 실제 도구로 내 소스를 선택하고 제안·전체 미리보기·별도 승인 저장 후 Studio 링크를 받을 수 있습니다. 아래는 MCP를 연결하지 않은 환경에서도 사용할 수 있는 요청 정리와 앱 제작 절차입니다. MCP 자체는 저장본 수정·게시·공유를 실행하지 않으므로 저장한 뒤에는 앱에서 이어갑니다.

## 1. 외부 코딩 에이전트에서 요청 정리하기

이미 사용하는 코딩 에이전트가 있다면 아래처럼 **질문 작성만** 요청할 수 있습니다. 여기서는 원본 파일이나 인증키 없이 열 구조만 전달합니다. 이 단계는 VanillaMeta 직접 연결을 요구하지 않습니다.

```text
VanillaMeta에 입력할 분석 요청문을 작성해줘.
데이터 열은 day(날짜), revenue(숫자), cost(숫자), company(문자열)야.
목표는 총매출 숫자와 날짜별 매출 시계열을 함께 보는 것이야.
revenue 합계를 사용하고, 전체 기간·UTC 기준으로 시작해줘.
이름은 매출 분석으로 해줘.
알 수 없는 열이나 계산값은 만들지 말고 필요한 확인사항을 알려줘.
지금은 문장만 작성하고 생성·저장·게시했다고 말하지 마.
```

출력된 요청에서 열 이름과 계산법을 확인한 뒤 앱의 질문란에 붙여 넣습니다. 바로 앱에서 아래 요청을 입력해도 됩니다. 외부 대화의 맥락이 앱으로 자동 전달되지는 않으므로 필요한 조건을 요청문에 포함하세요.

## 2. 앱에서 생성 요청

**질문으로 대시보드 만들기 → 내 데이터로 시작하기 → 비용·마진 샘플**을 선택합니다. 준비된 소스가 선택되었는지 확인하고 다음을 입력합니다.

> 총매출 SUM(revenue)을 숫자 지표로, 날짜별 매출 추세를 시계열 차트로 만들어줘. 제목은 매출 분석으로 해줘.

**지표와 차트 제안**을 누릅니다. 현재 생성 흐름은 지원되는 서버 저장 소스 하나와 최대 6개 블록을 사용합니다.

![소스를 선택하고 숫자와 시계열 생성 질문을 입력하는 화면](../images/01-source-question.png)

일반적인 “분석해줘”보다 대상 열·집계·차트 형태를 구체적으로 적으면 결과를 검토하기 쉽습니다. 회사별 비교·마진율 등 다른 요청은 [질문 예시](./recipes.md)를 참고하세요.

## 3. 숫자와 시계열을 함께 검토

**계산 미리보기**에서 다음을 확인합니다.

- 숫자 지표와 날짜별 시계열이 모두 있습니다.
- 매출은 `SUM(revenue)`, 날짜는 `day`입니다.
- 전체 기간·UTC·필터 없음 기준입니다.
- 이 샘플의 총매출은 **14,937.49 USD**입니다.

![합계와 날짜별 추세를 함께 확인하는 생성 미리보기](../images/02-ai-preview.png)

샘플 버전이나 필터가 다르면 기준값도 달라질 수 있습니다. **계산 기준 확인**과 **데이터 표 보기**로 확인하세요. AI 설명이 그럴듯하다는 이유만으로 다른 계산을 저장하지 않습니다.

## 4. 저장하고 다시 열기

**Studio에 저장하고 열기**를 누릅니다. 새 대시보드가 열리고 **저장됨**이 표시되면 새로고침합니다. 소스·숫자·시계열·제목이 유지되는지 확인합니다.

이때부터 앱에서 다시 열 수 있는 저장 분석이 있습니다. 아직 공개 게시나 조직 공유를 한 것은 아닙니다. 생성 중 실패했다면 초안과 질문을 확인하고 [복구 안내](./recovery.md)를 따르세요.

## 5. 후속 프롬프트로 수정

Studio에서 **시계열 블록 설정 → AI**를 열고 다음을 요청합니다.

> 선택한 시계열 블록의 제목을 날짜별 매출로 바꿔줘. 계산식과 다른 블록은 유지해줘.

![선택한 시계열의 제목을 후속 질문으로 바꾸는 화면](../images/03-ai-edit.png)

제안이 적용된 초안과 변경 대상, **전체 미리보기** 요구 여부를 확인합니다. 숫자와 비대상 블록이 유지되면 **저장 → 새로고침**합니다. “변경 없음” 응답은 수정 완료가 아니므로 대상과 요청을 다시 명확히 합니다.

AI가 모든 블록 추가·삭제·임의 계산식 변경을 어떤 질문란에서든 수행하는 것은 아닙니다. 현재 선택 블록과 지원 범위에 맞춰 요청하고, 배치·크기 조정은 [블록 편집](./ai-edit.md)을 사용하세요. 중앙 저장 지표의 계산식 변경과 개별 블록 제목 수정도 서로 다릅니다.

## 6. 게시 또는 사내 공유 선택

- **내가 확인할 게시본:** 게시·공유에서 비공개로 게시합니다.
- **링크가 있는 사람에게 공개:** 공개 범위와 만료를 확인한 뒤 링크 공개로 게시합니다. 수정 후에는 재게시가 필요합니다.
- **같은 조직 직원에게만 전달:** 조직 화면에서 원본 소스 읽기와 대시보드 조회 공유를 각각 설정합니다.

![게시 범위와 링크 공유를 확인하는 기존 검증 화면](../images/06-published-share-1440.png)

공개 링크는 설명에 적힌 범위를 확인하고 만들며, 시연 후 필요 없으면 게시 중지합니다. [게시·링크 공유](./publish.md)와 [조직 공유 샘플](./team-reuse-walkthrough.md)을 따라 목적에 맞게 선택하세요.

## 7. 다른 데이터로 재사용

받은 자료의 **내 소스로 복제** 또는 지원되는 게시본 복제를 사용합니다. 본인 소스를 선택하고 필요한 열을 연결한 다음 **모든 블록을 재계산한 미리보기**를 확인해 새 비공개 사본을 만듭니다.

[조직 공유·재사용 실습](./team-reuse-walkthrough.md)에서는 원본600 USD를 내 소스1200 USD로 재계산하고, 원본 공유 회수 후에도 사본이 유지되는 과정을 실제 화면으로 확인할 수 있습니다.

## 이 실습을 마쳤다면

대시보드 번호, 소스, 계산 기준, 숫자·차트, 저장 상태를 확인할 수 있어야 합니다. 게시했다면 공개 범위와 게시본을, 재사용했다면 원본과 사본의 구분도 확인합니다. 외부 에이전트 답변, 앱의 미저장 생성안, 저장본, 게시본은 각 단계의 결과로 구별하세요.

::: info 실행 근거
생성·제목 수정·저장·게시 화면은 기존 합성 샘플의 실제 검증 캡처를 재사용합니다. 조직 공유·소스 교체는 별도 샘플 가이드의 실제 여정을 연결합니다. 이 페이지의 기존 캡처와 외부 요청 정리 예시는 MCP 실행 증거와 구분합니다. 새 [MCP 실습](./mcp.md)에는 실제 Codex 호스트의 직접 생성·저장과 새 Studio 캡처가 있습니다. Claude Code 실행은 아직 별도입니다.
:::
