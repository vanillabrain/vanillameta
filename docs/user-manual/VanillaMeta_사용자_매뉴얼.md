# VanillaMeta 사용자 매뉴얼

데이터 연결 → AI 분석 생성 → 수정 → 저장 → 게시·공유 순서로 안내합니다. 처음에는 [샘플로 시작하기](빠른_시작_가이드.md)를 권합니다. 접속 주소·계정은 운영자가 안내하며, SQL 지식은 지원되는 파일 기반 AI 분석의 필수 조건이 아닙니다.

## 시작 전에 알아둘 것

| 용어            | 뜻                                |
| --------------- | --------------------------------- |
| 데이터 소스     | 분석할 파일이나 데이터 연결       |
| 지표(measure)   | 매출 합계처럼 계산할 값           |
| 차원(dimension) | 회사·상품처럼 값을 나누어 볼 기준 |
| 블록            | 숫자·차트 등 대시보드의 구성 요소 |
| 초안            | 아직 저장하지 않은 편집 내용      |
| 미리보기        | 제안된 계산·차트를 확인하는 결과  |
| 저장본          | 새로고침 후 다시 여는 내 대시보드 |
| 게시본          | 저장본으로 만든 읽기 전용 스냅샷  |

현재 Studio 생성은 지원되는 서버 저장 소스 하나로 최대 6개 블록을 구성하는 흐름입니다. 데이터 연결 목록에 있다고 모든 연결이 Studio에서 지원되는 것은 아닙니다. 외부 DB의 여러 테이블을 질문 한 번으로 자동 결합한다고 가정하지 마세요.

## 데이터 연결

### 샘플로 시작

대시보드 목록(`/dashboard`)에서 **질문으로 대시보드 만들기**를 눌러 `/studio/new`로 이동합니다. **매출·환불 샘플**, **비용·마진 샘플**, **앱 전환 샘플**, **Rill 광고 샘플** 중 목적에 맞는 데이터를 준비합니다. 매출·환불/비용·마진/앱 전환은 합성 샘플이며, Rill 광고 샘플은 공개 데모 데이터입니다.

샘플 선택은 분석용 소스 준비입니다. AI 질문 실행과 대시보드 저장·게시는 이후 별도로 진행합니다. 대시보드 목록의 **샘플 대시보드 보기**는 기존 샘플 보고서를 여는 기능이므로 질문으로 새로 만드는 흐름과 구별하세요.

### 내 파일로 시작

1. Studio 생성 화면에서 **파일 선택**을 누르고 CSV·JSON·Parquet 파일을 선택합니다.
2. 파일 준비 결과와 열 이름·형식을 확인합니다. 날짜는 날짜로, 매출·수량은 숫자로 인식되는지 확인하세요.
3. 준비한 소스를 **저장된 데이터**에서 선택합니다. 목록이 오래되었다면 **소스 새로 확인**을 누릅니다.
4. **데이터 검색**으로 이름을 찾거나 **데이터 업무 설명 확인**으로 저장된 설명을 살펴봅니다. 설명 조회가 실제 계산이나 지표 검증을 대신하지는 않습니다.
5. 질문을 입력해 계산 미리보기로 데이터가 의도대로 읽히는지 확인합니다.

대시보드 목록의 **일반 CSV·JSON·Parquet 분석**(`/data/file`)에서도 파일을 준비할 수 있습니다. 브라우저 안의 일회성 분석과 서버에 데이터셋으로 저장하는 작업은 구별하세요. 다른 화면에서 재사용하려면 서버 저장을 완료하고 Studio의 소스 목록에서 확인해야 합니다.

파일에 필수 열이 없거나 날짜 형식이 잘못되었다면 안내된 열·형식을 확인해 파일을 수정한 뒤 다시 준비합니다. 오류를 없애려고 잘못된 날짜나 누락 값을 임의로 채우지 마세요. 파일을 교체하면 기존 미리보기와 기준이 달라질 수 있으므로 다시 확인합니다.

CSV 업로드 후 소스 이름이 `margin`, 18행·12개 열로 확인된 모바일 예시입니다. 파일명에서 확장자를 제외한 이름이 표시될 수 있습니다.

### 외부 데이터베이스 연결

**데이터 연결 관리**(`/data`)에서 데이터 소스 생성 화면으로 이동해 지원되는 연결 유형을 선택합니다. 운영자가 제공한 접속 정보로 **연결 테스트** 후 **연결 저장**을 진행합니다. 데이터베이스는 사용자의 PC뿐 아니라 VanillaMeta 서버에서도 접근 가능해야 합니다.

연결 유형에 따라 서버 드라이버·설정이 필요합니다. Studio에서 **미지원**으로 표시되면 연결 성공만으로 AI 분석을 진행할 수는 없습니다. 기존 데이터셋·위젯 편집기를 사용하거나, 담당자와 지원되는 파일 소스 준비 방법을 확인하세요. 비밀번호·접속 문자열을 AI 질문에 붙여 넣을 필요는 없습니다.

## AI 분석 생성

1. **질문으로 대시보드 만들기**에서 소스를 선택합니다.
2. **만들 대시보드 요청**에 보고 싶은 값, 나눌 기준, 시간 단위, 차트 형태를 적습니다.
3. **지표와 차트 제안**을 누릅니다.
4. **계산 미리보기**에서 숫자와 시계열을 함께 확인합니다.
5. **계산 기준 확인**으로 합계·평균 등의 집계와 대상 열을 확인하고, **데이터 표 보기**로 결과를 대조합니다.
6. 구성과 값이 맞으면 **Studio에 저장하고 열기**를 누릅니다.

비용·마진 샘플의 질문 예시:

> revenue의 합계를 숫자로 보여주고 day 기준 일별 매출 시계열을 만들어줘. company별 매출 막대 차트도 추가해줘.

질문에는 실제 열·지표 이름을 사용하세요. 비율은 분자·분모와 0일 때의 처리, 날짜는 기간·시간대, 통화는 표시 단위를 함께 적으면 결과를 판단하기 쉽습니다. AI 설명만 읽고 계산이 맞다고 판단하지 말고 미리보기의 기준과 값을 확인하세요.

저장 전에 고치려면 **후속 질문 · 저장 전 편집**에서 **수정할 블록**을 고르고 **생성안 수정 요청**을 입력한 뒤 **수정안 미리보기**를 실행합니다. 대화형 생성안에서는 **수정안 전체 미리보기**로 표시될 수 있습니다. 이 단계는 아직 저장 전입니다.

## 저장한 분석 수정

1. 대시보드를 Studio 편집 화면(`/dashboard/대시보드번호/studio`)에서 엽니다. 주소의 대시보드번호는 실제 번호입니다.
2. 수정할 블록 오른쪽 **설정 아이콘**을 눌러 선택한 뒤, 보조 패널의 **AI** 탭을 누릅니다. 모바일 설정창에서도 AI 탭으로 전환합니다. 특정 블록을 고르지 않는 일반 질문은 **AI 열기**로 시작할 수 있습니다.
3. **AI에게 요청할 내용**에 요청을 적고 **전송**합니다.
4. 대상 블록·계산 기준·기간·필터와 다른 블록의 보존 여부를 확인합니다. **전체 미리보기**가 필요하다는 안내가 나오면 먼저 실행합니다.
5. **저장**을 눌러 **저장됨**을 확인한 뒤 새로고침합니다.

요청 예시:

- “선택한 차트를 주간 매출 추세로 바꿔줘. 숫자 지표는 유지해줘.”
- “첫 번째 숫자 블록의 제목을 총매출로 바꿔줘. 계산식은 유지해줘.”
- “company별 revenue 합계를 막대 차트 블록으로 추가해줘.”

일반 수정 요청은 초안을 바꿉니다. 다만 **“저장하고 링크로 공유해줘”**처럼 저장·공개를 명시하면 실제 저장과 링크 생성까지 실행할 수 있습니다. 결과의 실행 기록과 공개 범위를 확인하세요. 처음에는 수정 → 미리보기 → 수동 저장 → 게시 순서로 진행하면 단계별 결과를 확인하기 쉽습니다.

AI가 변경 없는 응답을 반복하면 대상과 변경할 내용을 구체적으로 다시 질문합니다. 설명만 한 응답이나 추가 확인 질문은 변경 완료가 아닙니다.

### 조건·계산 기준 확인

**분석 기준**에서 소스·기간·시간대·필터·지표 버전을 확인하세요. 기준을 편집했다는 이유만으로 모든 결과가 다시 계산되었다고 판단하지 마세요. 미리보기 결과에 적용된 범위를 확인합니다.

AI가 조건 변경을 제안하면 현재 조건과 제안 조건을 비교하고 **제안 조건 전체 미리보기 → 조건 변경안 적용** 순서로 확인한 뒤 저장합니다. 제안을 받았다는 것만으로 조건이 적용되지는 않습니다. 오래된 기준이라는 안내가 나오면 현재 기준으로 다시 질문하세요.

저장 지표의 계산식·버전이나 원본 파일이 바뀌어도 과거 분석·게시본이 모두 자동 갱신되는 것으로 가정하지 마세요. 새 기준을 채택하는 미리보기와 저장 여부를 확인하고 게시본은 별도로 재게시합니다.

### 블록 배치와 모바일 편집

블록의 이동 핸들로 위치를 바꾸고 크기 조절 핸들로 크기를 조절합니다. 화면이 작으면 블록을 선택한 뒤 제공되는 순서·크기 조절 버튼을 이용하세요. 겹침·경계 제한으로 원하는 위치에 놓이지 않을 수 있습니다.

**되돌리기 / 다시 실행**으로 편집을 확인하고 저장합니다. 모바일에서도 제목·버튼·입력창이 잘리거나 겹치지 않는지, 숫자와 시계열이 읽히는지 확인하세요. 화면 폭에 따라 배치가 달라질 수 있으므로 데스크톱 위치만으로 모바일 배치를 판단하지 마세요.

## 저장·새로고침·오류 복구

저장 성공은 **저장됨** 상태와 새로고침 후 결과로 확인합니다. 여러 블록을 바꿨다면 모든 변경이 미리보기에 포함되어 있는지 확인한 뒤 저장하세요.

| 상황                    | 할 일                                                                                                                   |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| AI 응답 실패·변경 없음  | 남아 있는 질문·초안을 확인하고 구체적으로 다시 요청합니다.                                                              |
| 미리보기 실패           | 오류 원인·소스·권한을 확인하고 **미리보기 다시 시도** 등 화면의 재시도 동작을 사용합니다.                               |
| 저장 응답이 끊김        | 실패로 단정해 새 요청을 반복하지 말고 **저장 결과 확인** 또는 보존한 동일 요청의 재시도로 결과를 확인합니다.            |
| 다른 탭에서 변경됨(409) | **최신 내용 비교**로 양쪽 변경을 확인합니다. 초안을 유지하려면 **최신 기준으로 내 변경 재적용** 후 다시 미리보기합니다. |
| 최신 상태 조회 실패     | 질문·초안을 보존하고 조회부터 재시도합니다. 충돌 여부를 모르는 상태에서 저장을 강행하지 않습니다.                       |
| 권한이 없어 편집 불가   | 소유자·조직 관리자에게 현재 대시보드 편집권과 소스 접근권을 확인합니다.                                                 |

새로고침 후 **블록 초안 복구 / 질문 복구** 안내가 보이면 내용을 확인하고 복구합니다. 원격 변경이 있다면 **최신본과 초안 비교 / 병합 미리보기**를 거칩니다. **최신 내용 불러오기 (내 변경 버리기)**는 내 편집을 버릴 때만 선택하세요.

복구는 해당 계정·조직·화면·탭의 보관 조건에 따르며 최대 24시간인 흐름이 있습니다. 모든 생성안·선택값이 복구되거나 다른 기기에서도 이어진다고 보장하지 않습니다. 브라우저 저장소 삭제·시크릿 모드 종료 전에는 저장을 완료하세요. 취소·보관 해제가 이미 서버에서 끝난 저장을 되돌린다는 의미도 아닙니다.

## 게시·링크 공유

| 작업      | 결과                                         |
| --------- | -------------------------------------------- |
| 저장      | 내 편집 가능한 대시보드 갱신                 |
| 게시      | 저장본으로 읽기 전용 스냅샷 생성             |
| 링크 복사 | 현재 게시 링크 복사. 공개 범위는 바뀌지 않음 |
| 재게시    | 수정한 저장본을 게시본에 반영                |
| 게시 중지 | 기존 게시 링크로 제공하는 게시본 중지        |

### 게시하기

1. 초안을 먼저 **저장**합니다.
2. **게시·공유**에서 **게시할 저장본 기준**과 분석 기준을 확인합니다.
3. 공개 범위를 선택합니다.
   - **비공개 · 로그인한 소유자만 조회**: 소유자 확인용입니다. 링크 전달만으로 직원에게 권한이 생기지 않습니다.
   - **링크 공개 · 링크가 있는 모든 사람이 조회**: 링크를 가진 사람이 열 수 있습니다. 조직 내부 전용과 다릅니다.
4. 필요한 경우 **링크 만료 시각 (내 시간대)**을 지정합니다. 비워 두면 자동 만료 시각을 지정하지 않은 상태입니다.
5. **내 데이터로 복제 허용** 여부를 선택합니다. 활성화할 수 없는 구성은 화면의 제한 사유를 확인합니다.
6. **게시하기**를 누르고 게시 범위·버전·만료를 확인합니다.
7. **게시본 열기**로 숫자·차트를 확인한 뒤 **링크 복사**로 전달합니다.

### 수정·중지하기

편집 초안을 바꿔도 게시본은 그대로입니다. 새 결과를 전달하려면 **미리보기 → 저장 → 게시·공유 → 재게시**를 진행하세요. 자동 실시간 갱신이나 예약 갱신을 전제로 사용하지 마세요.

제공을 끝내려면 **게시 중지 → 중지 확인**을 누르고 링크를 다시 확인합니다. 만료·게시 중지·현재 소스 권한 변경 등으로 게시본 접근이 제한될 수 있습니다. 이미 열람·내보내기한 자료나 별도로 저장한 독립 사본까지 회수되는 것은 아닙니다.

기존 위젯 대시보드의 `/share/…`, `/embed/…` 방식은 Studio의 `/published/…` 게시본과 별도 기능입니다. 이 매뉴얼의 게시 절차는 Studio 기준입니다.

## 조직 직원에게 조회 공유

조직 공유는 계정 메뉴의 **조직·직원** 화면(`/organization`)에서 관리합니다. Studio의 **조직 접근**은 별도의 조직 접근 관리 화면이므로 아래 직원 전달 메뉴와 혼동하지 마세요.

공유 관리가 가능한 현재 소유 관리자 기준:

1. **조직·직원** 화면에서 **자원별 권한 관리 열기**를 누릅니다. 공유할 직원이 같은 조직의 활성 구성원인지 확인합니다.
2. 먼저 분석에 쓰는 **데이터 소스**의 **권한 관리 → 새 수신자에게 권한 부여**를 엽니다. 수신자를 선택하고 **읽기** 권한과 변경 요약·동의란을 확인한 뒤 **권한 저장**을 누릅니다. 여러 소스를 사용한다면 각각 확인합니다.
3. 대상 **대시보드**의 **권한 관리**를 엽니다.
4. **조회 공유 열기 → 최신 공유 관계 읽기**로 현재 직원과 관계를 확인합니다.
5. **조회 공유**를 선택하고 받을 직원을 고릅니다.
6. **독립 복제 설정**을 확인합니다. 복제를 허용하려면 별도 동의 안내를 읽습니다.
7. 변경 미리보기와 확인란을 확인한 뒤 **공유 변경 저장**을 누릅니다.
8. 수신자는 같은 조직으로 로그인해 **받은 자료 열기 → 받은 자료 다시 읽기 → 열기**로 확인합니다. 숫자와 시계열이 나오는지 확인하고 새로고침합니다.

<img src="images/10-received-mobile.png" width="390" alt="수신자의 받은 자료 목록과 열기 버튼" />

대시보드 조회 공유와 **원 소스 읽기 권한은 별도**입니다. 소스 읽기 권한이 없으면 공유 저장 단계부터 거절될 수 있습니다. 열리지 않으면 관리자가 자원별 권한에서 해당 데이터 소스의 읽기 권한도 확인해야 합니다. 읽기 공유는 편집·게시·내보내기 전체 권한을 자동으로 주지 않습니다.

회수할 때는 최신 관계를 읽고 **공유 회수**를 선택해 대상·변경을 확인한 뒤 저장합니다. 다른 직접 권한이나 그룹 권한이 남아 있으면 계속 접근할 수 있으므로 권한 전체를 함께 확인하세요. 회수는 원본·이미 만든 독립 사본을 삭제하지 않습니다. 일반 직원에게 관리 메뉴가 보이지 않으면 조직 관리자에게 요청하세요.

공유 저장 결과가 불확실하면 **최신 공유 관계 읽기**로 확인합니다. 보존된 요청이 있다면 소스 권한 등 원인을 해결한 뒤 확인란을 선택하고 **같은 공유 요청 확인**으로 재시도하세요. 새 공유를 반복 생성하거나 보관 해제를 서버 취소로 간주하지 마세요.

## 복제해서 내 데이터로 재사용

내 분석은 **저장본 복제**로 마지막 저장본을 바탕으로 복제합니다. 미저장 초안까지 복제되는 것은 아닙니다.

받은 자료나 게시본은 소유자가 복제를 허용한 경우에만 재사용할 수 있습니다. 복제 화면에서 본인 소스와 필요한 열을 연결하고 **미리보기 → 저장**을 진행해 새 비공개 사본을 만듭니다. 원본이 변경되는 작업이 아닙니다. 소스·필수 열·지표가 맞지 않으면 안내를 해결한 뒤 다시 미리보기하세요.

복제 허용은 지표 정의·조건·배치 등의 재사용을 포함합니다. 모든 게시 구성에서 지원되는 것은 아니며, 현재 Pivot을 포함한 게시본의 재사용 등은 제한될 수 있습니다. 이미 저장한 사본은 원본 공유를 회수해도 남습니다.

## 완료 확인

- 선택한 소스·기간·필터·단위가 의도와 맞습니다.
- 숫자와 시계열을 미리보기에서 함께 확인했습니다.
- 수정 후 저장 상태와 새로고침 결과가 일치합니다.
- 게시 범위·만료·복제 허용을 확인했습니다.
- 수정한 게시본은 재게시했고, 직원 공유는 수신자 권한까지 확인했습니다.
- 작은 화면에서도 제목·버튼·입력창·차트가 잘리지 않습니다.

문서 기준 버전과 검토 범위는 [가이드 안내](README.md)를 참고하세요.

단계별 실제 화면은 [화면 캡처 모음](스크린샷_가이드.md)을 참고하세요.
