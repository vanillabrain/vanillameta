## 1. VanillaMeta 소개

### VanillaMeta란?

VanillaMeta는 **코드 작성 없이 데이터를 시각화**할 수 있는 비즈니스 인텔리전스(BI) 솔루션입니다. 다양한 데이터베이스에 연결하여 SQL 쿼리로 데이터를 추출하고, 50가지 이상의 차트를 통해 인사이트를 시각화할 수 있습니다.

### 주요 기능

#### 📊 다양한 차트 지원
- **기본 차트**: 라인, 바, 파이, 영역, 산점도
- **고급 차트**: 히트맵, 트리맵, 레이더, 깔때기
- **3D 차트**: 3D 라인, 3D 바, 3D 산점도
- **특수 차트**: 캔들스틱, 워드클라우드, 게이지

#### 🔗 멀티 데이터베이스 지원
- MySQL, PostgreSQL, MariaDB
- Oracle, SQL Server, SQLite
- BigQuery, Snowflake, Amazon Redshift
- CockroachDB

#### 🎨 직관적인 대시보드
- 드래그 앤 드롭 위젯 배치
- 반응형 레이아웃
- 템플릿 기반 빠른 시작
- 실시간 데이터 업데이트

#### 🔒 보안 및 공유
- 안전한 데이터베이스 연결
- 대시보드 공유 링크 생성
- 사용자별 접근 권한 관리

### 시스템 요구사항

#### 지원 브라우저
- Chrome 90+ (권장)
- Firefox 88+
- Safari 14+
- Edge 90+

#### 권장 사양
- 화면 해상도: 1280x720 이상
- 인터넷 연결: 안정적인 광대역 연결
- 메모리: 4GB RAM 이상

## 2. 시작하기

### 회원가입

1. **VanillaMeta 웹사이트 접속**
   - 브라우저에서 VanillaMeta URL로 접속합니다.

2. **회원가입 버튼 클릭**
   - 로그인 페이지에서 "회원가입" 버튼을 클릭합니다.

3. **정보 입력**
   - 이메일 주소
   - 비밀번호 (8자 이상, 대소문자 및 숫자 포함)
   - 비밀번호 확인

4. **이용약관 동의**
   - 서비스 이용약관 및 개인정보 처리방침에 동의합니다.

5. **회원가입 완료**
   - "가입하기" 버튼을 클릭하여 회원가입을 완료합니다.

### 로그인

1. **로그인 페이지 접속**
   - VanillaMeta 메인 페이지에서 로그인 화면으로 이동합니다.

2. **인증 정보 입력**
   - 이메일 주소
   - 비밀번호

3. **로그인**
   - "로그인" 버튼을 클릭하여 서비스에 접속합니다.

### 첫 대시보드 만들기

1. **대시보드 메뉴 접속**
   - 로그인 후 좌측 메뉴에서 "대시보드"를 클릭합니다.

2. **새 대시보드 생성**
   - "새 대시보드" 버튼을 클릭합니다.

3. **대시보드 정보 입력**
   - 대시보드 이름: 의미 있는 이름 입력
   - 설명: 대시보드의 목적 설명 (선택사항)

4. **템플릿 선택 (선택사항)**
   - 빈 대시보드로 시작하거나
   - 미리 정의된 템플릿 중 선택

5. **생성 완료**
   - "생성" 버튼을 클릭하여 대시보드를 생성합니다.

## 3. 데이터 연결하기

### 데이터베이스 연결하기

#### 연결 과정

1. **데이터 메뉴 접속**
   - 좌측 메뉴에서 "데이터" → "데이터소스"를 클릭합니다.

2. **새 데이터소스 추가**
   - "데이터소스 추가" 버튼을 클릭합니다.

3. **데이터베이스 타입 선택**
   - 지원되는 데이터베이스 목록에서 해당 타입을 선택합니다.

4. **연결 정보 입력**

   **공통 필드:**
   - 연결 이름: 식별하기 쉬운 이름
   - 호스트: 데이터베이스 서버 주소
   - 포트: 데이터베이스 포트 번호
   - 데이터베이스명: 연결할 데이터베이스 이름
   - 사용자명: 데이터베이스 계정
   - 비밀번호: 데이터베이스 비밀번호

   **추가 옵션 (데이터베이스별):**
   - SSL 사용 여부
   - 연결 타임아웃
   - 문자셋 설정

### 지원되는 데이터베이스

#### MySQL / MariaDB
- 기본 포트: 3306
- SSL 지원
- 문자셋: UTF-8 권장

#### PostgreSQL
- 기본 포트: 5432
- SSL 지원
- 스키마 지정 가능

#### Oracle
- 기본 포트: 1521
- SID 또는 Service Name 사용
- TNS 연결 지원

#### SQL Server
- 기본 포트: 1433
- Windows 인증 또는 SQL 인증
- 인스턴스명 지정 가능

#### SQLite
- 파일 경로 지정
- 읽기 전용 모드 지원

#### BigQuery
- 프로젝트 ID 필요
- 서비스 계정 키 파일 업로드
- 데이터셋 지정

#### Snowflake
- 계정 URL 입력
- 웨어하우스 지정
- 역할(Role) 설정

### 연결 테스트

1. **연결 정보 확인**
   - 모든 필수 정보가 올바르게 입력되었는지 확인합니다.

2. **연결 테스트 실행**
   - "연결 테스트" 버튼을 클릭합니다.

3. **결과 확인**
   - ✅ 성공: "연결 성공" 메시지 표시
   - ❌ 실패: 오류 메시지 확인 및 조치

4. **저장**
   - 연결 테스트 성공 후 "저장" 버튼을 클릭합니다.

### 연결 문제 해결

#### 일반적인 오류와 해결 방법

**"호스트에 연결할 수 없습니다"**
- 호스트 주소가 올바른지 확인
- 방화벽 설정 확인
- VPN 연결 필요 여부 확인

**"인증 실패"**
- 사용자명과 비밀번호 재확인
- 계정의 원격 접속 권한 확인
- 데이터베이스명 확인

**"타임아웃 오류"**
- 네트워크 연결 상태 확인
- 데이터베이스 서버 상태 확인
- 연결 타임아웃 값 증가

**"SSL 연결 오류"**
- SSL 인증서 확인
- SSL 사용 옵션 체크/해제
- 인증서 파일 경로 확인

## 4. 데이터셋 관리

### 데이터셋이란?

데이터셋은 **SQL 쿼리의 실행 결과를 저장한 논리적 데이터 모음**입니다. 위젯(차트)을 생성할 때 사용되는 데이터의 원천이며, 하나의 데이터셋으로 여러 개의 위젯을 만들 수 있습니다.

### SQL 쿼리 작성하기

#### SQL 에디터 기능

- **구문 강조**: SQL 키워드 자동 하이라이트
- **자동 완성**: 테이블명, 컬럼명 자동 완성
- **구문 검사**: 실시간 SQL 문법 검증
- **포맷팅**: SQL 자동 정렬

#### 쿼리 작성 가이드라인

1. **SELECT 문 사용**
   ```sql
   SELECT 
       column1,
       column2,
       SUM(amount) as total_amount
   FROM 
       table_name
   WHERE 
       date >= '2024-01-01'
   GROUP BY 
       column1, column2
   ORDER BY 
       total_amount DESC
   ```

2. **별칭(Alias) 사용**
   - 컬럼에 의미 있는 별칭 부여
   - 한글 별칭 사용 가능

3. **데이터 타입 고려**
   - 숫자형: 차트의 값으로 사용
   - 문자형: 카테고리나 라벨로 사용
   - 날짜형: 시계열 차트에 활용

### 데이터셋 생성

1. **데이터셋 메뉴 접속**
   - "데이터" → "데이터셋"으로 이동합니다.

2. **새 데이터셋 생성**
   - "데이터셋 추가" 버튼을 클릭합니다.

3. **데이터소스 선택**
   - 등록된 데이터소스 중 하나를 선택합니다.

4. **SQL 쿼리 작성**
   - SQL 에디터에 쿼리를 작성합니다.

5. **쿼리 실행 및 검증**
   - "실행" 버튼을 클릭하여 쿼리를 테스트합니다.
   - 결과 데이터를 미리 확인합니다.

6. **데이터셋 정보 입력**
   - 데이터셋 이름: 용도를 알 수 있는 명확한 이름
   - 설명: 데이터셋의 내용과 용도 설명

7. **저장**
   - "저장" 버튼을 클릭하여 데이터셋을 생성합니다.

### 데이터셋 편집

1. **데이터셋 목록에서 선택**
   - 편집할 데이터셋의 "편집" 버튼을 클릭합니다.

2. **쿼리 수정**
   - SQL 쿼리를 수정합니다.

3. **변경사항 테스트**
   - "실행" 버튼으로 수정된 쿼리를 검증합니다.

4. **저장**
   - 변경사항을 저장합니다.

⚠️ **주의사항**: 데이터셋을 수정하면 이를 사용하는 모든 위젯에 영향을 줍니다.

### 데이터 미리보기

#### 미리보기 기능

- **데이터 샘플 확인**: 상위 100개 행 표시
- **컬럼 정보 확인**: 컬럼명, 데이터 타입
- **데이터 분포 확인**: NULL 값, 고유값 개수
- **익스포트**: CSV, Excel 형식으로 다운로드

#### 데이터 품질 체크

1. **NULL 값 확인**
   - 차트에 영향을 줄 수 있는 NULL 값 존재 여부

2. **데이터 타입 확인**
   - 숫자형 데이터가 문자로 저장되어 있지 않은지

3. **데이터 범위 확인**
   - 이상치나 잘못된 데이터 존재 여부

## 5. 위젯 생성하기

### 위젯이란?

위젯은 **데이터를 시각화한 차트 컴포넌트**입니다. 데이터셋의 정보를 다양한 차트 형태로 표현하며, 대시보드의 구성 요소가 됩니다.

### 차트 유형 선택하기

#### 기본 차트

**📈 라인 차트**
- 용도: 시간에 따른 추세 표현
- 적합한 데이터: 시계열 데이터
- 예시: 매출 추이, 방문자 수 변화

**📊 바 차트 / 컬럼 차트**
- 용도: 카테고리별 값 비교
- 적합한 데이터: 범주형 데이터
- 예시: 제품별 판매량, 지역별 매출

**🥧 파이 차트 / 도넛 차트**
- 용도: 전체 대비 비율 표현
- 적합한 데이터: 구성비 데이터
- 예시: 시장 점유율, 카테고리별 비중

**📉 영역 차트**
- 용도: 누적 값의 변화 표현
- 적합한 데이터: 시계열 누적 데이터
- 예시: 누적 매출, 재고 변화

#### 고급 차트

**🎯 산점도**
- 용도: 두 변수 간 상관관계 표현
- 적합한 데이터: 수치형 변수 쌍
- 예시: 가격 대비 판매량

**🗺️ 히트맵**
- 용도: 2차원 데이터의 강도 표현
- 적합한 데이터: 매트릭스 형태 데이터
- 예시: 시간대별 요일별 트래픽

**🌳 트리맵**
- 용도: 계층적 데이터의 비율 표현
- 적합한 데이터: 계층 구조 데이터
- 예시: 카테고리별 하위 제품 매출

**📡 레이더 차트**
- 용도: 다차원 데이터 비교
- 적합한 데이터: 여러 지표의 점수
- 예시: 제품 특성 비교

#### 특수 차트

**📈 캔들스틱 차트**
- 용도: 주가 변동 표현
- 적합한 데이터: OHLC 데이터
- 예시: 주식 차트

**☁️ 워드클라우드**
- 용도: 단어 빈도 시각화
- 적합한 데이터: 텍스트 빈도 데이터
- 예시: 키워드 분석

**🎚️ 게이지 차트**
- 용도: 목표 대비 달성률 표현
- 적합한 데이터: 단일 수치 데이터
- 예시: KPI 달성률

### 데이터 매핑

데이터 매핑은 **데이터셋의 컬럼을 차트의 축이나 요소에 연결**하는 과정입니다.

#### 매핑 구성 요소

1. **X축 (카테고리/시간)**
   - 주로 범주형 또는 시간 데이터
   - 예: 날짜, 제품명, 지역

2. **Y축 (값)**
   - 주로 수치형 데이터
   - 예: 매출액, 수량, 비율

3. **시리즈 (계열)**
   - 데이터를 그룹화하는 기준
   - 예: 제품 카테고리, 부서

4. **추가 매핑**
   - 색상: 카테고리별 구분
   - 크기: 버블 차트의 크기
   - 라벨: 데이터 포인트 표시

#### 매핑 예시

**라인 차트 매핑**
```
X축: 날짜
Y축: 매출액
시리즈: 제품 카테고리
```

**파이 차트 매핑**
```
카테고리: 지역
값: 판매량
```

#### 기본 스타일

1. **차트 제목**

   - 폰트 크기와 위치 조정

2. **색상 테마**
   - 기본 색상 팔레트 선택
   - 커스텀 색상 지정

3. **범례(Legend)**
   - 표시 위치: 상단, 하단, 좌측, 우측
   - 표시 여부 설정

4. **축 설정**
   - 축 제목 표시
   - 눈금 간격 조정
   - 최대/최소값 설정

#### 고급 스타일

1. **데이터 라벨**
   - 값 표시 여부
   - 표시 형식 (숫자, 퍼센트)

2. **툴팁**

   - 커스텀 포맷 설정

3. **애니메이션**
   - 차트 로딩 애니메이션
   - 데이터 업데이트 애니메이션

4. **그리드**
   - 격자선 표시 여부
   - 선 스타일과 색상

1. **위젯 이름 지정**

## 8. 문제 해결

### 자주 묻는 질문(FAQ)

#### 계정 관련

**Q: 비밀번호를 잊어버렸습니다.**
A: 로그인 화면에서 "비밀번호 찾기"를 클릭하고 가입한 이메일 주소를 입력하세요. 비밀번호 재설정 링크가 이메일로 발송됩니다.

**Q: 이메일 주소를 변경하고 싶습니다.**
A: 현재는 이메일 변경이 지원되지 않습니다. 새 계정을 생성하시기 바랍니다.

#### 데이터 연결 관련

**Q: 데이터베이스 연결이 자주 끊어집니다.**
A: 
- 네트워크 연결 상태를 확인하세요
- 데이터베이스 서버의 연결 제한 시간을 확인하세요
- 방화벽 설정에서 지속적인 연결을 허용하는지 확인하세요

**Q: 큰 데이터를 조회하면 타임아웃이 발생합니다.**
A:
- 쿼리를 최적화하여 필요한 데이터만 조회하세요
- 인덱스가 적절히 설정되어 있는지 확인하세요
- 데이터 집계는 데이터베이스에서 처리하도록 쿼리를 작성하세요

#### 차트 관련

**Q: 차트가 제대로 표시되지 않습니다.**
A:
- 데이터 타입이 올바른지 확인하세요 (숫자 데이터가 문자로 저장되어 있지 않은지)
- NULL 값이 포함되어 있는지 확인하세요
- 브라우저 캐시를 삭제하고 새로고침하세요

**Q: 한글이 깨져서 표시됩니다.**
A:
- 데이터베이스 문자셋이 UTF-8로 설정되어 있는지 확인하세요
- 데이터베이스 연결 설정에서 문자셋을 UTF-8로 지정하세요

### 오류 메시지 가이드

#### 연결 오류

**"Connection refused"**
- 원인: 데이터베이스 서버가 연결을 거부
- 해결: 
  - 서버 주소와 포트 확인
  - 방화벽 설정 확인
  - 데이터베이스 서버 실행 상태 확인

**"Authentication failed"**
- 원인: 인증 정보 오류
- 해결:
  - 사용자명과 비밀번호 재확인
  - 데이터베이스 접근 권한 확인
  - 특수문자가 포함된 경우 이스케이프 처리

**"Database does not exist"**
- 원인: 지정한 데이터베이스가 존재하지 않음
- 해결:
  - 데이터베이스 이름 정확히 확인
  - 대소문자 구분 확인
  - 데이터베이스 생성 여부 확인

#### 쿼리 오류

**"Syntax error"**
- 원인: SQL 문법 오류
- 해결:
  - SQL 문법 확인
  - 데이터베이스별 SQL 방언 확인
  - 예약어 사용 시 백틱(`) 또는 따옴표 사용

**"Column not found"**
- 원인: 존재하지 않는 컬럼 참조
- 해결:
  - 컬럼명 정확히 확인
  - 테이블 별칭 사용 시 정확히 지정
  - 대소문자 구분 확인

**"Timeout exceeded"**
- 원인: 쿼리 실행 시간 초과
- 해결:
  - 쿼리 최적화 (WHERE 조건 추가)
  - LIMIT 절로 결과 제한
  - 인덱스 활용 확인

### SQL 쿼리 예제집

#### 기본 집계
```sql
-- 일별 매출 합계
SELECT 
    DATE(order_date) as date,
    SUM(amount) as daily_sales
FROM orders
GROUP BY DATE(order_date)
ORDER BY date DESC
LIMIT 30
```

#### 카테고리별 분석
```sql
-- 제품 카테고리별 매출 비중
SELECT 
    category,
    SUM(amount) as sales,
    ROUND(SUM(amount) * 100.0 / 
        (SELECT SUM(amount) FROM orders), 2) as percentage
FROM orders
GROUP BY category
ORDER BY sales DESC
```

#### 시계열 분석
```sql
-- 월별 성장률
WITH monthly_sales AS (
    SELECT 
        DATE_FORMAT(order_date, '%Y-%m') as month,
        SUM(amount) as sales
    FROM orders
    GROUP BY DATE_FORMAT(order_date, '%Y-%m')
)
SELECT 
    month,
    sales,
    LAG(sales) OVER (ORDER BY month) as prev_sales,
    ROUND((sales - LAG(sales) OVER (ORDER BY month)) * 100.0 / 
        LAG(sales) OVER (ORDER BY month), 2) as growth_rate
FROM monthly_sales
ORDER BY month DESC
```

#### 순위 분석
```sql
-- 상위 10개 제품
SELECT 
    product_name,
    SUM(quantity) as total_quantity,
    SUM(amount) as total_sales,
    RANK() OVER (ORDER BY SUM(amount) DESC) as sales_rank
FROM order_details
GROUP BY product_name
ORDER BY total_sales DESC
LIMIT 10
```

#### 조건부 집계
```sql
-- 지역별 신규/기존 고객 매출
SELECT 
    region,
    SUM(CASE WHEN customer_type = 'new' THEN amount ELSE 0 END) as new_customer_sales,
    SUM(CASE WHEN customer_type = 'existing' THEN amount ELSE 0 END) as existing_customer_sales,
    SUM(amount) as total_sales
FROM orders
WHERE order_date >= DATE_SUB(CURRENT_DATE, INTERVAL 30 DAY)
GROUP BY region
```

#### 이동평균
```sql
-- 7일 이동평균 매출
SELECT 
    date,
    daily_sales,
    AVG(daily_sales) OVER (
        ORDER BY date 
        ROWS BETWEEN 6 PRECEDING AND CURRENT ROW
    ) as moving_avg_7days
FROM (
    SELECT 
        DATE(order_date) as date,
        SUM(amount) as daily_sales
    FROM orders
    GROUP BY DATE(order_date)
) daily_data
ORDER BY date DESC
```
