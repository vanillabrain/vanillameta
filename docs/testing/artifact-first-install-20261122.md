# Docker 첫 설치와 Claude Code 고객 리허설

2026년 11월 22일, macOS arm64의 Colima에서 새로 clone한 고객 브랜치와 빈 PostgreSQL 17 볼륨으로 실행했다. 고객용 절차는 [Docker README](../../README_DOCKER.md), [도움말 목차](../user-manual/site/contents.md), [첫 차트](../user-manual/site/codex-first-chart.md)에 있다. [전체 여정 영상](./media/first-install-20261122/journey.mp4)과 [실제 응답 및 저장값](./media/first-install-20261122/results.json)을 함께 볼 수 있다.

## 설치와 연결

새 프로젝트에서 `VM_WEB_PORT=53482 VM_API_PORT=53483 docker compose up --build -d --wait`를 실행했다. Compose 프로젝트 이름으로 볼륨을 분리했고 기존 이미지 레이어를 사용했다. 명령 시작부터 세 서비스 준비까지 198초, 첫 차트를 브라우저에서 확인하기까지 380초였다. 그중 첫 프롬프트부터 차트 값 확인까지는 29초였다. 별도 사전 점검 스택의 웹 53480, API 53481에서도 OAuth 발견 주소가 해당 인스턴스를 가리켰다.

두 사람이 각각 웹에서 가입했다. 소유자가 조직을 만들고 동료가 발급한 일회용 조직 연결 코드로 구성원 등록을 마쳤다. 조직이나 OAuth 클라이언트 등록에 SQL, 발표용 Compose 파일, 데이터 시드를 따로 실행할 단계가 없다. Docker Engine, Compose 및 모델을 호출할 수 있는 Claude Code 계정은 준비물이다. 검증 호스트에서는 설치돼 있던 독립 Compose 실행 파일을 격리 Docker CLI 설정의 플러그인으로 연결했다.

새 Claude 프로젝트에서 제품 화면의 등록 및 로그인 명령을 실행했다. 실제 Claude Code 2.1.330이 프로젝트 범위 MCP에 연결됐고 브라우저에서 조직과 아티팩트 두 범위를 승인했다. API 53483에서 승인 요청을 시작해 클라이언트 콜백 53683으로 돌아왔고 결과 링크는 웹 53482를 가리켰다. [승인 화면](./media/first-install-20261122/consent.png)

## 고객 여정 결과

| 단계 | 실제로 확인한 결과 |
| --- | --- |
| 새 대화에서 생성 | 실제 MCP 생성 응답이 버전 1과 링크를 반환했다. 브라우저 표에는 서울 120, 부산 80, 범례에는 만 원 단위와 발표용 합성 데이터가 표시됐다. |
| 같은 대화에서 수정 | 같은 ID와 링크에 버전 2가 저장됐다. 새로고침 후 서울 120, 부산 100이었다. PostgreSQL에는 버전 1의 부산 80도 남았다. [수정본](./media/first-install-20261122/revision-2.png) |
| 허브 재열기 | 상세 탭을 닫고 소유자가 내 아티팩트에서 제목을 검색해 버전 2를 열었다. |
| 공유 전·후 | 공유 전 동료의 검색에 차트가 없었고 직접 URL도 본문을 표시하지 않았다. 소유자가 수신자 로그인 ID로 지정 공유한 후 동료가 공유받음에서 버전 2를 읽었다. [읽기 전용 화면](./media/first-install-20261122/received.png) |
| 회수와 재기동 | 회수 후 같은 링크의 읽기가 차단됐다. Compose stop 및 start 후 소유자 API는 200, 동료 API는 404였다. 재기동 전후 PostgreSQL의 원본 ID, 현재 값, 과거 버전, 공유 수 0이 동일했다. [회수 후 화면](./media/first-install-20261122/revoked-after-restart.png) |
| 도움말 | VitePress 30페이지를 빌드하고 내부 참조 1,830개를 검사했다. Ego에서 목차 → Docker 안내 → 첫 차트를 열었고 튜토리얼 이미지 7개가 로드됐다. |

두 계정의 브라우저 저장소는 같은 설치본의 localhost와 127.0.0.1로 분리했다. 영상은 Ego 화면 녹화이며 명령 및 대화 장면은 실제 프로세스 출력을 브라우저에 표시했다. 비밀번호·일회용 코드 입력과 녹화 구간 사이의 대기 시간은 생략했다.

## 예외와 확인 범위

별도 스택에서 웹·API 포트 점유 충돌을 확인했다. 승인 취소 뒤 발급된 grant·code·token은 0건이고 같은 요청 재사용은 409였다. 읽기만 허용하면 조회 도구 두 개만 나타나며 생성 요청으로 저장된 아티팩트는 0건이었다. 승인 만료 후 버튼 비활성 및 403, 접근 토큰 만료 후 MCP의 401 응답을 확인했다. 만료 시각은 검증 환경에서 단축했다. 이 예외들은 실제 웹·HTTP에서 확인했고, 성공 여정의 두 프롬프트는 실제 Claude 호스트에서 실행했다. [예외 영상](./media/first-install-20261122/oauth-exceptions.mp4)

이전 리허설의 재접속 지연과 같은 현상은 이번에 확인하지 못했다. 허브에서 Ego 포인터가 제목 링크 옆의 목록 행에 적중한 경우와 탭 포커스 변경 중 공유 입력 요소가 교체된 경우는 관찰했다. 실제 키보드로 링크와 공유 동작을 완료했다. 운영 사이트 배포, 다른 컴퓨터에서 localhost 링크로 접속하는 구성, 실제 고객의 독립 사용성 평가는 이번 수용 범위 밖이다.
