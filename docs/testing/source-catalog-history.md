# UC050 후속: 저장 이력·업무 설명 비교

2026-10-18. 비교 기준 `8e606a11` 이후 변경. [계획](../plans/UC-050.md#후속-단위-저장-이력설명-비교)·[UC050](../use_cases/UC-050-manage-analysis-catalog.md)·[첫 구현](source-catalog.md). FR014/015/NFR007의 제한된 후속이며 전체 조직 카탈로그 수용 완료가 아니다.

## 사용자 흐름과 계약

Explore → 데이터 업무 설명 → 저장 이력·버전 비교에서 저장 시각/표시명과 버전을 본다. 최초에는 접혀 있으며 명시 클릭으로만 조회한다. 최신순20개 뒤 이전 이력을 추가로 읽을 수 있다. 두 정상 버전의 이전/이후를 선택하고 비교하면 소스 표시명/설명·열별 표시명/설명/단위의 변경 전후를 보여준다. 항목 없음(null)과 빈 값(빈 문자열)을 구분한다. 숫자 버전0은 미저장 기본값이므로 이력/비교 대상이 아니다. 저장 시각은 현재 기기 시간대임을 표시한다.

이 기능은 읽기만 수행하며 현재 편집 입력·저장본·원본 데이터·계산식·지표·대시보드·게시본을 변경하지 않는다. 저장 성공으로 편집기 버전이 바뀌면 이력 영역도 새로 시작한다. 구조/기준 데이터 버전 차이는 별도 안내하며 구조 복원이나 기존 분석에 대한 변경 영향으로 해석하지 않는다. 오래된 버전 복원은 이번 범위가 아니다.

- `POST /bi/source-catalog/history`: sourceId와 선택적 beforeVersion. 매번 기존 소유권 검사 뒤 고정20건·다음 커서를 반환한다. 프로파일/원본 행을 조회하지 않고 연결정보·metadata JSON·원본 경로/버전 지문을 반환하지 않는다. 손상 버전은 unreadable 요약으로 격리한다.
- `POST /bi/source-catalog/compare`: sourceId/fromVersion/toVersion. 동일 소스의 양의 정수 저장 버전이며 from<to여야 한다. 존재하지 않으면404, 손상된 선택 버전은409다. 변경은 허용한 업무 필드만 반환한다. 권한 없는 요청은 기존 서버 경계로 거절한다.
- UI는 공통 small 버튼·입력/레이블·기본 여백을 사용한다. 변경 전후는 좁은 화면1열/넓은 화면2열이고 긴 문자열은 줄바꿈한다. 이력/비교 오류는 입력과 분리하며 명시 재시도를 제공한다. 다른 소스/저장 버전으로 바뀐 뒤 늦게 끝난 응답은 표시하지 않는다.
