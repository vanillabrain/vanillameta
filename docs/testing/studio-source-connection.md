# Studio 생성된 소스에서 첫 질문으로 연결

Status: Draft · UC040/P2/FR009 · IMPLEMENTED / UI_BLOCKED.

## 부족점과 변경

[UC040 계획](../plans/UC-040.md)의 후속이다. 파일/샘플 준비가 sourceId를 반환한 뒤 전체 소스 목록을 다시 조회하던 의존성을 제거했다. 그 재조회만 실패해도 이미 생성한 소스를 선택하지 못하는 공백이었다. 이제 기존 profile/지표 GET을 통해 해당 ID의 지원·소유 접근·구조를 확인하고 검증 성공한 새 소스만 현재 선택 목록에 추가한다. 기존 항목/질문/생성안·저장/인증/요청 세대 경계를 유지한다. profile 실패는 기존 소스 새로 확인으로 같은 ID를 다시 조회하며 소스를 자동 재생성하지 않는다. 새 의존성/BE/DB 변경은 없다.

## 실행 증빙 · 2026-10-17

- 기존 제품 코드에서 두 번째 목록 조회가 실패하는 새 소스 회귀를 재현했다. 올바른 frontend 작업 경로와 초기 준비 완료를 기다리는 fixture로 재확인한 실패 로그는 `/tmp/vm-source-ready/red.log`다.
- 수정 후 StudioCreate/creationRecovery2파일32테스트 PASS. 미등재 새 ID 추가·두 번째 목록 GET0·프로필 실패 시 미검증 소스 미추가·명시 같은 ID 재조회·질문 보존·생성 POST1을 확인했다.
- 타입/변경 lint/FE build PASS. 최초 회귀 준비 대기와 lint의 증가 연산자/포맷을 보완했고 제품 경계는 유지했다. 로그는 같은 폴더의 `green/type/lint/build.log`다.
- **실제 UI BLOCKED:** Ego96은 로그인 만료로 `/login`에 진입했다. 기존 사용자 로그인에 영향을 주지 않는 새 localhost 검증 계정 생성/자격증명 파일 보관 시도가 자동 승인 검토에서 명시 권한 부족으로 거절됐다. 실제 계정 생성/업로드/자료 공개는 실행하지 않았으며 우회하지 않았다. 사용자에게 전용 계정·테스트 파일 생성 허용 또는 기존 계정 직접 로그인을 요청한 상태다.
- 허용/로그인 복구 후 같은 Ego96에서 테스트 CSV 준비→소스 구조 확인/첫 질문 입력→요청 횟수·390/768/1440 크기/정렬을 검증한다. UI 검증이 남아 있어 전체 완료나 고객 파일럿 PASS로 표시하지 않는다. 고객 자료·기대값은 여전히 미제공이다.

코드/문서는 정적·회귀 검증 결과와 UI_BLOCKED를 구분해 commit/push한다. 후속 실제 화면 검증·3폭 캡처는 남아 있으며 완료로 표시하지 않는다. Ego96을 기존 계정 로그인 화면으로 넘겨 사용자 인증을 기다린다. 승인 전 신규 계정/자격증명 생성 명령을 반복하거나 기존 사용자 세션·권한을 우회하지 않는다.
