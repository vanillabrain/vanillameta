## 구현과 계약

Explore → 데이터 업무 설명에서 수정 → 변경 내용 미리보기 → 표시한 변경 확인 → 확인한 변경 저장으로 이어진다. 최초 소스 등록 전 기본 표시명과 기존 저장 버전 모두 비교 기준으로 사용한다. 표시명/설명/단위의 변경 전후를 보여주며 입력 앞뒤 공백을 정규화한 서버 draft를 명시 저장한다. 변경0건 또는 미동의 상태에서는 UI 저장을 막는다. 미리보기 후 입력 변경/최신본 재조회·오류/소스 전환은 미리보기와 동의를 해제한다. 미리보기·이력 조회/비교는 초안 본문을 바꾸지 않으며 최신 설명 재조회는 기존 입력 폐기 확인을 거친다. 저장 성공 시 응답으로 저장 기준/이력을 갱신한다. 서버가 정규화 후 변경0건을 확인하면 입력 본문을 바꾸지 않고 미저장 표시만 정리하며 저장 요청을 보내지 않는다.

`POST /bi/source-catalog/preview`는 save와 같은 소유권/실제 열·현재 데이터/설명 버전·길이/중복 검증을 공유하고 저장하지 않는다. whitelist draft와 업무 필드 차이만 반환한다. 기존 save 입력 계약은 유지하므로 직접 API 사용자가 미리보기 토큰을 제출해야 하는 새 보안 계약은 아니다. UI는 표시한 서버 draft를 그대로 제출하며 save는 다시 검증/CAS를 수행한다. 미리보기 뒤 경쟁 저장은409·추가쓰기0이며 입력은 유지한다. 통신/서버 오류로 저장 결과가 불명확하면 동의를 해제하고 최신 설명 조회로 반영 여부를 확인하도록 안내한다. 자동 재저장은 없다. 실제 HTTP 응답 유실 재현은 이번 범위가 아니다.

원본 데이터/열·계산식·지표·기존 분석·게시본은 전파/수정하지 않는다. 새 DB 스키마/의존성은 없다. 기존 이력/미리보기의 변경 전후 카드를 공통 컴포넌트로 추출해 동일한 타이포·간격·1열/2열 구조를 사용한다. 공통 입력/버튼 토큰을 사용하며 실제 높이/정렬을 측정했다는 뜻은 아니다.

## 별도 코드 리뷰 후속

별도 code-reviewer가 정상 UI의 동의 우회·기존 save/CAS 퇴행을 발견하지 않았다. 기본값 중복의 잠재 drift·공백만 수정했을 때 미저장 표시·미리보기 전후 값과 draft 일치 확인을 보완했다. 조회와 preview가 같은 snapshot 기본 메타데이터를 사용하고 조회 투영→미리보기 차이0을 회귀로 확인한다. 공백 초안/불일치 응답 회귀의 실패→수정 후 통과를 확인했다. 단순 JSON 상태 정리로 변경0건의 표시만 정리하며 입력을 자동 덮지 않는다. 기존 API의 동의 토큰 없음·실제UI/운영 미검증은 유지한다.
