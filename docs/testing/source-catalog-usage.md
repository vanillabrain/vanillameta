## 구현

Explore → 데이터 업무 설명 → 이 소스의 사용처 확인에서 활성 지표/본인 저장 분석을 명시 조회한다. 기본은 접혀 있다. 분석은 기존 저장 화면을 새 탭으로 열어 현재 편집의 초안·미리보기·동의를 유지한다. 조회·종류 선택·오류는 편집 상태나 원본/지표/분석/게시를 변경하지 않는다.

`POST /bi/source-catalog/usage`는 sourceId/kind(metrics 또는 analyses)/선택 afterId(양의 정수, 첫 요청에서는 생략하며 명시0은 거절)를 받으며 매번 실제 소스 소유권을 검사한다. 지표는 databaseId가 같은 활성(useYn=Y) 등록 지표의 ID/업무 표시명(없거나 손상되면 등록명)을 반환한다. 분석은 UserMapping의 본인 연결·미삭제·analysisDefinition.databaseId가 같은 저장 분석에 대해 기존 dashboard 권한을 재확인한 ID/제목만 반환한다. SQL·정의 JSON·행·연결정보·타인 제목은 응답에 포함하지 않는다. Studio가 저장한 legacy 분석 연결도 이 기준으로 읽으며 Studio 상태/게시본의 독립 의존 관계는 별도로 추적하지 않는다.

각 쿼리는 최대21개 후보를 읽고20개를 검사한다. 지표는 DB에서 소스로 제한한다. 분석은 본인 저장 분석 후보의 원본 JSON 연결과 권한을 확인하므로 빈 결과에도 다음 커서가 있을 수 있다. cursor는 마지막 검사 후보 ID로 전진한다. 전체 개수나 사용처 없음으로 단정하지 않고 UI의 `사용처 더 확인`으로 이어진다. 손상/불일치 정의·권한 거절 분석은 생략하고 예상하지 않은 저장소 오류는 실패한다. 권한403/401이면 UI의 이전 사용처 목록은 숨기고 편집 초안은 유지한다. 일반503 오류는 확인한 목록을 보존하고 해당 조회 재시도를 제공한다. 같은 origin 사용자 계정 경계는 기존 API 인증 처리에 따른다.

일반 위젯 대시보드·게시본·복사본의 간접 참조·열별 영향·수치/계산식 변경 영향은 미포함이다. 업무 설명의 자동 전파/삭제/비활성화는 없다. 단순한 조회 시점 목록이며 페이지 전체가 같은 revision에 고정되는 snapshot은 아니다. 새로 추가된 분석은 처음부터 다시 조회할 수 있다. 새 DB 스키마/의존성은 없다.

## 별도 코드 리뷰
