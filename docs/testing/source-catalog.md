# UC050 업무 메타데이터 첫 단위

2026-10-18. 비교 기준 `0486380b` 이후 이번 변경. [계획](../plans/UC-050.md)·[UC050](../use_cases/UC-050-manage-analysis-catalog.md)·[TC050](../test_cases/TC-050-enterprise-analysis.md). FR014/015 전체 구현 완료가 아니다.

## 구현

Explore에서 `데이터 업무 설명`을 열면 소스 표시명/설명과 실제 열 이름/타입·업무 표시명/설명/단위를 확인한다. 기본은 접혀 있으며 최초 클릭에만 조회한다. 일반 공통 UI Kit의 small 버튼/입력·반응형 grid를 재사용한다. 저장한 업무 설명은 같은 소스에서 다시 읽고 편집할 수 있다. 원본 열/데이터·지표·대시보드·AI 문맥은 변경하지 않는다.

서버는 매번 기존 소유권 검사·DuckDB 프로파일과 전체 열 일치·정규화 표시명 중복·크기를 검증한다. 버전은 source별 append-only이며 actor/기준 데이터·스키마 버전/시각을 기록한다. 원본 행이나 연결정보는 응답·메타데이터에 포함하지 않는다. 오래된 설명/데이터는409, 구조 변경은 보존형 저장 차단이다. 실패 시 입력을 보존하고 명시 최신본 조회에 입력 폐기 확인을 요구한다. 소스 전환 시 다른 소스의 늦은 응답을 무시한다.

## 자동 검증

실행 로그는 저장소 밖 `/tmp/vm-catalog/`에 둔다. SQLite 메모리 DB + 실제 migration/버전 insert를 사용하며 프로파일/기존 권한 서비스는 fixture다. 실제 DuckDB/HTTP/JWT/운영 MySQL 검증으로 확대 해석하지 않는다. FE는 HTTP 응답 fixture를 사용하는 컴포넌트 검사다.

- BE: 초기 조회 쓰기0/원본 미노출·저장 후 서비스 재생성/재조회·이력/actor 보존·타인 거절·오래된 데이터/설명409·잘못된 입력/열/타입/단위/중복 거절·스키마 변경 보존·동시 버전 쓰기 정확1건·저장 준비 중 소스 교체 거절·손상 이력3종의409/추가쓰기0.
- FE: 최초 접힘/명시 읽기·수정/저장/재마운트·저장409 입력 보존·최신본 교체 확인·읽기 재시도·스키마 잠금·접기 초안 유지·소스 전환/늦은 응답 차단·손상 이력 안내/저장 불가. 기존 SourceExplore 회귀를 함께 실행한다.
- FE 관련52개 PASS(새 편집기6/기존 Explore46), FE type/lint/build PASS. BE 관련77개 PASS(새 서비스21/기존 Explore56).
- strict 문서 검사: 오류0/기존 경고2/억제0. FR011/NFR002 상태 집계 경고를 임의 변경하지 않았다. 최종 pin/check PASS. 로컬 review packet은 awaiting_review·acceptance not_recorded다.
