# UC036 — 기존 대화 입력창의 생성안 후속 질문·저장

2026-10-16. P3/FR008·009·011. [UC](../use_cases/UC-036-creation-composer.md) · [설계](../architecture/creation-composer.md) · [계획](../plans/UC-036.md) · [TC](../test_cases/TC-036-creation-composer.md).

## 변경

최근 성공한 미저장 생성 실행을 기존 대화 입력창의 대상으로 표시한다. 같은 입력창에서 블록 번호/유일한 제목으로 수정하거나 새 블록을 추가하고, 전체 미리보기를 확인한 뒤 “이 생성안을 저장해 줘”로 비공개 저장한다. 위쪽 문맥도 생성안의 소스·전체 기간/필터 없음으로 맞췄다. 새 모드 선택은 선행하지 않는다. 명시 원본 복귀는 입력을 유지하고 자동 요청하지 않는다. 저장 완료 뒤 입력창은 원본 대상으로 돌아가며 완료 링크를 제공한다.

서버 message endpoint는 소유 실행·제안·소스 버전을 확인하고 한정된 번호/제목/append만 기존 UC035 수정기로 전달한다. 저장은 지원하는 단독 긍정 문구만 기존 원자 생성에 위임한다. 부정/의문/혼합 저장·공유/게시·원본 요청·모호한 대상은 변경하지 않는다. 임의 자연어 전체를 분류하는 새 LLM/범용 프레임워크는 만들지 않았다. 미완성/만료 생성안은 카드 확인을 안내하며 원본으로 자동 전송하지 않는다.

불명확 응답은 질문/동일 envelope를 유지하고 입력·카드 작업·원본 복귀를 잠근다. 같은 요청 재확인만 허용한다. 수정 완료 시 raw 질문 hash를 기존 receipt와 함께 기록해 이전 캐시가 없어도 재확인한다. 질문·SQL·미리보기를 실행 JSON에 추가 저장하지 않는다. 원본의 onApply/onSaved를 호출하지 않고 같은 useChat 메시지 목록에 후속 질문/결과를 표시한다. 대화 원문 자체의 reload 복원은 추가하지 않았다.

최종 대조에서 저장 transaction은 끝났지만 실행에 완료 영수증을 복구하기 전 늦은 수정이 바인딩을 바꿀 수 있는 경계를 발견했다. 같은 직렬 쓰기 큐에서 생성 journal을 다시 확인하고 이미 저장됐으면 수정 CAS를 거절하도록 보완했다. 기존 저장 결과를 잃지 않게 하는 범위이며 실제 화면에서 경합을 주입한 결과로 주장하지 않는다.
