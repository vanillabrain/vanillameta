## 발견한 문제와 보완

1. **기본 차트 누락 오류 안내:** 서버가 `chart component unavailable`을 반환했지만 화면은 필수 열·지표 오류라고 표시했다. 정확히 알려진 오류만 관리자 기본 차트 설정·동일 저장 요청 재시도 안내로 변환한다. 임의 서버 문구·파일 경로를 그대로 노출하지 않는다. 실제 초기 실패를 재현했고 새 안내 매핑은 회귀 검사로 확인했다. 기본 컴포넌트를 자동 생성하거나 보안 정책을 완화하지 않았다.
2. **가이드의 직원 공유 순서:** 수신자 소스 읽기 권한은 공유 저장 전 필요하다. 소스 read 부여→대시보드 전달→수신자 열람으로 교정했다. 모바일 블록 선택 후 AI 탭 전환과 게시 중지의 추가 확인 버튼도 명시했다.
3. **수신자 실제 조회 소비자:** DashboardAnalysis가 편집용 preview를 호출해 read-only 수신자에게 실패했다. [설계](../plans/UC-053-received-view.md)에 따라 `/ai/dashboard-view`를 연결했다. 요청의 허용된 표시 조건과 고정 revision만 받고 서버 저장 정의로 계산한다. client draft/SQL/source/widgets는400, 오래된 revision은409, 계산 전후 현재 read/정의·요청 epoch를 재검사한다. 기존 편집·저장·직접 SQL 경계는 유지한다. 집계 응답을 기다리며 기존 위젯을 잠깐 마운트하던 경로도 로딩 상태로 바꿨다. 소유자 전용 원본 API의 불필요한403·오류 알림을 실제 화면과 요청 기록에서 재현했고, 수정 후 요청0·알림0을 확인했다.

실제 MySQL HTTP 선택 검사: 수신자의 새 조회201·client draft 주입400·stale revision409·기존 편집 preview403·실제 `/database/execute`403. 초기 잘못된 SQL probe 주소의404는 권한 거절 증빙으로 사용하지 않고 올바른 경로의403으로 재검사했다. 요청 총수를 제품 완료율로 쓰지 않는다.

## 자동 검사와 재검사 구분

- 오류 안내는 먼저 회귀2개 실패를 확인한 뒤 수정했다. 조회 소비자는 UI에서 실제 실패를 확인했고, 새 FE 경계 검사도 기존 preview 호출로 실패한 뒤 보완했다. 새 BE 테스트 초안의 미선언 메서드 컴파일 오류는 제품 실패 수로 계산하지 않는다.
- BE: 저장 정의 조회/epoch·소유권 guard·AI dashboard·Studio 자원 접근 **4 suites/131 tests PASS**. 새 조회 경계와 기존 edit 거절을 포함한다.
- FE 최종 통합: 생성/복구/게시·저장 분석/개인 보기/원본 상세/대시보드 **8 files/395 tests PASS** 후, 로딩 중 기존 위젯 요청 방지 회귀를 추가해 영향받은 **4 files/307 tests PASS**로 재검사했다. 두 배치는 겹치며 앞선89개·중간306개와 중복 합산하지 않는다. API 계약 전환 후 mock 경로와 SQL 초안 대신 revision을 확인하도록 갱신한 4개 기대값의 중간 실패는 최종 성공으로 덮어 지우지 않는다.
- BE/FE build, TypeScript, 변경 코드 lint, Markdown 형식·상대 링크/이미지·diff 공백을 검사한다. 최종 전달은 Git 기록을 따른다.

## 범위와 한계

CSV와 샘플 기반 한 소스의 대표 여정이다. 외부 DB 연결 유형 전체, 모든 AI 질문/조건/다중 소스, 그룹·독립 복제의 전체 조합, 실제 모바일 터치, 운영 부하·운영 migration, 업무 담당자 수용은 미실행이다. 게시 중지는 조회 공유 회수가 아니며 이미 받은 독립 사본 삭제도 아니다. 검증용 게시본 중지를 확인한 뒤 Ego 공간을 종료했다. 감독기 `/stop`200과 `ownedContainerRemoved=true`, `temporaryCredentialsRemoved=true`, `persistentVolumesCreated=0`을 확인했고 추가 임시 계정 자격증명 파일도 제거했다.
