# 외부 베타 M2 — LLM 게이트웨이·스트리밍 검증 증빙

계획: `docs/plans/external-beta-m2-llm.md`. 이 문서는 **무엇을 실행했고 무엇을 실행하지 않았는지**를 단위별로 남긴다. 실행하지 않은 항목은 통과로 쓰지 않는다. 모든 테스트는 `audit` 서브에이전트가 격리된 worktree에서 실행했다.

## 실행 환경(재현에 필요한 사실)

- 권위 있는 실행기는 **Node 26.12.1**(Homebrew)이다. 프로젝트 `engines`는 Node 24를 요구하지만 이 머신에는 없고, 기본 `node`(22.23.1)에서는 DuckDB를 쓰는 모든 스펙이 기준 커밋에서도 실패한다. 백엔드: `node node_modules/jest/bin/jest.js --config package.json`.
- 의존성은 `npm ci --legacy-peer-deps`(스크립트 포함)로 설치한다. `npm ci`는 추적 중인 `backend-api/yarn.lock`을 다시 쓰므로 커밋 전에 되돌린다.
- 빌드는 Node 26에서 `--require ./scripts/typescript-api-compat.cjs ./node_modules/@nestjs/cli/bin/nest.js build`로 성공한다.

### 발견해서 고친 버그 3개(`f0dfb520`, 재확인 `52bb0d78`)

1. **관찰**: `GET /me/usage`가 모든 토큰에서 401 `accessTokenExpired`(`/ai/status`는 같은 토큰으로 200). **원인**: `UsageModule`이 `JwtService`를 제공하지 않아 가드가 `TypeError`를 던졌고, 가드가 모든 검증 실패를 "만료"로 뭉갰다(클라이언트는 유효한 세션을 끝없이 갱신하려 든다). **수정**: 모듈이 `JwtModule`을 가져오고, 토큰이 아닌 실패는 가드가 warn으로 남기며, `module-wiring.spec.ts`에 가드의 의존성 배선 검사를 추가. **재확인**: A·B 모두 200, 사용량이 `quota show`와 같음(19, 14), 토큰 없음·만료 401, "access token check failed unexpectedly" 0건. 가드 자체(모든 실패→401)는 근본 수정이 아니라 범위 밖 목록에 있다.
2. **관찰**: 제안 경로가 모든 모델 오류를 일반 503으로 바꿨다(시간 제한 503, 잘림·제공자 오류의 코드 소실). **수정**: `llmFailure`로 매핑. **재확인**: 504/502/502, bad-json은 일반 503.
3. **관찰**: 스트림 종료 기록(`msg:"stream"`)이 운영 기본 로그 수준(warn)에서는 보이지 않았다. **수정**: 실패·취소는 WARN, 정상은 INFO. **재확인**: 기본 수준에서 S5 취소가 499 `cancelled`로 보이고 정상 스트림은 줄을 남기지 않음.

**발견한 결함(원인은 별도 조사 중)**
1. **틀린 숫자가 성공으로 저장된다.** 퇴화한 비중 블록을 검증이 거르지 않는다. 상위 N·시간 단위처럼 표현할 수 없는 요구 세부가 조용히 버려지고 제목에만 남는다.
2. **원장 상태가 일어난 일과 다르다.** 모델 호출은 성공했지만 뒤 단계 검증에서 400이 되거나 `MODEL_FAILED`로 끝난 호출이 `ok`로 기록된다. 서버 503(`AI 생성안을 준비하지 못했습니다`)이 한 건 `cancelled`로 기록돼 사용자 중단처럼 보인다. 오류·취소를 일일 쿼터에 셀지는 사용자 결정 대기 중인 정책이다.
3. **`MODEL_FAILED`는 코드만 남는다.** 실행 상태에도 로그에도 원인이 없어 나중에 진단할 수 없다.
4. **저장 첫 클릭이 실패한 적이 있다.** 화면에서 "필수 열과 지표 정의를 확인해 주세요"와 저장 확인 대기 카드가 뜨고 확인을 눌러야 저장됐다. 원인은 확정하지 못했다. API 경로에서는 임시 DB에 `component` 표가 비어(로컬 시더가 사용자가 이미 있으면 건너뜀) `chart component unavailable`(영문 원문)로 400이 났고, 52개 행을 임시 DB에 직접 넣어 진행했다. 운영 구성에서 같은 일이 생기는지는 확인 대상이다.
5. 모호한 요청과 같은 프롬프트의 결과가 매번 다르다. 평문 JSON 오류(HTTP 400)와 NDJSON 오류(HTTP 201 안의 오류 이벤트)의 계약이 다르다. 제목만 바꾸는 요청이 블록이 하나여도 선택을 요구한다.

| 화면 | 저장 첫 클릭에 한 번에 저장됨(이번 한 번의 관찰이고 이전에는 확인 단계가 필요했다, 원인은 여전히 모른다). 1440·768·390 모두 가로 넘침 0. 중지 버튼 뒤 입력 유지. 답할 수 없는 요청은 필요한 데이터가 없다고 정직하게 답한다 |

**이전 결함이 사라진 이유(주의)**: 사라진 세 가지는 지원이 생겨서가 아니라 **거절**로 막은 것이다. 월별·상위 N·전체 대비 비중은 여전히 만들 수 없다.

**새로 드러난 문제**
1. **표현할 수 있는 요청도 모델이 자주 거절한다.** 표현 가능한 요청 12회 중 5회(약 42%)가 "매출 열이 없다"는 `missingColumns`로 끝났고, 일별 추이는 3번 모두 블록이 나오지 않았다. 게이트가 낸 것이 아니라 모델의 응답이다(게이트에는 `missingColumns` 경로가 없다). 데이터에는 숫자 열 `amount`와 날짜 열 `order_date`가 있다. 틀린 숫자를 내는 것보다는 낫지만 사용성 결함이다.
2. **거절 안내가 막다른 길로 이어진다.** 월별·분기별·상위 N 거절 문구가 "일 단위 추이로 다시 요청해 주세요"라고 하는데 일별 추이가 3/3 실패했다.
3. **제목과 데이터가 어긋나는 편집이 경고 없이 제안된다.** 카테고리 차트에 "지역별 매출", "월별 매출" 제목을 붙이는 `updateBlock`이 나온다. 요청한 이름을 모델이 조용히 버린 경우도 있다(생성 경로의 따옴표 라벨).
4. **모호한 요청은 여전히 일정하지 않다.** 3회 중 1회만 블록을 만들고 나머지는 질문한다. 가정을 밝히지 않은 채 만든 경우가 있다.
5. **문구가 경로마다 다르다.** 생성은 "아직 지원하지 않는 요청입니다", 채팅 편집은 "지원 예정 기능입니다"(계획이 있는 것처럼 읽힘), 블록 추가·조인 거절은 "공유 범위를 확인해 주세요"로 끝난다. 명확화·거절 실행도 단계 목록에는 "초안 준비 완료"로 보인다.
6. **한도 카운터가 거절도 센다.** 화면의 `AI 호출 n/30`이 거절·미지원 요청에서도 오르고, 한도 소진으로 같은 날 추가 실호출이 불가능했다.

**이번 재실행으로도 증명하지 못한 것**: `MODEL_FAILED` 진단 로그(`AI answer rejected`·`AI call failed` 줄)는 이번에 해당 실패가 일어나지 않아 확인하지 못했다. 이전 실행의 `ok` 상태와 결과 불일치도 바뀌지 않았다(이전에도 중단은 `cancelled`로 기록됐다). 프롬프트 주입은 메모 요약 요청이 `missingColumns`로 끝났고 주입 행이 응답에 보이지 않아 모델이 그 행을 읽었는지 보이지 않는다. 원장 `error` 3행(사용자 2)은 이번 로그 이전 시각이라 원인 로그가 없다(cmux 래퍼 실패로 추정). 첫 진행 표시는 서버 신호가 아니라 화면의 약 1초 타이머다(제안 스트림에는 단계 이벤트가 없다). 운영 제공자의 실제 토큰 수, 스트리밍, 추론 강도, 429·5xx·`LLM_TIMEOUT` 매핑, 5초를 넘는 호출의 하트비트는 모두 여전히 미검증이다. 편집 경로의 따옴표 예외는 그 경로에 게이트가 없어서 검증 대상이 아니었다.

**판정**: 검증자는 개발 제공자 기준 "주의 사항이 있는 초대 베타 가능"으로 판정했다(숫자는 모두 맞고 조용한 오작동은 없지만 위 1~3은 초대 전에 고쳐야 한다). 이것은 `gpt-6-luna`에 대한 판정이고, 운영 제공자의 응답 품질과 거절률은 따로 재야 한다.
