# UC033 — 같은 대화에서 생성 질문 답변

2026-10-16. P3 / FR008·009·011. [UC](../use_cases/UC-033-inline-creation-clarification.md) · [설계](../architecture/inline-creation-clarification.md) · [계획](../plans/UC-033.md) · [TC033](../test_cases/TC-033-inline-creation-clarification.md).

## 변경

Studio 대화의 환불률 분모 질문을 같은 실행 카드에서 답한다. 선택 → 답변하고 미리보기 → 명시 비공개 저장이다. 새 대시보드 생성은 시작한 편집기를 덮지 않는다. 서버는 원 질문·소스를 캐시에서 읽고 권한/원 제안/소스 revision을 확인한다. 모델 대기 뒤 최신 실행을 다시 확인하며, 마지막 답변 requestId/hash로 완료 재시도를 재실행 없이 돌려준다. 질문·SQL·원본 행을 실행 JSON에 추가 저장하지 않는다.

실행 중에는 대화의 acting을 공유한다. 응답을 확인하지 못하면 선택을 잠그고 같은 답변만 재확인한다. 생성안 GET 실패는 읽기 재시도이며 모델이나 저장을 자동 실행하지 않는다. 필수 열 질문은 기존 소스 확인 화면 연결을 유지한다. 새 일반 설정·전역 크기 예외·의존성은 추가하지 않았다.

## Ego75 실제 여정

격리 로컬 3698/4899→4898, 공개 합성 커머스 source32 / 원본39. Codex gpt-6-luna 경로를 그대로 사용했다. 고객 데이터·새 공개 링크는 사용하지 않았다.

1. `환불률을 보여주는 새 대시보드를 만들어 줘. 아직 저장하거나 게시하지 마.` → 같은 카드 분모 질문. 금액 선택부터 답변·미리보기·저장 완료까지 원본39 URL과 탭1개를 유지했다.
2. 실제 서버가 답변을 완료한 후 임시 프록시가 해당 응답 한 번만503으로 교체했다. 선택 amount/질문·기존 편집을 보존하고 선택 변경을 잠갔다. 정상 프록시 복원 후 `같은 답변으로 다시 확인` → 동일 requestId/본문201 → 새 생성안 GET200. 답변/미리보기 시 dashboard·metric·publication 증가0이다.
3. 금액 기준 21.23% 미리보기를 확인하고 `제안 확인 후 비공개 저장` → 대시보드42. 원본39의 document/definitions/sourceRevision과 원본35 해시가 유지됐다. 기존 지표26을 재사용해 metric 증가0, 명시 저장은 dashboard/state 각1개 증가다.
4. 대화 reload와 저장 완료 링크로 연 복사본42 reload는 GET만 발생했다. 복사본의 ID/정의/모든 폭 배치/revision을 보존했다. 완료 링크를 누른 시점에만 선택적으로 새 탭 p2를 열었다. 별도 API 확인에서 완료 답변 재전송201, 같은 requestId의 다른 답변409, 같은 생성안 저장 재전송은 동일42다. 잘못 추정한 `/creation/save` 경로404 뒤 실제 `/creation`으로 재검증했으며 404를 저장 검증으로 계산하지 않았다.
5. 최종 클라이언트 응답 검증/안내 수정 후 같은 질문을 다시 실행하여 주문 건수 선택 → 같은 카드 숫자22.86%+날짜별 선 차트 미리보기를 확인했다. 이 둘째 생성안은 저장하지 않았다.

CSV manifest SHA256을 확인한 독립 Decimal 계산은 금액4457.60/20994.61×100=21.23211624316908%, 결제 성공35주문 중 환불8주문=22.85714285714286%다. 각각 실제 preview 데이터와 오차1e-12 이내다. 이번 변경은 대화 연결이며 Rill 탐색 UI의 신규 기능 비교는 범위에 추가하지 않았다. 기존 Rill 수치/탐색 증빙과 커머스 oracle을 혼동하지 않는다.
