# 첫 고객 매출·환불 파일럿 인수 명세

상태: **NOT_RUN — 실제 고객 데이터/업무 정답 미제공**. 입력 준비 현황 갱신: 2026-10-18. P2~P5/TC005의 실사용 수용 범위다. 합성 샘플·Rill 통과 결과로 고객 수용을 대신하지 않는다. 새 서비스/커넥터/DB/모델은 추가하지 않는다. 기존 DuckDB worker와 Studio, 지정 gpt-6-luna 연결을 사용한다.

## 실행 전에 필요한 입력

- 업종과 검증할 업무 질문1개, 비식별 파일의 로컬 경로와 파일 버전/해시. 첫 범위는 한 통화·한 기간·한 채널 집계다. 이메일/이름/전화/주소/결제 비밀값은 필요하지 않다. 조인 키는 주문/결제/환불 간 같은 가명 규칙으로 유지한다.
- 담당자가 확인한 총매출/환불액/순매출과 환불률의 분모, 기간·시간대·취소/실패 결제 처리, 세금/배송/할인 포함 여부. 정답은 화면이나 생성 SQL에서 역산하지 않고 별도 원장/집계와 대조한다.
- 복제 대조용 두 번째 파일이 있으면 그 경로/정답. 없으면 다른 데이터의 재사용 조건은 NOT_RUN으로 남긴다. 공유는 기본 비공개로 확인하고 실제 외부 공개 범위는 별도 명시된 경우에만 실행한다.

### 입력 양식

첫 실행에는 아래 한 묶음만 받는다. 비밀번호·API 키는 포함하지 않으며 아직 확인하지 않은 정답은 추정값 대신 `미확인`으로 적는다.

```text
업종 / 업무 질문:
orders CSV 로컬 경로:
payments CSV 로컬 경로:
refunds CSV 로컬 경로(환불 없음은 필수 헤더만 있는 파일):
customers CSV 로컬 경로(선택):
통화 / 기간 / 시간대:
날짜 기준(주문일 코호트 또는 결제·환불 발생일):
성공 결제액 / 환불액 / 차감 수취액 정답:
환불률 분모(금액 또는 주문 건수) / 분자·분모 정답:
정답 확인 근거 / 담당자:
세금·배송·할인 / 취소·실패 처리 기준:
```

파일을 받으면 먼저 필수 열·참조 키·통화·날짜 의미를 읽기 전용으로 확인한다. 원본 변경 없이 변환이 필요한 항목을 기록하고, 독립 정답이 확인된 질문 하나의 PILOT-01~04부터 실행한다. 현재 Studio 연결은 주문일 코호트이므로 발생일 현금 흐름 요청을 같은 의미로 통과시키지 않는다. 두 번째 파일·담당자 수용 입력이 없으면 PILOT-06·07은 계속 NOT_RUN이다.

현재 commerce bundle의 정확한 필수 열은 아래와 같다(`backend-api/src/analysis/commerce-import.ts`). 임의 파일명을 인식/열 이름을 자동 매핑한다고 가정하지 않는다. 실제 원본에 맞는 매핑이 필요하면 원본을 보존한 준비 사본과 변환 내역을 먼저 기록한다.

| CSV | 필수 열 |
|---|---|
| orders | order_id, customer_id, ordered_at, order_status, currency, subtotal, tax_amount, shipping_amount, order_total |
| payments | payment_id, order_id, paid_at, payment_status, amount |
| refunds | refund_id, payment_id, order_id, refunded_at, refund_reason, amount |
| customers (선택) | customer_id, acquisition_channel |

**현재 제약:** Commerce importer는 파일 묶음마다 USD(소수 최대2자리) 또는 KRW(정수 원) 한 통화를 지원한다. [합성 원화 검증](commerce-krw.md)은 실제 고객 검증과 구분한다. 다중통화/미지원 통화 파일은 currency만 USD로 바꾸거나 임의 환산해 통과시키지 않는다. [Studio 명시 원화 생성·수정·저장](studio-krw.md)은 합성 데이터로 확인했다. 후속 [고정 Commerce 문맥 전달](commerce-ai-context.md)과 [생성·신규 저장 단위 검증](commerce-units.md)도 확인했으나 일반 CSV의 통화 추론·기존 편집 AI 전체 정책·고객 파일 수용을 증명하지 않는다. 주문 상태/결제 상태·금액 합계·참조 무결성도 기존 검사를 따른다. 환불이 없으면 필수 헤더가 있는0행 CSV를 제공한다. [EMPTY-01~04 합성 검증](commerce-empty-refunds.md)에서 일반/분석 수입·실제 UI 저장/reload를 확인했으며 환불 파일 생략/0바이트 지원이나 고객 수용으로 확대하지 않는다.

기존 commerce 요약의 상품금액(subtotal) 기준과 Studio 분석의 성공 결제 amount 합계 기준은 서로 같다고 가정하지 않는다. 날짜도 결제/환불 발생일 기준 현금 흐름과 주문일 코호트를 구분한다. 고객이 원하는 정의를 선택해 모든 비교에 같은 조건을 적용한다. 정의/타입/통화가 맞지 않으면 먼저 차이를 보고하고 완료 숫자를 만들기 위해 데이터를 바꾸지 않는다.

## 최소 인수 케이스

| ID | Given / When | Then | 상태 |
|---|---|---|---|
| PILOT-01 | 준비된 파일/정답을 기존 연결 화면에서 수입 | 행 수·열/타입·오류 안내 확인, 원본 보존 | NOT_RUN |
| PILOT-02 | 담당자의 질문을 gpt-6-luna로 요청 | 필요한 분모만 확인, 지표/분류/계산 기준·전체 미리보기 제공 | NOT_RUN |
| PILOT-03 | 전체 기간과 기간/채널 조건 하나씩 적용 | 독립 정답과 금액/건수/환불률 일치, 날짜 기준·통화 명시 | NOT_RUN |
| PILOT-04 | 블록 하나 직접 수정/AI 제목 수정 후 비공개 저장·reload | 비대상 계산/ID/배치 보존, 숫자 불변, 저장본 재조회 | NOT_RUN |
| PILOT-05 | 저장본에서 명시 비공개 게시·수정본과 구분 | 게시 버전/읽기 권한·초안 분리 유지, 공개하지 않음 | NOT_RUN |
| PILOT-06 | 담당자 본인 새 소스에 매핑·복제 | 새 비공개 ID/새 소스 정답, 원본·게시본 불변 | NOT_RUN |
| PILOT-07 | 실제 담당자가 도움 없이 연결→질문→저장 경로 수행 | 완료/막힘·소요시간·도움 횟수 기록, 담당자 수용/보류 명시 | NOT_RUN |

새 파일과 관련된 위 조건만 실행한다. 기존 권한/만료/장애 조합 전체를 반복하지 않는다. 금액은 Decimal/정수 최소 단위로 정확히 비교하고 비율은 원시 분자·분모와 화면 반올림을 구분한다. 실패/수정이 있으면 해당 조건만 재검증한다. 휴대폰/키보드는 변경된 상태만 추가 확인하며 VoiceOver BLOCKED를 유지한다.

## 결과·종료 기준

별도 증빙 폴더에 입력 해시·정의/필터·독립 정답·실제 API/UI 결과·390/1440 대표 캡처·담당자의 수용/보류를 기록한다. 원본 고객 파일/자격증명은 저장소에 커밋하지 않는다. 준비 입력과 정답이 없으면 해당 조건은 NOT_RUN으로 유지한다. 고객 부재 상태의 에이전트 실행을 담당자 수용 PASS로 표시하지 않는다. Rill은 기존 계산/UX 기준을 재사용하고 고객 파일을 외부 데모에 업로드하지 않는다.

종료 조건은 정해진 한 업무 질문의 숫자 일치·저장/reload·원본 불변과 실제 담당자의 완료 판단이다. 모든 자연어·모든 장애·운영 출시 완료와 구분한다. 새 소스/외부 공유 입력이 없는 조건은 보류할 수 있으며 남은 조건을 그대로 보고한다.
