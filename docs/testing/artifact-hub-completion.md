## 발견한 공백과 수정

| 공백 | 수정 |
|---|---|
| Studio 링크와 목록 새 탭 링크가 목록 조건을 잃음 | version1 복귀 문맥에 검색·유형·정렬·표시·보관 범위를 담고 URL로 전달한다. 목적지는 항상 `/dashboard`이며 임의 경로를 받지 않는다. |
| 보관함 선택이 재마운트 때 초기화됨 | `artifactView=archived`를 URL에서 읽어 기존 권한별 목록 쿼리를 선택한다. |
| 상세 조회에서 상단 목록 링크가 기본 목록으로 감 | 상세·Studio의 링크와 삭제 완료 복귀가 검증된 목록 주소를 사용한다. |
| 헤더와 새 허브의 이름·언어가 불일치 | 헤더를 아티팩트로 맞추고 새 허브 제어·안내·카드 문구를 한·영 번역 키로 옮긴다. |

`artifactNavigation.ts`가 고정 스키마를 검증한다. version·enum·문자열 길이·중복 문맥·추가 필드가 잘못되면 기본 목록으로 복귀한다. `aiSourceId` 등 다른 작업용 쿼리는 복귀 문맥에 넣지 않는다. 영어의 긴 정렬 문구와 추가 버튼이 잘리는 문제도 실제 화면에서 발견해 정렬 필드192px·추가 버튼 최소160px로 보완했다.

현재 목록의 필터를 바꿀 때 기존 관련 없는 쿼리를 보존하는 동작은 유지한다. 권한은 기존 서버 API가 결정한다.

Studio의 목록은 계속 새 탭으로 연다. 새 탭에 초안 내용을 전달하지 않으며 원래 편집기·되돌리기 상태는 유지한다. 생성 화면에도 유효한 복귀 문맥이 있을 때 목록 주소를 적용한다. 생성·복제의 모든 경로를 이번 검증으로 완료 처리하지 않는다.

## 남은 제품 구현

이번 수정은 기존 분석 산출물 허브의 연결·상태·언어를 완성하는 단위다. 다음 항목까지 구현 완료라고 주장하지 않는다.

- 공통 사이드바와 전체·공유받음 통합 허브. 기존 조직 권한·받은 분석 기능은 있지만 허브에 합쳐진 것은 아니다.
- 문서·보고서·HTML·PDF·PPT를 한 자산 모델로 관리하는 업로드·버전 교체 흐름.
- Google/MS 원문 연결, MD 사본, 비용 승인 요약과 갱신 버전 관리.
- 외부 AI의 원격 OAuth 승인. 현재 로컬 stdio MCP 제작과 다른 범위다.
- 실제 차트 썸네일. 지금은 추가 집계 호출 없이 저장된 시각화 안내를 표시한다.
- Studio 전체 영어 번역, 모바일 신규 설계, VoiceOver·운영 수용. 이번에는 신규 허브 문구와 데스크톱만 확인했다.

## 최종 재검토와 정리

최초 독립 리뷰의 목록 문맥 유실·필터 초기화 지적은 실제 코드와 계약에 맞지 않아 기각했다. 새 GPT-6 Astra 리뷰는 두 지적이 오탐임을 확인했고, 후행 슬래시 목록 주소의 문맥 유실을 발견했다. 브라우저에서 재현한 뒤 대소문자·후행 슬래시 경로를 정규 목록으로 처리하도록 수정했다. helper12개와 실제 후행 슬래시→Studio 복귀가 통과했다.

정상4463 런타임은 인증 stop200, 소유 컨테이너0, runRoot 제거, status=stopped를 확인했다. Ego90도 종료했다. 초기22e26a 환경은 현재 drain 증명 부재로 계속 보존한다. 정상 정리 결과를 초기 실패 자원까지 확대하지 않는다. 프로젝트의 임시 빌드 설정·런타임 사본과 개별 테스트 인증정보 파일은 제거했고, 비밀 없는 설정·실행 사본은 증빙에 보존했다. Git 커밋·push는 요청하지 않아 실행하지 않았다.
