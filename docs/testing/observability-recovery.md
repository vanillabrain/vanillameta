## 검증

- **실패 재현:** 기존 시각 상관·미대응 이벤트·암호화/미지원 엔진·시간 범위 검사에서 6개, 미설정 캐시 검사에서 2개, 연결 정보 전달에서 1개, 실행 계획 직렬화에서 1개 회귀 실패를 수정 전에 확인했다. 컴파일 오류였던 최초 캐시 테스트 초안은 제품 실패 수에 포함하지 않는다.
- **최종 BE:** 관측/캐시·Redis codec·운영자 guard·연결/스트리밍·시드/migration·빈 대시보드 등 **23 suites / 218 tests PASS**, 6.43초. 이전 범위와 중복 합산하지 않는다.
- **최종 FE:** 앞선 인수 수정 관련 위젯 선택·외부 E2E seed 차단과 Studio/게시/분포 선택 회귀 **5 files / 74 tests PASS**. 새 UI 변경은 없으며 [Ego 122의 기존 인수 캡처](develop-acceptance-20261021.md)를 재실행으로 표현하지 않는다.
- **Node 24.19.0 build / lint:** backend build 성공, 변경 파일 lint 오류 0. 기존 unused/non-null 경고는 별도다. 앞선 FE build/type와 문서 링크 검증은 해당 인수 범위 증빙을 따른다.
- **실제 전체 Nest / Docker MySQL 8.4.11 / native DuckDB:** 최종 실행 `301b9ef2-44ae-4b60-95c9-4a20b14a4f7a`의 **27 HTTP / 7개 의미 검사 PASS**. 운영자/일반 직원/비인증 200/403/401, 서로 다른 이벤트 계열 영속 저장, 소스 소유권·Redis 없는 접수 503/이력 유지, 암호화된 실제 MySQL 소스 EXPLAIN, 실제 잠금 대기 SQL, cron 메트릭 수집을 확인했다.
- 잠금은 이번 소유 MySQL의 합성 probe 표에만 걸었다. 제품 SQL 보호를 완화하지 않았으며 완료 결과 `COUNT(*)=1`과 실제 저장된 **1,592ms / 1,598ms**, 두 실행 계획의 `JSON_VALID=1`을 확인했다. 같은 실행의 두 관측 기록이며 고유 사용자 쿼리 2개로 합산하지 않는다.
- 자연 cron 수집을 기다린 최종 런타임 로그에서 duration 범위 초과·암호문 파싱 실패·Redis 미설정 연결 끊김 경고가 없음을 확인했다. 권한 거절/Redis 없는 작업 접수의 의도한 오류까지 로그 0이라고 주장하지 않는다. 설정된 Redis의 실제 장애 경고 보존은 단위 검사이며 이번 HTTP 실행은 Redis 미설정 모드다.

## 실패와 재검사 구분

첫 실제 HTTP 실행은 암호화 EXPLAIN까지 통과한 뒤 잘못된 optimizer 인자에 따른 연결 시간 초과로 중단됐다. 다음 실행은 실제 느린 쿼리 저장까지 통과했으나 cron 확인을 100ms마다 조회해 HTTP 429로 중단됐다. 후자는 실행기의 해당 대기 간격만 5초로 조정했다. 제품 throttle을 끄거나 응답 시간 제한을 늘리지 않았다. 각각의 실패 증빙과 소유 런타임 정리를 보존하고 새 fixture에서 최종 7개 검사를 통과했다.

## 실행·증빙·경계

실행기는 기존 소유권 검사에 `--observability` 선택 경로를 추가한 `scripts/qa-main-legacy.cjs`다. 새 `scripts/qa-enterprise-mysql.cjs` 런타임에만 사용한다. 고정 loopback/컨테이너 label·owner 표식·DB·API PID·환경 일치를 대조하고 첫 테스트 계정만 진단 운영자로 지정한다. 일반 사용자 DB나 운영 환경에 실행하지 않는다.

```sh
# Node 24에서 backend build 후, 새 전용 런타임을 별도 터미널에 유지한다.
QA_LEGACY_OPERATIONS_USER_IDS=1 node scripts/qa-enterprise-mysql.cjs
node scripts/qa-main-legacy.cjs \
  "$PWD/.aiwf/evidence/TC050-integrated-mysql/runtime/runtime.json" \
  --no-redis --observability
```

인증된 감독기 `/stop`의 HTTP 200과 `ownedContainerRemoved=true`/`temporaryCredentialsRemoved=true`를 확인해 이번 소유 앱·컨테이너·임시 자격증명을 정리했다. 원시 증빙은 Git 제외 `.aiwf/evidence/observability-recovery-20261021/`와 실행별 `TC050-main-legacy`에 둔다. 자격증명·암호문 본문·capability 링크는 공개 커밋에 포함하지 않는다.

운영 migration/schema 변경, 실제 Redis 장애/클러스터, 외부 warehouse/모든 엔진, 이번 실제 LLM·새 브라우저 여정, 실휴대폰/운영 부하/업무 담당자 승인과 전체 16개 요건 수용은 이번 완료 범위가 아니다. 개발·검증 변경은 앞선 인수 수정과 함께 develop에 전달하며 최종 SHA는 Git 로그로 확인한다.
