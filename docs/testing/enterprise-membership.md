# UC051 조직·직원 첫 단위 검증

2026-10-18 · develop-v2. FR016·NFR005/007의 일부이며 FR017 자원별 권한/전체 TC050 수용 완료가 아니다. [계획](../plans/UC-051.md)·[전체 목표](../plans/enterprise-completion.md)를 따른다.

## 구현 경계

미소속 계정의 격리 조직 생성, 본인이 특정 조직에 대해 발급한15분 일회용 연결 코드와 정확한 로그인ID로 기존 직원 등록, admin/member·팀·활성 변경, 자신의 조직 직원20건 커서 조회를 구현했다. 조직 관리 권한은 기존 데이터 소유권을 확장하지 않는다. 코드 원문은 응답1회/클라이언트 메모리에만 있고 DB에는 SHA256만 남기며 등록 트랜잭션에서 소비한다. 재발급은 이전 코드를 무효화하고 명시 취소로 서버에서도 폐기한다. 만료는 사용 유효기간이며 미사용 해시의 물리 보존 기간 보장은 아니다. 코드는 지정한 조직만 소비할 수 있고 잘못된 코드로 다른 계정의 소속을 탐지할 수 없게 같은400을 반환한다. 조직 소속 계정의 일반 삭제는409로 차단하며 명시 탈퇴/이관은 후속이다.

SQLite의 단일 연결에서 조직 변경 transaction이 겹치지 않도록 DataSource별 큐를 적용하고 실패 후에도 다음 요청을 처리한다. 이는 모든 다른 모듈의 SQLite 경합까지 검증했다는 의미는 아니다. 쓰기 actor는 JWT에서만 취하고 현재 DB active/admin·조직·expectedVersion을 검사한다. 구성원 변경/CAS/감사는 한 트랜잭션이다. 직원ID만으로 등록하거나 타 조직 편입·자기 비활성/자기 역할 하향은 허용하지 않는다. 과거 access/refresh의 epoch0은 기존 계정과 호환하지만 비활성/재활성은 authVersion을 올리고 jwtId를 제거한다. 다음 보호 bearer 요청/로그인/refresh를 거절하며 재활성화해도 예전 토큰은 다시 유효해지지 않는다. refresh 검증 후 재발급 직전에도 현재 active/epoch를 확인한다.

`/organization`은 기존 보호 Layout/프로필 메뉴에서 진입한다. 변경 요약/동의 뒤 명시 쓰기,409/통신 실패 시 입력 보존, member 목록 비노출과 재조회 흐름을 제공한다. 공통 컨트롤/줄바꿈 구현과 실제 렌더 검증을 구별한다.
