# UC053 받은 자료 조회·열기 검증

2026-10-18 · FR021/022/NFR005/008 후속. [설계](../plans/UC-053-received.md)·[조회 공유](recipient-deliveries.md)를 따른다. 전체 요건/사람 수용 완료가 아니다.

## 결과

- JWT 본인 계정의 현재 조직·active 공유·송신자 활성/소속·현재 유일 소유권을 대조한다. 20개 후보마다 기존 SourceAccess로 대시보드와 모든 소스 read를 검사한 후 제목(최대300 UTF16 units)/번호/공유 버전만 반환한다.
- 소스 비활성/read 회수·공유 회수·소속 변경·소유권 변경/중복·삭제는 제목을 숨긴다. 원본/공유 관계/감사/영수증/알림 표시 상태를 저장하지 않는다. SQL·정의·익명 링크·토큰·송신자/소스 정보를 반환하지 않는다.
- nextAfterId는 마지막 검사 후보다. 표시0행이어도 다음 구간을 읽으며, 새 접근 허용은 첫 구간 재조회로 확인한다. 페이지들은 별도 현재 조회이며 장기 고정 snapshot을 보장하지 않는다.
- 조직 화면의 admin/member 공용 접힌 받은 자료에서 열기·다시 읽기·다음 구간과 기존 보호 `/dashboard/:id` 링크를 연결했다. 열 때 서버 권한을 다시 확인한다. 실패 시 낡은 목록/링크를 숨기고 첫 구간을 다시 읽는다. 닫기/계정 key 변경 후 늦은 응답과 StrictMode 효과 재실행도 처리한다.

## Rill 소스 대조

로컬 참조 checkout HEAD `dd080fc7b19ea02602ece065044ca164dc60ff78`의 [projects.go](https://github.com/rilldata/rill/blob/dd080fc7b19ea02602ece065044ca164dc60ff78/admin/server/projects.go) 48~95행에서 조직 관리 권한/본인 멤버십/공개 프로젝트에 따라 목록을 나누고 page token/page size를 사용하는 코드를 읽었다. 같은 파일 275~306행은 개별 GetProject에서 현재 ReadProject를 검사한다. 이를 VM의 ‘목록에서 허용 범위 발견→개별 열기에서 재검사’와 대조했다. VM은 비공개 직원 delivery에 한정하고 별도 소스 read도 요구한다. Rill의 공개/관리자 예외·그룹 동작을 VM에 구현했다는 뜻은 아니다. 실행 바이너리/실제 Rill 화면 비교는 이번 단위에서 NOT_RUN이다.
