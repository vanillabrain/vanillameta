## 발견·수정

1. 처음 번호 질문은 실제 provider가 일반 clarify를 반환해 생성·저장 없이 끝났다. 이를 성공으로 세거나 수동 선택으로 대체하지 않았다. 번호/제목은 대상 참조이고 존재/모호성 확인은 서버 책임이라는 분류 지침과 번호 예시를 보강했다. 같은 원문을 다시 실행해 정상 대상·저장/reload를 확인했다.
2. 서버 대조에서 따옴표 제목의 중복을 첫 항목으로 고르던 점과 새 제목 `"2번 차트"` 안의 숫자를 대상으로 읽던 점을 수정했다. quoted duplicate는 전체 후보, quoted new-title의 숫자/서수는 대상에서 제외한다. 회귀를 먼저 실패 확인했다.
3. 알 수 없는 비따옴표 블록 참조와 지원하지 않는 한글서수·음수/소수 번호는 이전 선택으로 돌아가지 않고 후보로 끝난다. 문맥형 `선택한/현재/이/해당 블록`과 대상 표기가 없는 질문은 기존 선택을 쓸 수 있다. 미지원 표현 전체를 이해한다고 주장하지 않는다. 최종 대조에서는 따옴표 없는 새 제목에 다른 블록 번호/이름이 들어가는 경우도 확인해 `제목을/제목은` 뒤의 대상형 문자열은 후보 확인으로 제한했다. 이 마지막 순수 resolver 보강은 실패 회귀→BE120·build/lint로 검증했으며 앞선 Ego 번호/제목/후보 문장은 해당 새 제목 분기와 무관하여 다시 실행하지 않았다. 실행 서버도 마지막 빌드로 갱신했다.
4. 별도 native executor가 FE만 읽기 리뷰했다. 확인 후 다시 clarify될 때 처음 안내와 구분하고, null/잘못된 후보·clarify 저장 플래그를 차단했다. 선택 후 질문·초안 변경 시 이전 확인 key뿐 아니라 그 확인에서 온 임시 선택도 해제한다. 적용 뒤 선택 표시와 재요청의 확인 key 제거 회귀를 보강했다. 수정 뒤 독립 재승인은 주장하지 않는다.

Ego 후보 클릭의 첫 exact-text selector는 React 텍스트 노드 분리 때문에 대상을 찾지 못했다. 현재 DOM/후보 제목이 맞는지 확인한 뒤 실제 button의 title 속성으로 선택했다. 제품 변경·우회 저장·새 TaskSpace를 사용하지 않았다. 이 첫 클릭 실패는 확인 후 저장 PASS와 구분한다. 저장 후 대기 selector가 aria-label을 가정해 한 번 timeout됐지만 실제 SVG는 aria-labelledby를 쓴다. 현재4블록·3개 숫자 추세 group의 참조 제목·숫자·저장 응답을 확인해 성공 여부를 판정했다. 제품 렌더 오류로 보고하지 않는다.
