# 조직 공유·받은 자료·재사용 샘플 가이드 검증

2026-10-21 · develop · [계획](../plans/org-share-sample-guide.md) · [공개 가이드](../user-manual/site/team-reuse-walkthrough.md)

## 실행 환경과 구분

전용 qa-enterprise-mysql 실행기의 새 MySQL 8.4.11/Nest/native DuckDB/Vite에서 같은 조직의 합성 소유 admin·수신 member 두 계정을 사용했다. 기존 사용자 서버/자료는 변경하지 않았다. 공개 가이드의 CSV 두 개와 동일한 파일, 저장 지표 및 숫자·시계열 두 블록은 API로 준비했다. 새 빈 DB에 제품 Component 초기값만 추가했다. 이번 여정은 AI 질문 생성이나 UI 업로드 검증이 아니다.

Ego 공간128에서 실제 버튼·선택기·로그인으로 진행했다. 소스 선택기 상단의 다른 샘플 이름을 제외하고 필요한 매핑 영역을 브라우저에서 캡처했다. 캡처 픽셀과 텍스트를 합성하지 않았다. 화면의 로그인 ID는 전용 임시 계정이며 비밀번호·토큰·고객 정보는 공개하지 않는다.

## 확인한 여정

1. 소유자: source 읽기만 동의/저장 → dashboard 조회 공유·독립 복제 허용의 별도 동의/저장 → 최신 공유 관계 재조회 → 새로고침/재조회 후 상태 유지.
2. 수신자: 받은 자료 → 원본 열람/새로고침 → 합계600 USD 및 날짜별100/200/300.
3. 받은 자료의 내 소스로 복제 → 본인 소스 선택 → amount→sales_amount/day→day → 두 블록 모두 유지 → 매핑 확인으로 전체 미리보기1200 USD 및200/400/600.
4. 새 비공개 대시보드 만들기 → 새 ID/본인 소스/두 블록 → 새로고침 보존.
5. 소유자 조회 공유 회수/최신 재조회 → 수신자 받은 자료 빈 목록 → 개인 목록의 사본 Studio 열기/새로고침 → 본인 소스와1200 보존.

API 보조 검사는 원본 Studio 직렬화가 최초와 동일함을 확인했다(queriedAt 제외). 회수 전 수신자의 원본 preview POST는403이었다. 회수 후 원본 Studio GET과 received remix-reference GET은403, 소유자 원본 GET과 수신자 사본 GET은200이었다. 사본 문서도 회수 전후 동일했다. source의 직접 read는 별도로 유지했으므로 이 결과를 source 권한 회수로 표시하지 않는다.

## 반응형·스크린샷

공유·받은 자료·열 매핑·사본 Studio를390/768/1440px에서 확인했다. 각 폭의 innerWidth와 레이아웃이 안정된 뒤 측정한 문서 가로 넘침은0이었다. 초기 크기 전환 직후 일시적인768px 넘침과390px의 이전 폭 값을 관측했으나 목표 innerWidth를 기다린 재측정에서 재현되지 않았다. 제품 CSS를 이 일시 값 때문에 수정하지 않았다.

공유 버튼32px/글자14px, 공유 선택기32px/모바일16px, 매핑 선택기36px/모바일16px를 확인했다. 수신 링크는 좁은 폭에서 줄바꿈하며 매핑 라벨/선택기와 Studio 컨트롤도 겹침 없이 배치됐다. 새 캡처11개(18~28)를 직접 열어 검토했다. 실휴대폰 터치/모든 OS·브라우저 검증은 아니다.

## 문서·배포 확인

실제 UI에 맞춰 소스 읽기와 조회 공유·독립 복제 허용을 분리하고, 저장 후 최신 관계 재조회, 매핑 확인이 미리보기를 실행하는 점, 사본 제목/ID 구분, 회수와 다른 권한의 독립성을 보완했다. 공개 사이트 메뉴·홈·전체 목차·조직·재사용 페이지를 연결했다. 제품 코드 변경은 없다.

루트와 `/guide/` 하위 경로 빌드는 각각23개 HTML/1041개 로컬 참조 오류0이었다. Ego 문서 화면390/768/1440px의 가로 넘침0·강조 문법 노출0 및 모바일 접기 영역/캡처11개 로딩을 확인했다. 전용 실행기는 정상 종료했고 ownedContainerRemoved/temporaryCredentialsRemoved=true, persistentVolumesCreated=0이었다. 별도 임시 계정 파일도 제거했다. push에 대응하는 GitHub Actions 실행과 온라인 새 페이지·이미지 확인은 최종 전달에서 별도로 제시한다. 운영 MySQL migration·다중 그룹/모든 역할·전체 기업 수용을 이번 대표 여정 통과로 확대하지 않는다.
