# UC053 동적 그룹 공유·받은함·독립 복제 검증

2026-10-18. [설계](../plans/UC-053-group-deliveries.md)는 FR021/NFR005/007/008의 구현 단위다. 전체16개/TC050 수용 완료가 아니다.

## 동작과 보존 경계

소유 admin이 그룹에 조회 공유와 별도 복제 동의를 명시 저장한다. 현재·향후 구성원은 현재 조직/계정/그룹 활성·유일 소유권과 별도 소스 read가 모두 맞을 때만 받은함/분석을 연다. 기존 개인 공유·직접/그룹 grant는 독립이며 그룹 공유는 read만 추가한다. 구성원 제외·그룹 비활성·계정/소속/소유권 변경을 다음 요청에서 확인하고 이미 만든 독립 사본은 보존한다.

그룹 버전/관계 CAS·감사·도메인 분리한 UUID 영수증은 한 transaction이다. replay는 과거 성공 확인이며 회수된 관계를 복원하지 않는다. 신규 공유 때 모든 현재/미래 구성원의 소스 권한을 강제하거나 자동 부여하지 않는다. 대신 받은함에서 소스 미허용 자료의 제목도 숨긴다. 그룹 감사의 subjectId는 그룹ID이며 개인 알림 대상자로 해석하지 않는다. 그룹 알림은 후속이다.

받은함은 개인/그룹 후보를 정렬·중복 제거한20후보 단위로 읽고 숨긴 자료도 cursor에 반영한다. 표시 version은 유효한 관계 버전 중 최대값으로, 전체 그룹 변경 revision이 아니다. allowCopy는 현재 허용된 관계 중 하나의 명시 동의다. private `g-` reference는 그룹ID/version·공유 version·원본 fingerprint를 묶고 template/preview/save에서 재검사한다. 기존 개인 `d-`와 익명 게시 토큰을 혼동하지 않는다.

## 실행 증거

- 선택 BE 3 suites/91개 PASS: 실제 SQLite/JWT HTTP로 그룹 공유·현재/미래 구성원·같은 token의 받은함 회수·개인 공유 중복/독립성·read 외 동작 거절·source read 독립·그룹/계정/소속/소유자 변경·CAS/도메인 충돌/replay·영수증 실패 전체 rollback·추가 migration 반복을 확인했다.
- 실제 SQLite/DuckDB/HTTP의 개인/그룹 받은 분석 복제 양쪽 경로에서 전체 미리보기→원자 저장→저장본 재조회와 합계1000 독립 정답, 새 대시보드/블록 ID·모든 폭 좌표·원본 불변·추가 게시0·allowCopy 회수 주입 전체 rollback·동일 요청 재확인·공유/원 소스 회수 후 사본 독립성을 확인했다. 그룹 버전 변경은409, 구성원 제외는403이다.
- 선택 FE 5 files/41개 PASS: 접힌 명시 조회/확인·현재→제안·409 초안 보존/명시 reset·응답 유실 동일 UUID/body 재확인·접기/다시 열기 뒤 요청 보존·실제 unmount 뒤 late 응답 무시·비활성 그룹 회수·그룹 reference 수락/다른 분석 거절/JWT 경로 분리를 검사했다.
- 양쪽 type/lint/build를 실행했다. 최종 전체 BE는 161 suites/2696개 PASS·1 suite/9개 SKIP이다. 중단된 이전 전체 실행은 완료로 합산하지 않고 로그를 보존한 뒤 프로세스 부재를 확인해 재실행했다. 로그는 Git 제외 `.aiwf/evidence/UC053-group-deliveries`에 보관한다.

초기 선택 실행의 실패는 HTTP sandbox bind와 fixture 확장의 update 인수/이전 source grant CAS 재사용, FE 비동기 완료 시점/기존 API 함수 호출 인수 기대였다. 실제 fixture와 검사를 수정하고 재실행했다. 제품에 권한 우회나 잘못된 CAS 허용을 추가하지 않았다.

추가 받은함 경계 suite 21개 PASS: 겹치는 두 그룹의 동일 자료를 중복 없이 읽고, 소스 권한이 없는20개 후보 뒤의 cursor로 다음2개를 확인했다. 전체 FE 124 files/1746개 PASS·격리 headless core E2E 8개 PASS다. strict 명세 lint는 기존 FR011/NFR002 상태 경고2개·오류0이며 경고를 숨기거나 요건 수용 상태를 올리지 않았다.

## 독립 검토와 화면 한계

초기 executor는 제공자 disabled404로 작업을 시작하지 못했고 Main이 구현했다. 사용자 갱신 라우팅에 따라 별도 Sol 검토자가 읽기 전용으로 검토했다. 응답 유실 상태의 패널 접기가 로컬 요청을 버린다는 P2 한 건을 확인했다. Main이 패널을 접어도 mount를 유지하도록 수정하고 동일 body 재확인 회귀를 통과했다. 검토자의 수정 후 재검토/공식 승인으로 표시하지 않는다.

도구32px·선택기36px/모바일16px/데스크톱14px·wrap/min-w-0은 코드/컴포넌트 검사다. 실제 Ego96은 사용자 제어 상태이며 새 Ego/390·768·1440 실측·실휴대폰은 NOT_RUN이다. 기존 isolated headless core는 새 그룹 UI 실측을 대신하지 않는다. 이번 단위 Rill 실제 화면 비교도 미실행이며 권한 합산의 고정 소스 비교는 [선행 증빙](dynamic-groups.md)을 따른다.

MySQL 그룹 공유 DDL/동시성·운영/대규모·사람 수용·그룹 알림/개인별 fanout·공유 요청의 browser reload 복구·영속 export/파일·공통 분류/보관/동일 문맥 비교는 별도 잔여다. 전체 목표는 유지한다.
