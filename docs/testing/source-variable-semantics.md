# UC050 업무 변수 의미 검증

2026-10-18 · develop-v2 · 기준65ff67f5 이후 [설계](../plans/UC-050-variable-semantics.md)의 작업 변경. FR015·NFR005/006/007·TC050 E01 선택 범위이며 전체16개 목표는 active다.

## 구현

기존 추가 전용 source_catalog_entry에 업무 유형(auto/수치/범주/날짜), 날짜 형식과80자 업무 분류를 보존한다. 원본 열 이름/유형·원본 값·계산식은 변경하지 않는다. schema 호환/유일 표시명/전체 크기·동작별 edit 권한과 CAS를 유지한다. 문자열 날짜는 세 가지 고정 형식만 허용하고 전체 non-null 값의 정확한 형식/실제 날짜를 검사한다. NULL은 허용하되 빈 값/불가능한 날짜/다른 패딩/공백은 거절한다. 미리보기는 쓰기0이며 저장 준비에서도 검사한다. 저장 큐에서는 같은 불변 파일 버전/권한을 확인하므로 전체 검사를 반복하지 않는다. 이 최적화는 기존 업로드의 UUID 경로/불변 파일 계약을 전제로 하며 같은 경로의 외부 파일 변조까지 보장하지 않는다. 날짜 오류는 열별 invalidCount/blankCount를 표시하고 NULL 준비를 안내하며 원본 값은 반환하지 않는다. 전체60KB 검사는 날짜 스캔보다 먼저 수행한다.

옛 저장본은 auto/빈 형식/분류이고 옛 클라이언트가 새 필드를 생략하면 해당 열의 최신 선언을 유지한다. 명시 auto/빈 값으로만 초기화한다. 불량 최신 이력은409로 보존형 차단한다. 세 필드는 현재/과거 diff에 포함되며 Explore 입력/동의/서버 draft·저장/다시 읽기와 Studio 명시 조회를 연결한다. 추가 설정은 열별 기본 접힘·공통36px/32px 토큰·1열/넓은3열을 사용한다. 실제 UI 실측은 미실행이다.
