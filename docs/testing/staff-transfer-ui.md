# UC051 직원 관리 실제 화면 후속

2026-10-19 · Status: Draft · develop-v2/f5f9a230 후속. [설계](../plans/UC-051-staff-transfer.md)·[기존 MySQL 증빙](staff-transfer.md)·[UC051](../use_cases/UC-051-manage-enterprise-access.md)·[TC050](../test_cases/TC-050-enterprise-analysis.md)에 연결한다. 이번 UI는 별도 임시 SQLite/업로드 QA 서버이며 MySQL 브라우저 검증이 아니다. 전체16개 요건/TC050·운영/사람 수용은 Open이다.

## 환경과 경계

Ego 단일 공간101·단일 페이지에서 검증했다. 사용자 기존 서버/계정/브라우저 공간은 변경하지 않았다. 새 QA runtime의 합성 계정3개와 조직2개를 API로 준비하고, 검색/발급/철회/수락/이동/로그아웃/로그인은 실제 화면으로 조작했다. 준비 중 signup의 plain-text success를 JSON으로 해석한 설정 오류가 있었으며 새 합성 계정 준비 후 진행했다. 사용자가 제공한 기업 자료는 사용하지 않았다. 이번 QA runtime은 현재 로컬 Node22.23.1을 사용했으며 저장소 지정 Node24 운영 환경의 검증으로 승계하지 않는다.

수락 내용을 검토 뒤 변경하는 경합은 배경 API로 재수락해 만들었다. 다른 브라우저 탭을 직접 조작한 증거로 부르지 않는다. 최종 이동과409 복구는 실제 Ego 화면으로 수행했다. XHR 관찰은 method/path/status만 기록하며 요청·응답을 교체하지 않았다. 합성 credential/동의 원문은 Git 제외0600 파일에서만 사용했다.

## 발견과 수정

1. 요청 없음 상태 GET이 Nest에서200/빈 본문으로 직렬화돼 FE 초기 상태 조회가 실패하고 코드 발급을 시작할 수 없었다. controller가 JSON content-type과 명시 null을 반환하도록 수정했다. 실제 Nest HTTP의 초기/발급/철회 후 상태 회귀를 추가했다.
2. 운영 HttpExceptionFilter는 오류를 data.message로 감싸지만 직원 API helper는 그 위치를 읽지 않아 철회/수락 변경 사유를 일반 충돌로 표시했다. 문자열/문자열 배열의 명시 사유만 읽고 임의 객체/내부 필드는 출력하지 않는다.400/403/409·잘못된 shape 회귀와 같은 필터를 테스트 앱에 연결했다.
3. 명시4xx 거절까지 결과 미확정으로 안내했다. 변경 거절/이동 없음·재검토와 네트워크/5xx/성공 응답 미확정의 상태 확인 안내를 구별한다. 두 경우 모두 자동 재전송하지 않는다. 입력한 관리자 코드는 오류 직후 유지되며, 조직 기준 재조회 시 화면이 초기화되어 다시 입력/검토한다.
4. 검색 입력/버튼은 각각36px이나 설명문 때문에 버튼 top이28px 낮았다. 설명문을 행 밖으로 분리하고 aria-describedby로 입력과 안내를 연결했다. 접근성 연결은 컴포넌트 회귀로 검증했다.768/1440에서는 높이36px/top차이0px,390에서는 정상 세로 배치(입력 top과 버튼 top 차이44px = 높이36+간격8)다.

## 실제 여정

- 원 조직 admin: `%_`를 문자로 검색해 같은 조직 직원1명만 표시. 이메일/다른 조직 목록을 검색하지 않는다.
- 직원: 실제 로그아웃/로그인→이동 요청 없음 JSON 상태→대상 번호 지정·명시 동의→코드 발급→철회→새 코드 발급.
- 대상 admin: 철회 코드 검토 거절과 구체적 사유 표시→유효 코드 검토→팀/member 명시 수락. 수락만으로 직원 소속은 바뀌지 않는다.
- 원 조직 admin: 실제 재로그인→직원/양쪽 조직 version/수락 팀 검토. 이후 배경 API가 팀을 바꾸면 최종 이동409·쓰기 없음·자동 재전송 없음. 알려진 거절 안내 후 조직 재조회→코드 재입력→최신 수락 내용 재검토→명시 이동201.
- 이동 후: 원 조직 version2→3·목록2명→1명, 대상 조직 version1→2. 이전 직원 토큰의 보호 context 조회401. 직원 실제 재로그인 후 새 조직/member/최종 수락 팀, 브라우저 reload 후 같은 이동 완료 상태를 확인했다. 관리자 검색/수락/최종 이동 UI와 코드 재표시는 직원에게 없다.
- 대상 admin: 이동 직원이 현재 명단에 표시되고 이미 처리된 코드 검토는409다.390px에서 구체적 오류 안내·가로 넘침0을 확인한다.

자료/원본 파일 bytes·지표/Studio/독립 사본/게시 행의 보존과 권한 비부활은 [실제 MySQL 선택 검사](staff-transfer.md)를 따른다. 이번 실제 화면은 모든 원본/게시 링크를 열어 재검증한 것이 아니다.

## 크기·정렬

390/768/1440 대표 화면·입력/버튼 bounds/font와 document 가로 넘침을 측정했다. 일반 입력/동작36px, 도구32px, 버튼14px·입력 모바일16px/큰 화면14px를 확인했다. 검색은 위 행 정렬 기준을 따르며 세 폭 가로 넘침0이다. 회원 완료 화면도 세 폭에서 새 조직/팀/완료·관리 UI 숨김을 확인했다. 실제 기기·터치/소프트 키보드·모든 오류/로딩 조합은 미검증이다.

Ego 자동 스크롤이 복구 버튼을 고정 nav 뒤에 놓아 클릭을 막은 경우는 현재 bounds를 확인한 뒤 마우스 스크롤로 버튼을 표시해 이어갔다. 강제 DOM 클릭이나 권한 우회를 사용하지 않았다. 제목/안내 문자열의 복수 매칭·확인 dialog 누락·선택자 공백 차이로 생긴 자동화 실패도 제품 저장 성공으로 계산하지 않았다.

## 실행 증거

Git 제외 `.aiwf/evidence/UC051-staff-ui/`에 캡처·측정 JSON·redacted snapshot·XHR·실행 로그를 둔다. 실제 UI 한 여정의 여러 관찰을 독립 테스트 수로 합산하지 않는다. unit/HTTP/MySQL의 겹치는 사례도 합산하지 않는다.

| 검사                          | 결과/로그                                                                                                           |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| Ego101 실제 주 여정/선택 오류 | `target-accepted.txt`, `known-conflict.txt`, `source-complete.txt`, `source-xhr.json`, `old-token.json`             |
| 크기/정렬                     | `employee-layout.json`, `search-layout-final.json`, `employee-completed-layout.json`, `mobile-error.json`, 대응 PNG |
| 보호 HTTP/SQLite              | `backend-tests.log`;2 suites25 PASS/3 SKIP/2.886초 (MySQL 전용3개 제외)                                             |
| 실제 Docker MySQL8.4.11       | `mysql.log`;25 PASS/3.26초·소유 fixture 정리 PASS                                                                   |
| FE API/컴포넌트               | `frontend-accessible-final.log`;36 PASS/1.22초, 이전 FE 배치와 중복                                                 |
| type/scoped lint/build        | 각 `backend-*`/`frontend-*` 로그                                                                                    |

초기 HTTP 실행은 로컬 소켓 EPERM으로 실행하지 못한 로그(`backend-null.log`)와 로컬 소켓 허용 후22 PASS/3 SKIP(`backend-null-network.log`)를 구별한다. 명시 거절 안내 변경 후 기존409 기대 문구2개가 실패한 FE 로그(`frontend-tests.log`)를 보존하고, 기대 문구를 계약에 맞춰 최종36 PASS로 확인했다.

독립 정적 검토에서 제한된 변경을 확인했고, 검색 안내 접근성 연결 LOW는 aria-describedby/id 및 컴포넌트 단언 보완으로 종결했다. 최종 잔여 지적0이며 검토자가 실제 UI/MySQL을 재실행한 증거와 구별한다.

## 남은 항목

운영 DB 적용·기존 데이터 migration·MySQL 앱 브라우저·전 역할/보호 경로·물리 휴대폰/접근성 전체·퇴사/탈퇴·조직 소유 자료 인계·사람 수용은 남는다. 기존 전역 명세 ID 중복/경고는 이번 범위에서 변경하지 않는다. scoped UC051/TC050은 오류0·경고0이며 전체 strict는 기존 오류17·경고5다. 전체 요건 완료율을 선택 테스트 개수로 계산하지 않는다.
