## 대조 범위와 판정

직원 관리의 `enterprise.controller.ts`/`enterprise.service.ts`/Enterprise UI는 기존 계정 연결·cursor 목록·팀/역할/활성 변경을 제공한다. 이전 점검 당시 직원 검색·조직 이동/탈퇴와 동일하지 않았다. 이번 [직원 검색·조직 이동 후속](staff-transfer.md)은 검색과 명시 이동/권한 회수/개인 자료 보존을 추가했으며 탈퇴·업무 자산 이관 전체 수용은 별도다. `source-catalog-usage.service.ts`의 직접 참조 제한, `notification.service.ts`의 출력 사건, `bi-explore.service.ts`의 직전 기간 비교, `export-jobs.service.ts`의 interrupted/복구를 대조했다. 전체 경로 보안·운영 사건 감사를 재수행한 것은 아니다.

TC050 E13은 추가16개 밖 NFR003에도 연결되지만 TC050 종료 기준에는 남는다. 실제 headless 폭 검사를 Ego·물리 휴대폰·운영·사람 수용으로 승계하지 않는다. “승인된 데이터”를 근거 없이 다단계 승인 workflow의 추가 필수 요건으로 확대하지 않는다. 현재 활성/이용 권한과 업무 승인 기준은 구분한다.

## 다음 작업

1. FR016 직원 검색·명시 이동의 선택 검증 다음은 탈퇴/업무 자산 이관 계약과 전 역할/업무 수용이다. Ego의 선택 관리 화면·대표 폭은 [후속](staff-transfer-ui.md)에서 확인했다. FR022/TC050 자동 사건·FR025 비교 기간 범위도 구체적인 수용 조건으로 고정한다. 미확정 정책을 자동 삭제/이관으로 구현하지 않는다.
2. FR021/NFR008의 미확정 공유·독립 복제 요청을 reload 후 같은 요청으로 확인하는 여정을 보완한다.
3. TC050의 동일 조건 조회→기간 비교→파일 정답, 역할별 회수, 실제 export 프로세스 재시작을 MySQL에서 연결한다. 운영·실기기·업무 수용은 별도 gate로 남긴다.

현재 MySQL 실행의 정확한 범위/소유 fixture 정리와 재현 명령은 [이번 증빙](semantic-business-mysql.md)을 따른다. 모든16개 행을 구현/선택 검증/전체 수용으로 나누어 관리한다.
