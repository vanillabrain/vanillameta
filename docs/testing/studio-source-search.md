# UC050 업무 이름으로 Studio 데이터 찾기

## 범위와 계약

2026-10-18, 비교 기준 `a312b1d7`. FR014/015·BR050-01의 [계획](../plans/UC-050.md) 후속이다. MK AI 연동/조직 공유·공식 승인·AI 자동 이름 적용은 추가하지 않는다. 새 DB 스키마/의존성은 없다.

기존 GET `/bi/sources` 기본 응답은 id/name/engine이다. 명시 query `catalog=1`일 때만 소유 목록과 최신 source_catalog_entry를 MAX(version) LEFT JOIN 한 쿼리로 결합한다. 검증한 actor/ownerId 조건과 기존 JWT guard를 유지하며 source별 쿼리/전체 이력 적재·프로파일/원본 행 실행은 하지 않는다. 목록 자체는 종전과 같이 소유 전체 목록이며 페이지/대규모 부하 성능을 보장하지 않는다. 이력의 최신 표시명이 공백제외1~100자 문자열이면 catalogLabel/catalogVersion을 더한다. 최신 값이 손상됐거나 미등록이면 원본 이름만 반환하며 예전 정상 이름을 대신 노출하지 않는다. 연결 설정·원본 metadata/설명/열·타 소유/NULL 소유 이름은 반환하지 않는다. catalog flag는 생략 또는 문자열1만 허용하고 다른 값은400이다.

Studio의 공용 fetchStudioSources만 opt-in한다. 선택기 기본은 접힌 `데이터 검색`이고 펼치면 업무 이름/원본 이름/ID를 NFKC·소문자·앞뒤 공백 정규화한 부분검색으로 찾는다. 옵션은 업무 이름(있을 때)·원본 이름·ID로 동명이름을 구분한다. 검색 불일치라도 현재 선택은 남기고 검색 결과 개수와 별도로 안내한다. 검색을 접으면 전체 목록을 다시 보여주며 실제 선택은 명시 select 변경만 실행한다. 미지원 엔진 선택 불가는 유지한다. 검색은 로컬 읽기만 하며 질문/제안/선택 소스/생성 미리보기·저장 준비를 바꾸지 않는다. 업무 이름은 목록 조회 시점의 탐색 참고이고 최신 설명/열 구조는 선택 후 기존 업무 설명 조회에서 대조한다.

## 검증

- FE 신규 선택기/목록 검증: 접힘·업무/원본/ID 검색·Unicode 정규화·동명이름·미지원·검색0건 선택 유지/접기 복원·목록 변경·busy 잠금·옵션 summary 검증. 생성 컴포넌트에서 제안500 이후 검색0건에도 선택/원 질문/생성안·저장 버튼 보존/추가GET·POST0을 확인한다.
- 공용 선택기는 Studio 생성/재사용에 연결한다. 기존 Remix 테스트는 선택기를 mock하므로 재사용 실제 화면 증거로 확대하지 않는다. StudioCreate/대화 생성/업무설명·생성 계약 회귀를 함께 실행한다.
