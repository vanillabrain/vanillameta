# UC048 — 새 생성 질문·소스 복구 검증

## 범위와 판정

2026-10-17, develop-v2. P2/P3·FR009/NFR004의 새 생성 입력 보존을 보완했다. 구현/회귀 PASS이며 실제 Ego 화면·390/768/1440px 크기·정렬은 로그인 대기로 BLOCKED다. 고객 파일럿·운영·실휴대폰·전체 제품 수용은 미검증이다.

## 구현

- `/studio/new`의 사용자가 편집한 질문과 선택 소스 ID만 기존 로그인 scope의 탭 저장소에 별도 키로 보관한다. 24시간/8KiB/2000자 제한이며 SQL·파일·토큰·제안·미리보기는 보관하지 않는다.
- 재진입의 소스 목록 조회 후 복구/폐기를 제안한다. 명시 복구에서 소스 profile/지표를 다시 확인하고 성공한 경우 질문을 적용한다. 접근 실패는 질문을 표시하지 않고 기록을 유지한다. AI·업로드·저장은 자동 실행하지 않는다.
- 저장 확인 요청 복구가 우선이며 직접 source/proposal 링크는 보관 질문으로 덮지 않는다. 현재 질문의 저장 성공은 기록을 정리하고 다른 직접 링크의 저장은 무관한 기록을 유지한다.
- 기존 Notice·32px 작은 버튼과 반응형 action 행을 재사용했다. 실제 실측은 수행하지 않았다. 저장소 오류는 현재 생성을 막지 않는 안내를 제공한다.

- TypeScript/변경 파일 ESLint PASS. 로그는 `/tmp/vm-create-question/type.log`, `lint.log`, `unit.log`에 보관한다.

## 실제 화면 검증 제한

기존 Ego TaskSpace96은 로그인 화면에서 사용자에게 인계된 상태다. 신규 계정 생성은 자동 승인 검토에서 거절됐으며 생성하지 않았다. 로그인 권한을 우회하거나 다른 세션의 인증을 복사하지 않았다. 따라서 실제 새로고침·복구·생성·저장과 세 폭의 크기·정렬은 **BLOCKED/NOT_RUN**이다. 기존 계정 로그인 또는 계정 생성의 명시 허용 후 같은 공간에서 수행할 후속 gate다. 이 문서는 컴포넌트 재마운트를 실제 브라우저 새로고침 검증으로 간주하지 않는다.
