## 설계·최소 변경

AIWF UC/TC/설계/계획을 먼저 작성하고 기존 UC017/025의 세 방향 비교·복구 경계를 확인했다. 최신 조회 revision이 보관 기준과 다르면 복구 전 안내를 추가했다. 이 단계는 버전 차이 안내이며 실제 항목 충돌은 복구 후 저장 상태 GET으로 확인한다. 기존 helper/서버 CAS/저장/게시 계약을 그대로 사용했고 새 의존성·DB·API·LLM 변경은 없다. Source/Measure/Dimension/Publication 모델·용어는 바뀌지 않아 entity/glossary를 중복 수정하지 않았다.

## 실제 두 탭 여정

1. 첫 탭에서 미저장 대시보드 제목을 “UC026 · 내 초안과 최신본 합치기”로 바꾸고 질문 “보관한 초안의 제목과 다른 탭에서 변경한 OS 차트를 함께 유지해 줘.”를 입력해 같은 탭 보관을 확인했다. 이번 여정은 보관 질문을 자동 실행하지 않고 직접 편집·재미리보기로 처리한다. 실제 LLM 재질문은 이번 실행 범위가 아니다.
2. 둘째 탭에서 대시보드 제목을 “UC026 · 다른 탭의 최신 제목”, OS 제목을 “UC026 · 다른 탭에서 수정한 OS별 요청 수”로 바꾸고 전체 미리보기201→저장201을 수행했다. 기준과 최신 revision은 달라졌다.
3. 첫 탭 실제 reload에서 복구 전 버전 차이 안내를 확인했다. 후보를 자동 덮어쓰거나 저장하지 않았다. 보관한 초안 복구를 명시 선택하자 제목·질문을 복원하고 AI/미리보기/저장을 잠갔다. 저장 상태 확인 GET200 후 대시보드 제목 충돌과 비대상 최신 변경 보존 안내를 확인했다. `reload-offer-audit`/`state-check`는 GET만 있다.
4. **충돌 항목에 내 변경 사용**을 눌러 로컬 대시보드 제목과 최신 OS 제목을 합쳤다. 질문은 유지했고 저장은 새 미리보기 전 비활성이었다. `merged-form`의 보관 기준 revision도 최신본으로 갱신됐다. 전체 재미리보기201은 최신 revision을 사용했고, 저장201은1회였다.
5. 저장 후 재조회한 items 전체가 둘째 탭 최신 items와 같고, 대시보드 제목만 로컬 값이다. 숫자 블록 전체는 최초와 같다. OS는 제목·그에 따른 savedDefinition.title만 바뀌었고 계산/표시/ID/모든 폭 배치는 보존됐다. 저장 성공 후 feature 보관 key0·편집기 재진입 질문 빈값·복구 안내 없음이다.
6. 같은 저장 revision의 게시 결과 미리보기201→명시 링크 게시201로 버전11을 만들었다. 공개/저장 화면을 실제 reload해 로컬 제목+최신 OS 제목을 확인했다. 숫자1,269,026,000·추세169점의 시간/값·OS28그룹 값이 미리보기와 게시 snapshot에서 일치했다. 공개 JSON은 인증 헤더 없이 GET200을 확인했지만 공개 탭은 로그인 세션이므로 익명 브라우저 세션 검증으로 표기하지 않는다.
7. 임시 링크를 중지해 최종 버전12/inactive·공개 GET404를 확인했다. 복사본35의 병합 결과는 비공개로 보존한다. 제품 서버 fault/데이터 초기화는 사용하지 않았다.

`assertions.py/json`은 위 보존·revision·추가쓰기0·저장1회·정리·게시 버전을 비교한다. 최초 Rill oracle 수치는 UC025/TC005 증거를 재사용했고 이번에 Rill 화면을 새로 실행하지 않았다. 이번 요청의 쓰기 대상은 복사본35뿐이며 원본27은 변경 요청을 보내지 않았다. 원본27 전체 응답 재조회는 이번 실행에 포함하지 않았다.
