# UC053 수신자 조회 공유 검증

2026-10-18 · FR021/022/NFR005/007/008의 조회 공유 단위. [계획](../plans/UC-053-deliveries.md)·[전체 완료 목표](../plans/enterprise-completion.md)를 따른다. 동적 그룹/수신자 독립 사본 전달을 이 단위 완료로 대체하지 않는다.

## 구현 결과

- 별도 `EnterpriseDashboardDelivery` 관계의 read만 기존 dashboard 권한/발견 목록에 합성한다. 양쪽 활성 계정/현재 조직·현재 유일 소유권을 대조한다. edit/publish/export는 기존 직접 grant만 따른다. 대시보드와 별개로 모든 연결 소스의 read가 필요하다.
- 소유 admin의 최대50명 원자 공유/회수·관계별 CAS와 요청 UUID/digest 영수증을 구현했다. 한 수신자 소스 거절/409면 관계·감사·영수증 모두 rollback이다. 같은 요청 내용의 수신자 순서는 정규화하며, 다른 body/조직 replay는409다. 응답 유실 후 replay는 과거 작업 확인만 하며 이후 회수를 되돌리지 않는다.
- 회수는 직접 grant/원본 정의·매핑/수신자 독립 사본을 지우지 않는다. 비활성/다른 조직으로 이동한 기존 수신자도 회수 가능하다. 이미 같은 상태면 version/감사 이벤트를 추가하지 않는다.
- 공유/회수 감사 이벤트를 개인 알림 원장에 연결하고 권한 변경과 다른 문구로 표시한다. 알림 표시 상태 저장 실패는 공유 저장과 독립이다. 외부 발송은 없다.
- 조직→자원별 권한→대시보드에서 접힌 조회 공유 패널을 연다. 명시 관계/직원 읽기·직원 페이지/조직 버전 확인·직원/현재 불러온 팀 snapshot 선택·인원/변경 미리보기·명시 확인→원자 저장이다. 미확정 응답은 동일 요청만 재확인하고 최신 관계 읽기 실패에도 요청을 보존한다. 성공/영수증 replay 후 새 쓰기 전에 최신 관계를 다시 요구한다.
- 현재32px 도구/14px 본문/12px 보조·flex wrap/min-w-0·긴 팀 이름 줄바꿈을 적용했다. 컴포넌트 구조 검증과 실제 크기·정렬 실측은 구분한다.

## 별도 Main 검토

구현 뒤 별도 읽기에서 정책 합성·직접 grant 불변·SourceAccess의 모든 소스 검사·대시보드 controller 목록 filter/개별 read·CAS/영수증 순서·본문 canonical clone·현재 조직 binding·UI 재시도/늦은 응답을 확인했다. receipt에 organizationId를 추가하고 조직 이동 replay 거절을 보강했다. UUID 생성 실패도 busy가 해제되도록 try/finally 안에 두었다. 독립 에이전트 검토를 수행했다고 주장하지 않는다.

## MySQL 잠금 경계

첫 권한 snapshot 전에 actor/수신자의 User·Membership을 정렬된 ID로 잠그는 MySQL/MariaDB 분기를 추가했다. 기존 계정/소속 변경과의 경합은409 재시도로 분리한다. 전체 BE 실행 뒤 추가한 분기이며 현재 SQLite 선택 검사와 타입/린트/빌드만 실행했다. 실제 MySQL 동시 실행/잠금 순서·운영 지연을 검증한 것으로 간주하지 않는다.

## 미완료 범위

일반 소유 member의 공유 정책·동적 그룹 membership·수신자 별도 받은함/독립 사본 전달 및 소스 교체·미확정 요청의 브라우저 새로고침 복구·영수증 보존/만료·대규모 목록 성능·MySQL 실제 동시 실행·Ego/실휴대폰·전체 TC050/사람 수용은 후속이다. 현재 팀 선택은 불러온 명단만 대상으로 하며 동적 그룹 권한이 아니다. 전체16개 요건 완료율은 하위 구현 수로 계산하지 않는다.
