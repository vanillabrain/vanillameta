# UC051 인계 전 파일 보관 관측 증빙

Status: Draft

[설계](../plans/UC-051-handover-custody.md)·UC051 A6/BR-051-07·TC050 E02/E03의 선택 단위다. 현재 소유자만 수락된 고정 요청의 관리 파일 신원/알려진 소비자/열린 갱신을 읽는다. 실제 이전·퇴사·전체16개/TC050 수용은 Open이다.

## 범위

기존 명시 연결 조회와 구별한 custody GET와 명시 화면 버튼이다. schema·migration·자산/권한·파일·감사 쓰기를 추가하지 않는다. observed는 파일 연결 신원의 관측이며 내용 정상·배타적 보관·복구/수신자 책임 확정이 아니다. SQL을 실행하거나 파일을 복사/삭제하지 않으며 전역 의존성·운영 수용을 증명하지 않는다.

## 검증 기록

구현 후 실행한 결과만 반영한다. 설계 검토에서 삭제용 helper의 무제한 재귀 순회를 그대로 재사용하지 않도록 지적받았다. 관측에 필요한 파일/manifest와 SQLite companion만 읽는 전용 reader, 경로 길이/깊이·소비자 수·manifest 읽기 한도로 설계를 보완했다. 기존 삭제 복구용 누락/미등록/validation_failed 허용은 관측 성공으로 승계하지 않는다.

## 실제 환경에서 확인한 보완

격리 QA 가입 시 자동 생성된 암호화 SQLite 샘플5개는 이 기능의 허용된 관리 경로 밖이어서 소비자 검사에 미확인 상태를 남긴다. 첫 API oracle은 이를 고려하지 않고 공유 미관측을 기대해 실패했으며, 실제 상태를 확인한 뒤 기존 샘플을 삭제/수정하지 않고 기대값을 unresolved로 바로잡았다. 이 실패를 제품의 공유 부재 증명으로 바꾸지 않는다.

동시에 선택 파일의 공유가 이미 발견됐는데 다른 소비자 오류가 이를 가리는 동작을 발견했다. 적어도 하나의 공유가 확정되면 present를 유지하고, 관측된 공유가 없을 때만 미확인을 unresolved로 표시하도록 보완한다. present 역시 전체 소비자 검사를 완료했다는 의미는 아니다. 외부 연결 카드의 반복된 파일 대상 아님/0개 항목도 줄여 연결 계정 별도 검토 안내에 집중한다.

독립 검토에서는 소비자 순회 한도의 조기 반환이 이미 관측한 hardlink를 가리는 잔여 분기를 지적했다. 실제 hardlink와2001개 metadata 행을 준비한 HTTP 회귀로 expected present/actual unresolved를 재현하고, 한도에 걸려도 확정 관측은 유지하도록 보완했다. 첫 재현 실행의 로컬 listen EPERM은 제품 실패와 별도 보존하고, 허용된 로컬 HTTP 환경에서 실제 판정 실패를 다시 확인했다. 양성 관측이 없는 순회 한도는 계속 unresolved다.

## Ego105 실제 화면·불변성

전용 격리 SQLite 서버와 합성 계정·조직/metadata, 실제 DuckDB CSV import3개를 준비했다. 2개만 해당 source에 등록하고1개는 미등록 상태로 유지했다. 다른 소유자의 같은 파일 설정과 실패/만료됐지만 미해제 lease도 별도로 준비했다. 원본 준비의 import/register 쓰기는 검토 GET의 쓰기0와 구별하며 외부 DB 연결은 열지 않았다.

소유자 로그인→수락 요청 번호 조회→연결 검토 열기→파일·갱신 상태 명시 조회에서 정상 등록 파일의 신원 관측, 미등록 파일의 확인 불가, 알려진 공유 present와 열린 작업 주의, 외부 연결의 별도 계정 검토를 확인했다. 기존 자동 샘플 때문에 공유 미관측을 확정할 수 없는 카드도 주의 상태로 유지했다. 경로/파일명/manifest/신원/hash·미선택 소비자 제목은 실제 HTTP/UI에 노출되지 않았다.

네트워크 offline 실패(status0)→이전 결과 제거·같은 요청 번호/4개 고정 제목 보존→명시 재조회200을 확인했다. 이번 작업의 임시 manifest만 배경에서 validation_failed로 바꾼 후 명시 조회에서 해당 신원이 확인 불가로 바뀌었고, 원래 바이트를 복원한 뒤 새로고침/요청 번호 입력/명시 조회에서 다시 신원 관측으로 표시됐다. 이 배경 변경은 실제 UI 편집으로 계산하지 않는다. reload 후 패널은 접혀 있고 결과가 자동 복원/실행되지 않았다.

최종 검토 보완 build를 서버에 반영한 뒤 같은 Ego 공간에서 공유/갱신 경고와 재조회200을 다시 확인했다. 정상 로그아웃→수신자 로그인→같은 요청 조회에서도 고정 제목4개만 보이고 연결/파일 검토 패널은 숨겨짐을 확인했다. 실제 HTTP의 소유자200·수신자403·admin403·타 조직403·익명401과 원본/비밀 비노출을 검증했다. 순수 GET 전후66개 표의 행/hash와13개 파일의 내용/hash/mtime이 모두 같았다. manifest의 명시 fixture 변경/원복과 로그인/reload의 기존 인증 이력 쓰기는 별도이며 이 순수 조회 비교에 포함하지 않는다.

최종390/768/1440 화면을 메인이 열람했다. 확인 버튼36px·기존 접기 도구32px·입력36px와 글자16/16/14px, 가로 넘침0·상세 한계 접힘을 확인했다.390/768은 카드 세로8px 간격,1440은 행별 두 카드 top 차이0px다.768의 콘텐츠 폭은 scrollbar 포함753px여서 실제 한 열 표시를 기록했다. FE 디자인은 이후 변경하지 않았으며 마지막 BE 경계 보완 뒤 같은 화면 재조회로 연결을 확인했다. 실제 휴대폰/모든 상태 화면을 뜻하지 않는다.
