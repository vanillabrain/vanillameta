# UC-014 명시 저장 질문 검증

2026-10-15 · 기준 `d4a64306` 위 UC-014 변경 · P3. AIWF UC/설계/TC/계획과 실패 회귀를 먼저 작성했다. 기본 자동 질문에서 현재 초안 저장 또는 선택 블록 변경+저장을 명시하면 서버 미리보기 뒤 기존 저장 API를 호출한다. 변경만 요청하면 미리보기로 끝난다. 수동 목적은 기존 미리보기 전용이다.

## 기능 검증

Ego TaskSpace14 / 공개 Rill source7·검증 분석22 / 기존 Codex/gpt-6-luna 설정. 모델 자동 대체는 없다. 설정 확인과 독립 모델 attestation은 구분한다.

- **PASS 저장만:** 블록을 선택하지 않고 제목을 `요청 수와 평균 입찰가 · 질문 저장`으로 직접 편집했다. “현재 편집 내용을 저장해 줘.”→editor/ai201(`save`,saveRequested=true,미리보기4블록)→editor201→저장 화면→실제 reload를 확인했다. 전체 응답 deep 비교에서 title/revision 외에는 동일하다. 저장 중 비활성 컨트롤과 안내도 캡처했다.
- **PASS 변경+저장:** 2번 복사본 `모바일 연속 요청 수`에서 “선택한 블록의 소수 자릿수를 3자리로 바꾸고 현재 분석에 저장해 줘.”를 요청했다. editor/ai201은 content/true이고 기존 소수2자리 요청에 대해 새 item 소수3자리와4블록 미리보기를 반환했다. 뒤따른 저장 요청은 새 소수3자리 body로201이었다. reload 후4 unique ID·복사본634.513M·추세·exact634513000을 확인했다. 원본3개 정의·모든 SQL·세 화면 폭 배치·기존 선택 블록의 나머지 필드는 완전 동일하다.
- **PASS 부정 저장 요청:** “저장하지 말고 선택한 블록의 소수 자릿수만 2자리로 바꿔 줘.”는 content/saveRequested=false의 변경 미리보기만 만들었다. 실제 저장 API0회이며 저장 분석 전체 응답(revision 포함)이 전후 deep equal이다. 미저장 소수2자리 초안은 reload로 버리고 저장된3자리 상태로 돌아왔다.

서버 editor/ai는 저장하지 않는다. save-only도 compiler→preview이며 후속 기존 저장 API가 소유권·revision을 다시 검증한다. 수정 요청은 저장 문구를 제거한 editPrompt만 기존 생성기에 전달한다. UI는 상태 갱신 전의 이전 items가 아니라 검증한 nextItems로 저장한다.

## 디자인 검증

최종 버튼은 실행 범위를 드러내는 `AI 요청 실행`이며 별도 저장 모드를 추가하지 않았다. 고급 목적 설정은 기본 접힘이다. 자동 모드에서 저장을 명시해야 한다는 보조 안내를 추가했다.390px은 입력/버튼 세로 배치,768/1440px은 중앙 정렬 행을 사용한다. 최종 실측·캡처는 `final-measurements.json`·`final-editor-*.png`를 따른다. 버튼28px/입력32px·12px글꼴과 가로 넘침0을 실측하고 캡처로 정렬을 확인했다. 대표 기본/저장중/미리보기 상태만 확인했으며 실제 휴대폰 검증은 아니다. 숫자/시계열 디자인과 원래 Rill 전체기간635M/$5.57 비교 증거는 SQL·데이터 집계가 불변이어서 재사용했다. 이번에 Rill 화면을 다시 조작하거나 Rill에 같은 질문 저장 기능이 있다고 주장하지 않는다.

## 실행 중 문제와 범위 제한

처음 실제 저장 실패 UI를 만들려던 CDP 차단 패턴은 /editor/ai까지 함께 차단하여 status0의 일반 AI 오류를 만들었다. 기대한 저장 단계 오류 검증으로 세지 않았다. finally에서 차단을 해제한 뒤 실제 provider를 사용해 성공 흐름을 검증했다. 저장 실패·409·취소는 자동 회귀의 증거와 구분한다.

저장 중 화면을 캡처하기 위한 일시1500ms 네트워크 지연 때문에 첫 reload의 load 대기가15초를 초과했다. finally에서 지연0으로 복원한 뒤 실제 reload를 다시 실행하여4블록·저장 제목/수치를 확인했다. 수정+저장 최초 클릭은 Ego 자동 스크롤이 고정 헤더 아래로 버튼을 가져가 실패했고 요청0회였다. 현재 상태를 확인하고 버튼을 중앙으로 스크롤한 뒤 같은 질문을 정상 실행했다. 이 도구 실행 오류를 제품 저장 오류로 보고하지 않는다.

부정/조건부 의도의 해석은 LLM의 엄격 계획+지침을 사용하며 모든 자연어 변형을 결정적으로 보장하지 않는다. 실제 확인 문장 이외의 오해 가능성은 남는다. 저장 전송 뒤 취소/서버 rollback/exactly-once 영수증·운영MySQL·실제 휴대폰·모든 오류 UI·게시/다중블록/전체 TC005 수용은 미검증/미구현이다. 전송 뒤 결과 불명확은 자동 재시도하지 않고 최신 저장 상태 확인을 안내한다.

증빙은 저장소 밖 `/tmp/vm-prompt-save/`의 before/after 응답·XHR events·compare.json·최종 UI 캡처, `/tmp/vm-save-{be,fe}-*.log`와 `.aiwf/evidence/UC-014/`에 보관한다. 인증 토큰/비밀번호는 기록하지 않았다. TaskSpace14는 종료했고 임시 sessionStorage 관찰 키·CDP 차단/지연을 제거했다. 임시 증거의 영구 보관은 보장하지 않는다. 실제 서버는 기존4898/3698을 재사용했고 다른3000/4000 서비스는 종료하지 않았다.
