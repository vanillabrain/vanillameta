# Vision

## Product

VanillaMeta — Prompt To Dashboard

## Problem

운영팀은 데이터 연결, 지표 계산, 차트 제작, 배치, 공유를 서로 다른 화면에서 반복한다. 원하는 결과를 질문해도 편집·게시·재사용까지 이어지지 않으면 대시보드 제작 업무가 끝나지 않는다.

## Outcome

사용자가 한 요청으로 데이터 기반 대시보드를 만들고, 대화 또는 직접 블록 편집으로 수정하며, 반응형 결과를 저장·게시하고 다른 데이터로 재사용한다. 내부는 Source·Measure·Dimension·Block·Dashboard·Publication 책임을 구분하고 사용자 화면은 대화와 결과 중심으로 유지한다.

최상위 계약과 우선순위는 [제품 목표](strategy/prompt-to-dashboard.md), 목표 데이터·상태 계약은 [통합 설계](architecture/prompt-to-dashboard.md), 전체 수용 시나리오는 [UC-005](use_cases/UC-005-prompt-to-dashboard.md)를 따른다. UC-001~004는 이 목표를 지원하는 구현된 하위 범위이며 그 검증 결과를 전체 제품 완료로 확대하지 않는다.

## Users

운영 담당자: 데이터로 결과물을 만들고 수정·게시한다. 공유 수신자: 게시 결과를 조회하고 허용된 결과물을 복제해 자신의 데이터로 재사용한다.

## Success Criteria

TC-005의 생성 → 지표·차원 재사용 → 블록 이동/크기 조절 → AI 수정 → 저장/새로고침 → 게시/재게시 → 다른 계정 조회 → 복제/소스 교체가 모두 실제 화면/API로 통과해야 제품 목표를 달성한 것으로 판정한다. 390/768/1440px에서 블록·컨트롤 손실 및 화면 가로 넘침이 없어야 한다. 동일 조건의 계산 결과는 서버 및 독립 정답과 일치해야 한다. 현재 전체 여정은 not_run이다.

## Non-Goals

현재 단계의 Rill 전체 복제, YAML 파일 트리 고객 노출, 외부 엔진 선행 구현, 임의 생성 코드를 실행하는 범용 앱 호스팅, 실시간 공동 편집, 미래 확장만을 위한 전면 리팩터링은 목표에 포함하지 않는다. 고객이 요청한 대시보드 게시·공유는 목표에 포함하며 운영 인프라 배포 완료와 구분한다.

## 사내 기업 활용 확장 — 2026-10-18

사내 활용을 위해 조직/데이터 관리자·분석 담당자·수신자의 카탈로그·권한·조건 탐색·전달·출력·보관 요구를 추가했다. [목표 설계](architecture/enterprise-analysis.md), TC050은 Draft/NOT_RUN이다. 기존 제작/편집 기반을 재사용하며 MK AI 별도 프로젝트의 연동 계약은 보류한다. 이 추가가 기존 TC005 전체 수용이나 VM 기업 운영 완료를 뜻하지 않는다.
