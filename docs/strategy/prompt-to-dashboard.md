# 제품 목표와 방향 유지 계약

2026-10-14 사용자 요청에 따른 최상위 제품 목표. 기존 계획과 우선순위가 다르면 이 문서와 최신 사용자 지시를 따른다. 구현 선택은 가설이며 확인되지 않은 기능은 완료로 기록하지 않는다.

## 하나의 목표

**프롬프트로 데이터 대시보드를 생성·수정하고, 반응형 블록을 직접 편집하며, 게시·공유·복제·재사용까지 이어가는 솔루션.**

Rill은 데이터 의미·계산·탐색의 기준이며, Claude Artifact의 대화 옆 결과물 편집·공유 경험은 제품 흐름의 참고다. 참조 제품의 기능 개수나 화면 복제 자체는 완료 기준이 아니다. 기존 Rill 비교 지침은 관련 탐색/계산 화면에 계속 적용한다.

## 사용자 경험 계약

- 하나의 입력창에서 생성·질문·수정·저장·게시·복제를 요청한다. 명시한 동작은 현재 소유권·리소스 범위에서 실행하고 완료된 동작/실패한 동작을 결과 옆에 표시한다. 사용자가 모드나 API를 골라야 하는 구조를 기본으로 삼지 않는다.
- 연결된 소스를 선택하거나 파일을 첨부하면 AI가 필요한 지표와 차원을 제안한다. 내부 용어는 지표/분류 기준으로 설명하며 이름·계산 기준을 결과와 함께 검토할 수 있게 한다. 모호한 환불률 분모처럼 결과를 바꾸는 질문만 묻는다.
- 한 요청은 여러 실행 단계가 될 수 있다. 생성 요청만 했으면 초안/미리보기까지, 저장·공유까지 명시했으면 검증된 결과의 저장·게시까지 진행한다. 새 공유 범위는 요청에 근거해야 하며 불명확하면 비공개 초안을 유지한다. 단계마다 형식적인 승인 질문을 강제하지 않는다.
- 대화 옆 캔버스에서 블록을 추가·삭제·복제·이동·크기 조절한다. 설정은 블록 선택 시 나타난다. 숫자와 그 추세는 기본적으로 함께 보이고 설명·차트·표·필터도 블록으로 다룬다.
- 드래그 편집과 AI 수정이 같은 결과물에 반영된다. 특정 블록 수정은 다른 블록 ID·계산·배치를 유지한다. 반응형 읽기와 반응형 편집을 모두 지원한다.
- 저장, 게시, 공유 중지, 복제를 구별한다. 편집 중인 초안은 이미 게시한 결과를 몰래 바꾸지 않는다. 복제 결과는 원본을 바꾸지 않으며 새 소스로 매핑 후 미리보기를 거친다.

P1 첫 단위인 안정적 블록 ID·선택 AI 수정·배치 보존/표시는 [UC-006 검증](../testing/block-layout-continuity.md) 범위로 구현했다. 편집기 복제·로컬 undo/redo는 [UC-007](../testing/block-editor-history.md) 단위/API PASS, 실제 UI BLOCKED다. [UC-008](../testing/working-draft-ai.md)에서 선택 AI 수정도 같은 미저장 초안·이력에 연결했다(단위/실LLM/API PASS, UI BLOCKED). [UC-009](../testing/responsive-block-layout.md)에서 화면 폭별 좌표 저장·복원을 연결했다(단위/실LLM/API PASS, UI BLOCKED). [UC-010](../testing/pointer-block-layout.md)에서 포인터 drag/resize 연결과 키보드 편집을 추가했다(컴포넌트/API 및 실제 키보드·저장·새로고침 PASS, 대표 반응형 화면 확인, 실제 마우스·터치 미검증). [UC-011](../testing/ai-block-layout.md)에서 선택 블록·선택 폭의 자연어 배치 요청을 공통 이력에 연결하고 실제 지정 LLM·저장·새로고침을 확인했다. 자동 의도 분류와 다중 블록 배치는 후속이며 P1 전체는 Open이다. 신규 기능은 관련 UC/BR/TC와 최소 단위로 나누어 설계한 뒤 구현한다.

## 방향 이탈 방지

작업 시작 시 작업 문서에 다음을 기록한다: 연결된 P 단계/FR/수용 기준, 관찰된 부족점, 변경할 파일/계약, 실제 검증 방법, 종료 조건. 가장 앞선 미완료 단계에서 전체 여정을 막는 항목을 우선한다. 직접 기여하거나 해당 단계의 보안·정확성·UI 회귀를 막는 작업만 현재 범위에 넣는다.

Pivot 고도화, 더 많은 차트 유형, 커넥터, API/알림 등은 전체 여정의 확인된 장애를 해결할 때 진행한다. 새로운 외부 수요 없이 Rill 기능 목록을 따라 범위를 늘리지 않는다. 목표의 데이터·편집·게시 경계를 훼손하는 임시 구현은 편의상 완료 처리하지 않는다.

완료 보고는 구현 범위, 동작 증거, 디자인 증거, 미실행 항목, 다음 P 단계로 나눈다. 단위 테스트·스펙 pin·문서 상태·코드 존재만으로 전체 여정을 완료 처리하지 않는다. 현재 상태는 [통합 설계의 구현 대조](../architecture/prompt-to-dashboard.md#현재-구현과-목표의-차이)를 확인한다. 이 표는 관련 코드/실행 증거가 바뀔 때만 갱신한다.
