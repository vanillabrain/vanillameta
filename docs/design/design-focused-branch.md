작업 브랜치는 `codex/self-service-next-20261014`, 시작점은 develop-v2와 통합한 `5ef232dc`다. 이후 이 브랜치의 우선순위는 셀프서비스 BI 화면의 디자인·가독성·상호작용 개선이다. 수정은 이 워크트리에서 수행하고 develop-v2 병합은 별도 요청 시 진행한다.

## 2026-10-15 사용자 방향 반영

최신 우선순위는 [Prompt → Canvas → Publish 재검토](prompt-canvas-direction-review-20261015.md)를 따른다. 먼저 Dashboard Studio의 대화·캔버스·선택 블록 설정·공유 흐름을 설계한다. MUI는 유지하고 레퍼런스와 대표 시안을 기준으로 검토하며, 전면 shadcn 이관이나 임의 혼합은 시작하지 않는다. 아래 화면별 개선은 이 제품 흐름 안에서 수행한다.

## 화면별 개선 대상

1. **지표 탐색 / 공통 필터**: 상단 도구 모음을 소스·보기 전환, 기간·필터, 표시 설정으로 묶는다. 필터 추가 전후의 정렬을 유지하고 긴 이름·다중 선택·오류 안내의 줄바꿈을 확인한다.
2. **대시보드 / KPI / 차트**: 주요 액션과 보조 액션의 위계, KPI 값·단위·추세·설명의 간격, 카드와 차트 축의 정렬을 정리한다. 원본 행 보기와 AI 진입점의 과도한 시각적 경쟁을 줄인다.
3. **Pivot / 저장 보기 / AI 패널 / 공유**: 표의 숫자 정렬과 스크롤 범위, 패널 너비, 긴 코드·메시지, 팝업 버튼과 폼 상태를 통일한다.
4. **온보딩 / 데이터 연결**: 기존 흐름을 유지하면서 빈 상태의 다음 액션과 연결·처리 상태를 명확하게 한다.

## 시작 시 확인된 코드상 문제 후보

- AnalysisUi의 강조색은 indigo이고 기존 제품은 blue를 사용한다. 대표 화면에서 실제 사용 위치를 확인한 뒤 브랜드 계열로 통일한다.
- 일반 버튼 28px와 입력 32px가 같은 행에 섞인다. 역할별 밀도 기준과 수직 중앙 정렬을 정의하고 모바일 터치 영역을 별도로 확인한다.
- SourceExplore에 공통 토큰 외의 색·반경·간격 값이 남아 있다. 전역 치수를 무조건 강제하지 않고 바뀌는 영역부터 공통 기준을 적용한다.

위 항목은 코드 조사 결과이며 아직 실제 화면의 결함 PASS/FAIL 판정은 아니다.

## 완료 기준

- 각 화면은 변경 전 캡처 → 소규모 수정 → 같은 상태·폭의 변경 후 캡처 순서로 진행한다.
- 대표 폭은 데스크톱 1440px와 모바일 390px다. 필터 없음/긴 다중 필터, 선택/비활성/오류/키보드 포커스 중 영향받는 상태를 선택한다.
- 버튼·입력 높이와 기준선, 간격, 글꼴·행간, 색 대비, 긴 텍스트·큰 값의 잘림, 페이지 가로 넘침을 확인한다. 표의 의도된 내부 스크롤은 구분한다.
- 화면 확인은 vanillameta-verify 기준으로 수행한다. Aside 불가 시 허용된 Codex 브라우저를 사용하며 브라우저·URL·커밋/diff·뷰포트와 한계를 기록한다.
- CSS 변경은 변경 UI와 필요한 타입·린트만 검사한다. 통과한 수치·저장 테스트는 관련 로직이 바뀌지 않으면 재사용한다.
- 기능 PASS와 디자인 PASS를 구분한다. 미확인 조건은 NOT_RUN으로 남긴다. 캡처는 저장소 밖 증빙 폴더에 저장하고 채팅에도 표시한다.
