# Prompt → Canvas → Publish 방향 재검토

2026-10-15. 검토 기준: `5ef232dc`의 코드와 공식 제품·라이브러리 문서. 실제 제품 여정 전체를 새로 실행한 디자인 감사가 아니라 제품 구조·구현 대조 및 레퍼런스 조사다. 화면별 디자인 PASS를 선언하지 않는다. 런타임·수치 검증 기록은 기존 MD 범위를 유지한다.

## 판단

제품 방향은 맞다. 이미 vision.md와 strategy/prompt-to-dashboard.md는 프롬프트 생성·반응형 블록 편집·게시·복제·소스 교체를 목표로 한다. 다만 화면별 기능 확장과 미관 수정만으로 이 목표에 도달하지 않는다. 앞서 디자인 집중 계획의 첫 순위를 지표 탐색 툴바 정리로 잡은 것은 수정한다. **첫 기준 화면은 대화와 편집 가능한 결과물이 함께 있는 Dashboard Studio**로 삼는다. 탐색은 Studio를 지원하는 상세 분석 화면으로 유지한다.

차별화 가설은 ‘검증 가능한 지표를 사용하는 대시보드를 말로 만들고, 직접 배치하며, 다른 데이터에 재사용하는 가장 짧은 흐름’이다. 시장 차별화가 입증됐다는 뜻은 아니다. 일반 AI 생성기보다 출처·계산 일관성, 기존 BI보다 제작·배포 흐름의 간결함으로 고객 검증한다.

## 사용자 개념과 내부 모델

사용자가 Source → Measure → Dimension → Widget 화면을 순서대로 완수해야 하는 구조는 피한다. 결과를 만들면서 필요한 개념을 점진적으로 보여준다.

| 내부 개념 | 사용자 표현 | 첫 흐름 |
| --- | --- | --- |
| Source | 내 데이터 | 파일·API·DB 연결 또는 샘플. 기간·열 타입·행 수·갱신/오류 상태를 요약 |
| Measure | 지표 | 매출, 환불액, 순매출, 환불률 등을 AI가 제안. 단위·집계·분모·중복 기준과 출처를 검토 가능 |
| Dimension | 나눠 볼 기준 | 날짜·상품·채널 등. 열 분류부터 시작하고 파생 정의는 필요할 때 추가 |
| Block | 블록 | 지표+추세, 차트, 표, 설명, 필터. 지표/차원을 참조하며 안정적인 ID와 배치를 가짐 |
| Dashboard | 대시보드 | 같은 정의를 AI와 직접 편집이 수정하는 결과물 |
| Publication / Template | 공유 버전 / 내 데이터로 사용 | 게시 결과와 편집 초안을 분리. 복제 시 열·지표·차원 매핑을 확인 |

자동 생성은 같은 이름의 계산식을 중복 생성하는 방식이 아니다. 기존 ID·버전을 재사용하고 업무 의미가 다를 때만 새 정의를 제안한다. ‘환불률’처럼 분모가 답을 바꾸면 확인하되, 차트 색 변경처럼 명확한 요청에 형식적인 확인을 추가하지 않는다.

## 목표 화면

### 첫 화면

상단에 ‘데이터를 연결하고 원하는 대시보드를 설명해 주세요’ 입력을 둔다. 입력 가까이에 파일 연결·기존 데이터 선택·매출/환불 샘플을 배치한다. 데이터 준비 후 같은 흐름에서 지표와 분류 제안을 간단히 확인한다. 첫 결과를 보기 위해 지표 관리 화면으로 이동하지 않는다.

### Dashboard Studio

- 상단: 제목, 초안/저장/게시 상태, 되돌리기·다시하기, 미리보기, 공유. 색이 강한 주요 액션은 최소화한다.
- 중앙: 실제 결과 캔버스. 선택 테두리·드래그 핸들·resize affordance는 편집 중 명확하게 보이고 읽기 상태에서는 정돈한다.
- 우측: 하나의 패널에 ‘AI’와 선택 블록의 ‘설정’ 탭. 대화 내용·선택·미저장 변경을 탭 이동으로 잃지 않는다. 왼쪽 데이터/지표 목록은 필요할 때 여는 보조 영역으로 두어 상시 4열 화면을 피한다.
- 선택 블록: 지표/차원/표현/크기·위치·복제를 같은 문맥에서 수정한다. AI에 ‘이 블록’ 문맥을 전달한다.
- 생성 중: 데이터 확인 → 지표 결정 → 계산 검증 → 블록 배치 상태와 부분 실패를 보여준다. 실패한 단계만 재시도하고 이미 만든 결과를 보존한다.
- 좁은 화면: 캔버스를 중심으로 AI·설정을 drawer/sheet로 연다. 이동 버튼·순서 변경·크기 preset으로 drag 외 경로를 제공한다. desktop/tablet/mobile 배치를 따로 보존한다.

자유 배치는 현재의 grid snap 자유도를 우선 유지한다. 겹침 없는 조정과 반응형 읽기 순서를 보장하는 것이 첫 목표다. 임의 절대좌표와 요소 겹침까지 지원하는 Figma급 캔버스는 별도의 요구다.

### 게시·재사용

‘저장’은 초안 보관, ‘게시’는 수신자에게 보여줄 버전 확정이다. 첫 단계는 기간·필터·기준 시점이 있는 집계 snapshot을 제안하며 live 모드는 별도 표시·검증한다. 이는 VM 제안이지 Claude의 정책과 같다는 뜻이 아니다.

공유 화면에 접근 범위·기준 시점·갱신 상태·공유 중지를 표시한다. 공개 가능한 결과와 원본 데이터 접근권은 구분한다. ‘내 데이터로 사용’은 정의·배치를 복제하고 새 소스의 열·지표·차원을 매핑한다. 원본 소유자의 인증·공개 설정을 복사하지 않는다. 같은 화면 URL을 만들 수 있는 제품 게시와 운영 인프라/커스텀 도메인 배포는 구분한다.

## 현재 구현과 격차 — 코드 확인

- Source, DuckDB worker, 저장 지표와 분석 compiler, AI 생성/preview/save, 공유 링크, Widget/grid 기반은 재사용한다.
- `DashboardAssistant.tsx`는 단순 읽기 전용이 아니다. mode 기반 수정 제안, 명시 적용, revision 경합, 이전 정의 되돌리기를 지원한다. 하지만 생성·수정·게시·복제가 하나의 대화 실행 흐름으로 통합됐다는 증거는 없다. 이전 architecture 문서의 ‘읽기 전용’ 요약은 현재 코드보다 오래됐다.
- 안정적 blockId와 AI 선택 수정의 배치 보존은 기반이 있다. 통합 block CRUD·undo/redo 전체와 breakpoint별 편집 완료로 확대하지 않는다.
- `DashboardModify/index.tsx`는 1390px 고정 폭과 `layouts={{ lg: layout }}`를 사용한다. 반응형 읽기와 반응형 편집은 별개이며 후자를 보완해야 한다.
- 기존 `DashboardShare`는 token/on-off/endDate 중심이다. 게시 revision·집계 snapshot·재게시/복제 매핑을 완료로 간주하지 않는다.
- 프런트엔드 src의 MUI 직접 import 파일은 160개(테스트 포함)다. 전체 교체는 버튼만의 수정이 아니며 폼·메뉴·날짜 선택·portal·테마·테스트까지 영향을 준다.

## MUI vs shadcn 결정

**지금은 MUI 유지, Studio 디자인을 먼저 고정한다. 전면 전환은 하지 않는다.** MUI는 [테마/컴포넌트 설정](https://mui.com/material-ui/customization/theming/)으로 색·글꼴·간격·형태를 바꿀 수 있다. 공식 최신 문서의 신규 API를 현재 설치 버전 7.x에 그대로 적용한다는 뜻은 아니다.

shadcn은 [컴포넌트 소스 배포·수정](https://ui.shadcn.com/docs)을 제공해 제품 고유 UI에 유리하다. 대신 소스 변경본·스타일 토큰·upstream 변경 반영을 팀이 관리해야 한다. AI가 소스를 읽기 쉽다는 특성은 대시보드의 계산·생성·게시 정확성을 보장하지 않는다.

레이아웃 엔진·시각화·UI 컴포넌트를 분리해서 판단한다. 기존 [react-grid-layout](https://github.com/react-grid-layout/react-grid-layout)은 이동·resize·breakpoint 배치를 담당한다. [shadcn Resizable](https://ui.shadcn.com/docs/components/resizable)은 패널 크기 조절이며 이를 대체하지 않는다. 공식 최신 RGL v2 예제를 설치된 v1의 API로 복사하지 않는다.

전환 재평가 조건: 같은 Studio 시안/상태를 MUI로 구현했을 때 반복적인 구조 우회가 필요한지, 새 컴포넌트 소유권의 이익이 이관·접근성·폼/날짜/portal 재검증 부담보다 큰지 확인한다. 비교가 필요해지면 독립 prototype에서 대표 화면 한 개를 비교하고 결정한다. 그 전에는 생산 화면에 두 체계를 혼합하지 않는다. 화면별 편의에 따른 임의 혼합은 또 다른 불일치를 만든다. MUI/shadcn 어느 쪽도 앱 합성 후의 접근성을 자동 보장하지 않는다.

## 수정된 다음 순서와 종료 조건

1. **Studio 기준 시안**: 첫 입력, 생성된 캔버스, 선택 블록 설정, 게시 미리보기의 4개 상태를 1440/768/390px로 설계. 기존 단일 블루 강조와 중립 표면을 기본안으로 하되 레퍼런스별 근거를 붙인다. 컴포넌트 수치 이전에 영역·액션 위계를 고정한다.
2. **기존 엔진으로 편집 연결(P1)**: 동일 정의에 add/remove/duplicate/move/resize, undo/redo, breakpoint별 저장/재조회. AI 수정 후 수동 배치와 비대상 블록이 유지돼야 한다.
3. **통합 생성·수정(P2/P3)**: 파일/기존 소스로 지표·차원을 제안하고 기존 지표를 재사용. 한 대화에서 선택 블록 수정과 오류 복구까지 연결한다.
4. **게시·재사용(P4/P5)**: 초안/게시 버전 분리, 다른 계정 조회, 공유 중지, 복제 후 소스 교체와 원본 불변을 검증한다.

대표 수용 흐름: 주문·환불 데이터 연결 → ‘매출·환불·채널별 현황을 만들어 줘’ → 제안 계산 검토 → 블록 이동/resize → ‘이 차트만 주간으로’ → 저장/재조회 → 명시한 범위 게시 → 다른 계정 조회 → 내 데이터로 복제. 같은 fixture 수치, 키보드 이동, 폭별 레이아웃, 원본 불변을 확인한다.

의미 없는 모든 테스트 반복은 피한다. 설계만 바꾸는 이번 검토에는 전체 테스트·LLM 호출·화면 PASS가 없다. 기존 gpt-6-luna와 VoiceOver BLOCKED는 유지한다. 이 문서는 전면 UI 프레임워크 교체 승인이나 전체 구현 완료 선언이 아니다.
