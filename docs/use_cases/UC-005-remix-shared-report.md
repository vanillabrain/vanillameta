# 유스케이스: 공유 리포트 리믹스

## 개요

**유스케이스 ID:** UC-005
**유스케이스명:** Remix Shared Report
**주 액터:** 수신자
**목표:** 원본을 건드리지 않고 공유 리포트의 독립적인 편집 가능 사본을 자신의 작업공간에 얻는다
**시작 이벤트:** 수신자가 공유 리포트의 리믹스를 요청한다
**상태:** Draft

**Requirements:** [FR-005, FR-013, NFR-007, C-004](../requirements.md)

## 사전 조건

- 수신자가 공유 링크를 보유한다
- 공유된 리포트가 존재한다

## 주 성공 시나리오

1. 수신자가 공유 리포트의 리믹스를 요청한다.
2. 시스템이 링크가 활성이고 만료되지 않았는지, 수신자가 로그인했는지, 링크가 리믹스를 허용하는지 확인한다.
3. 시스템이 복사 커밋 직전에 링크와 리믹스 허용을 다시 확인하고 정의를 복사한다 — 스냅샷 링크면 그 판본의 원본 리비전(sourceRevisionId)의 구조·레이아웃·옵션을 새 리비전의 definition에, 캡처된 동결 위젯 결과 행만 materializedResults에 담는다. 라이브 링크면 원본의 현재 리비전 정의만 새 리비전으로 만들고 행은 복사하지 않는다 — 허가되지 않은 데이터는 복사하지 않는다.
4. 시스템이 사본의 출처 — 원본 리포트, 원본 리비전(스냅샷 링크면 그 판본과 원본 리비전), 사용된 공유 링크 — 를 기록한다.
5. 수신자가 새 사본을 소유자로서 열고 자유롭게 편집할 수 있다.

## 대안 흐름

### A1: 수신자 미로그인

**트리거:** 수신자가 로그인 계정이 없다 (2단계)
**흐름:**

1. 시스템이 로그인 또는 가입을 요청한다.
2. 수신자가 로그인한다.
3. 2단계에서 계속.
4. 수신자가 로그인을 포기하면 유스케이스 종료.

### A2: 링크 비활성 또는 리믹스 불가

**트리거:** 링크가 비활성·만료됐거나 리믹스를 허용하지 않는다 (2단계)
**흐름:**

1. 시스템이 이 리포트는 리믹스할 수 없음을 알린다.
2. 유스케이스 종료.

### A3: 수신자가 접근 불가한 데이터셋

**트리거:** 사본의 데이터셋 바인딩이 수신자가 사용할 수 없는 데이터 소스를 가리킨다 (3단계)
**흐름:**

1. 시스템이 해당 바인딩을 연결 해제된 상태로 복사한다 — 동결 결과는 3단계에서 이미 materializedResults로 복사됐으므로 다시 복사하지 않는다.
2. 시스템이 해당 바인딩을 수신자가 자기 데이터 소스에 다시 연결하도록 표시한다.
3. 4단계에서 계속.

### A4: 커밋 시점에 링크 무효

**트리거:** 3단계의 재확인에서 링크가 철회·만료됐거나 리믹스 허용이 취소됐다 (3단계)
**흐름:**

1. 시스템이 복사를 거부하고 사본을 만들지 않는다 — 부분 사본은 남지 않는다.
2. 유스케이스 종료.

## 사후 조건

### 성공 사후 조건

- 출처가 기록된 독립적인 리포트 사본이 수신자의 작업공간에 존재한다
- 원본 리포트, 리비전, 스냅샷, 공유 링크는 변하지 않는다

### 실패 사후 조건

- 사본이 생성되지 않는다
- 리믹스 시도로 원본 리포트가 수정되는 일은 없다

## 비즈니스 규칙

### BR-001: 리믹스는 공개 범위를 넓히지 않는다

리비전의 원본 데이터 상속 표시는 상속된 결과와 바인딩이 모두 수신자 소유
데이터로 교체될 때까지 이후 리비전에도 유지된다. 상속 표시가 남아 있는
사본은 새 공유 링크를 발행할 수 없다 — 단, 상속 데이터의 원본 링크가
캡처 시점에 Public이었던 경우 Public 뷰어 스냅샷 링크만 허용된다. 발행
요청 시 시스템이 현재 리비전의 상속 표시를 검사해 이를 강제한다 — 비공개
원본이 리믹스만으로 공유 가능한 사본이 되지는 않는다.

### BR-002: 계보는 기록된다

모든 리믹스 사본은 원본 리포트, 원본 리비전 또는 스냅샷 판본, 사용된 공유
링크를 기록해, 파생 작업의 출처와 공유 범위 추적이 가능해야 한다.
