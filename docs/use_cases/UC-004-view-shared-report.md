# 유스케이스: 공유 리포트 열람

## 개요

**유스케이스 ID:** UC-004  
**유스케이스명:** View Shared Report  
**주 액터:** 수신자  
**목표:** 공유 링크가 부여한 리포트를 본다 — 라이브 에디션은 최신 데이터, 스냅샷 에디션은 동결 데이터로  
**시작 이벤트:** 수신자가 공유 링크를 연다  
**상태:** Draft

**Requirements:** [FR-001, FR-003, FR-011, NFR-001, NFR-005, NFR-007, C-004](../requirements.md)

## 사전 조건

- 수신자가 리포트에 발급된 공유 링크를 보유한다

## 주 성공 시나리오

1. 수신자가 공유 링크를 연다.
2. 시스템이 링크가 활성 상태이고 만료되지 않았으며 수신자가 공개 범위 요건을 충족하는지 확인한다 — 로그인 수신자에게는 링크와 수신자를 잇는 공유 그랜트를 기록한다.
3. 시스템이 링크에 고정된 에디션을 렌더링한다 — 라이브 에디션은 최신 데이터, 스냅샷 에디션은 저장된 결과.
4. 수신자가 리포트의 제목, 위젯, 데이터가 반영된 시점을 본다.

## 대안 흐름

### A1: 링크 만료 또는 철회

**트리거:** 링크가 만료됐거나 철회됐다 (2단계)  
**흐름:**

1. 시스템이 링크를 더 이상 사용할 수 없음을 알린다.
2. 유스케이스 종료.

### A2: 미인증 수신자의 Authenticated 링크

**트리거:** 로그인하지 않은 수신자가 공개 범위가 Authenticated인 링크(신규 또는 이전된 레거시)를 연다 (2단계)
**흐름:**

1. 시스템이 어떤 리포트 데이터도 보여주지 않고 로그인을 요청한다.
2. 수신자가 로그인하면 2단계에서 계속 — 접근이 허용되면 공유 그랜트가 기록된다.
3. 수신자가 로그인을 거절하면 유스케이스 종료 — 어떤 데이터도 노출되지 않는다.

### A3: 라이브 데이터 소스 장애

**트리거:** 라이브 에디션이 최신 데이터를 조회하지 못한다 (3단계)  
**흐름:**

1. 시스템이 최신 데이터를 사용할 수 없음을 알린다.
2. 수신자가 같은 리포트의 스냅샷에 대한 별도의 유효한 접근 권한(다른 활성 링크 또는 공유 그랜트)을 보유한 경우에만 시스템이 그 저장 에디션을 대신 제안한다.
3. 수신자가 수락하면 시스템이 저장 에디션을 렌더링하고 4단계에서 계속.
4. 그런 권한이 없거나 수신자가 거절하면 시스템이 조회 실패를 표시하고 유스케이스 종료 — 스냅샷 데이터는 노출되지 않는다.

### A4: 에디터 링크 수신자

**트리거:** 링크가 에디터 역할을 부여한다 (4단계)  
**흐름:**

1. 시스템이 렌더링된 리포트 위에 편집 기능을 추가로 표시한다.
2. 수신자는 편집으로 이어갈 수 있다(UC-006 참조).
3. 4단계에서 계속.

## 사후 조건

### 성공 사후 조건

- 수신자가 링크의 에디션과 역할이 허용하는 범위 안에서 리포트를 본다
- 스냅샷 에디션은 저장된 결과만으로 렌더링된다

### 실패 사후 조건

- 어떤 리포트 데이터도 노출되지 않는다
- 리포트와 버전들은 변하지 않는다

## 비즈니스 규칙

### BR-001: 신선도는 링크가 결정

라이브 에디션은 조회 시각을, 스냅샷 에디션은 캡처 시각을 보여준다. 수신자는
표시된 데이터가 어느 순간의 것인지 항상 알 수 있다.

### BR-002: 잘림은 뷰어에 표시된다

캡처 한계로 잘린 위젯은 렌더링된 에디션에서 잘림을 시각적으로 표시한다 —
수신자는 데이터가 일부라는 것을 구별할 수 있다.

### BR-003: 레거시 링크는 로그인이 필요하다

이전된 활성 레거시 익명 라이브 링크는 같은 URL과 라이브 콘텐츠를 유지하지만
로그인을 요구한다 — 미인증 수신자는 거부 대신 로그인을 요청받는다.
만료·철회된 링크는 부활하지 않는다.
