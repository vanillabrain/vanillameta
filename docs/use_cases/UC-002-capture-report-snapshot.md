# 유스케이스: 리포트 스냅샷 캡처

## 개요

**유스케이스 ID:** UC-002
**유스케이스명:** Capture Report Snapshot
**주 액터:** 리포트 작성자
**목표:** 리포트의 현재 리비전 시점에 데이터 결과, 차트 옵션, 레이아웃을 동결한 불변 스냅샷 판본을 만든다
**시작 이벤트:** 리포트 작성자가 리포트의 스냅샷 캡처를 요청한다
**상태:** Draft

**Requirements:** [FR-002, FR-014, NFR-004, NFR-009](../requirements.md)

## 사전 조건

- 리포트 작성자가 로그인한 상태다
- 리포트가 존재한다

## 주 성공 시나리오

1. 작성자가 리포트의 스냅샷 캡처를 요청한다.
2. 시스템이 각 위젯의 데이터를 데이터 소스에서 한 번씩 조회한다.
3. 시스템이 조회된 결과, 차트 옵션, 레이아웃과 캡처 시점의 현재 리비전 참조를 새 스냅샷 판본으로 저장한다.
4. 시스템이 새 판본을 캡처 시각과 함께 스냅샷 이력에 표시한다.

## 대안 흐름

### A1: 일부 위젯 조회 실패

**트리거:** 하나 이상의 위젯이 데이터를 조회하지 못하지만 적어도 하나는 성공한다 (2단계)
**흐름:**

1. 시스템이 실패한 각 위젯에 오류 표시를 스냅샷에 기록한다.
2. 시스템이 나머지 위젯의 캡처를 완료한다.
3. 시스템이 실패한 위젯을 작성자에게 알린다.
4. 3단계에서 계속.

### A2: 위젯당 저장 한계 초과

**트리거:** 위젯의 조회 결과가 위젯당 저장 한계를 넘는다 (3단계)
**흐름:**

1. 시스템이 초과분을 한계까지 잘라내고 해당 위젯에 잘림을 기록한 뒤 저장을 완료한다.
2. 4단계에서 계속.

### A3: 총량 저장 한계 초과

**트리거:** 직렬화된 스냅샷 전체가 총량 저장 한계를 넘는다 (3단계)
**흐름:**

1. 시스템이 캡처를 거부하고 용량 초과를 알린다 — 스냅샷은 저장되지 않는다.
2. 유스케이스 종료.

### A4: 리포트에 위젯이 없음

**트리거:** 리포트에 위젯이 하나도 없다 (2단계)
**흐름:**

1. 시스템이 빈 리포트는 캡처할 수 없음을 알린다.
2. 유스케이스 종료.

### A5: 모든 위젯 캡처 실패

**트리거:** 모든 위젯이 데이터를 조회하지 못한다 (2단계)
**흐름:**

1. 시스템이 캡처를 중단하고 실패 사유를 알린다 — 스냅샷은 저장되지 않는다.
2. 유스케이스 종료.

## 사후 조건

### 성공 사후 조건

- 저장된 결과, 차트 옵션, 레이아웃과 원본 리비전 참조를 담은 새 스냅샷 판본이 존재한다
- 스냅샷은 불변이며 독립적으로 공유 가능하다
- 스냅샷에 데이터 소스 자격 증명이나 접속 정보가 저장되지 않는다

### 실패 사후 조건

- 스냅샷이 생성되지 않는다
- 이전 버전들과 리포트는 변하지 않는다

## 비즈니스 규칙

### BR-001: 스냅샷은 불변

한번 저장된 스냅샷의 내용은 절대 바뀌지 않는다. 갱신된 데이터는 리비전
번호와 독립된 새 판본 번호를 가진 새 캡처로만 반영된다.

### BR-002: 스냅샷은 비밀을 담지 않는다

스냅샷은 결과 행과 표현 옵션만 저장한다 — 데이터 소스 자격 증명, 접속
문자열, 비밀이 포함된 쿼리문은 절대 저장하지 않는다.
