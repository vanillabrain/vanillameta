# 유스케이스: 리포트 버전 복원

## 개요

**유스케이스 ID:** UC-009
**유스케이스명:** Restore Report Version
**주 액터:** 리포트 작성자
**목표:** 리포트의 현재 상태를 선택한 과거 리비전의 정의로 되돌리되 그 사이의 이력은 잃지 않는다
**시작 이벤트:** 리포트 작성자가 리포트 버전의 복원을 요청한다
**상태:** Draft

**Requirements:** [FR-007](../requirements.md)

## 사전 조건

- 리포트 작성자가 로그인하고 리포트를 소유한다
- 리포트에 과거 리비전이 하나 이상 있다

## 주 성공 시나리오

1. 작성자가 리포트의 버전 이력을 연다.
2. 시스템이 생성 시각과 출처가 표시된 리비전 목록을 보여준다 — 스냅샷 판본은 그 원본 리비전으로 탐색된다.
3. 작성자가 리비전을 선택해 미리 본다.
4. 작성자가 복원을 확정한다.
5. 시스템이 선택된 리비전의 정의를 담은 새 리비전을 만들어 현재 리비전으로 지정하고 모든 이력을 보존한다.

## 대안 흐름

### A1: 미리보기에서 취소

**트리거:** 작성자가 선택한 리비전의 복원을 포기한다 (4단계)
**흐름:**

1. 시스템이 대기 중인 복원을 버린다.
2. 유스케이스 종료.

### A2: 바인딩이 변경됨

**트리거:** 선택된 리비전의 데이터셋 바인딩이 현재 사용 가능한 데이터셋과 맞지 않는다 (4단계)
**흐름:**

1. 시스템이 복원으로 깨질 바인딩을 경고한다.
2. 작성자가 확정하면 복원이 진행되고 영향받는 위젯이 재연결 필요로 표시된다.
3. 작성자가 취소하면 유스케이스 종료.

## 사후 조건

### 성공 사후 조건

- 리포트의 현재 상태가 선택된 리비전의 저장된 구조와 바인딩과 같다
- 직전 현재 리비전을 포함한 모든 리비전과 스냅샷이 이력에 남는다
- 특정 판본에 고정된 스냅샷 공유 링크는 여전히 그 판본을 서빙한다

### 실패 사후 조건

- 리포트의 현재 상태는 변하지 않는다
- 어떤 리비전이나 스냅샷도 삭제되거나 변경되지 않는다

## 비즈니스 규칙

### BR-001: 복원은 이력을 다시 쓰지 않는다

복원은 과거 리비전의 정의를 담은 새 현재 리비전을 만들 뿐 기존 리비전이나
스냅샷을 삭제하거나 덮어쓰지 않는다 — 복원된 상태 자체가 최신 리비전이
된다.
