# 유스케이스: 공유 접근 관리

## 개요

**유스케이스 ID:** UC-010
**유스케이스명:** Manage Share Access
**주 액터:** 리포트 작성자
**목표:** 리포트의 공유 링크를 검토·연장·교체·철회해 접근 권한을 작성자 통제 아래 둔다
**시작 이벤트:** 리포트 작성자가 리포트의 공유 관리를 연다
**상태:** Draft

**Requirements:** [FR-008, NFR-007](../requirements.md)

## 사전 조건

- 리포트 작성자가 로그인하고 리포트를 소유한다
- 리포트에 공유 링크가 하나 이상 있다

## 주 성공 시나리오

1. 작성자가 리포트의 공유 관리를 연다.
2. 시스템이 각 링크의 에디션, 역할, 공개 범위, 만료일, 상태를 목록으로 보여준다.
3. 작성자가 링크를 선택하고 작업 — 만료일 변경, 교체, 철회 — 을 고른다.
4. 작성자가 링크 철회를 선택해 확정한다.
5. 시스템이 링크와 그에 바인딩된 모든 스코프 접근과 공유 그랜트를 비활성화한다.
6. 링크가 즉시 접근 부여를 멈춘다.

## 대안 흐름

### A1: 만료일 연장 또는 단축

**트리거:** 작성자가 활성이고 만료되지 않은 링크의 만료일 변경을 선택한다 (3단계)
**흐름:**

1. 시스템이 새 만료일을 적용한다 — 링크의 나머지 권한과 상태는 그대로 유지된다.
2. 유스케이스 종료 — 철회 흐름으로 이어지지 않는다.

### A2: 링크 교체

**트리거:** 작성자가 3단계에서 교체를 선택해 같은 권한의 새 URL을 원한다 (3단계)
**흐름:**

1. 시스템이 기존 링크를 비활성화한다 — 기존 URL과 그 스코프 접근·공유 그랜트는 즉시 무효가 된다.
2. 시스템이 동일한 에디션, 역할, 공개 범위, 리믹스 허용, 만료일과 — 스냅샷 에디션이면 — 같은 고정 판본을 가진 새 링크를 발급한다.
3. 시스템이 새 링크를 작성자에게 반환한다 — 새 링크의 스코프 접근과 공유 그랜트는 자동으로 발급되지 않고 수신자가 다시 획득한다.
4. 유스케이스 종료.

### A3: 모든 링크 철회

**트리거:** 작성자가 리포트의 모든 공유 링크를 철회한다 (3단계)
**흐름:**

1. 시스템이 확인을 요청하고 영향받는 링크를 나열한다.
2. 작성자가 확정하면 시스템이 모든 링크와 스코프 접근·공유 그랜트를 비활성화한다.
3. 6단계에서 계속.

### A4: 만료일이 유효하지 않음

**트리거:** 작성자가 만료일 변경을 선택한 뒤 과거 날짜나 형식에 맞지 않는 값을 입력한다 (3단계)
**흐름:**

1. 시스템이 날짜를 거부하고 요구 조건을 설명한다 — 어떤 링크도 변경되지 않는다.
2. 유스케이스 종료.

## 사후 조건

### 성공 사후 조건

- 철회 시: 선택된 링크(또는 모든 링크)가 더 이상 접근을 부여하지 않고 그 스코프 접근과 공유 그랜트도 무효가 된다
- 만료일 변경 시: 링크의 만료일만 갱신되고 나머지 권한과 상태는 그대로다
- 교체 시: 기존 링크는 비활성이고 동일 권한(고정 판본 포함)의 새 링크가 활성이다
- 선택되지 않은 나머지 링크는 권한이 그대로 유지된다
- 리포트와 버전들은 변하지 않는다

### 실패 사후 조건

- 모든 링크가 이전 상태를 유지한다 — 부분적인 철회는 일어나지 않는다

## 비즈니스 규칙

### BR-001: 철회는 즉각적이고 완전하다

철회된 링크는 도구와 캐시된 세션을 포함한 이후의 모든 접근을 거부한다 —
유예 기간은 없다.

### BR-002: 철회는 회수가 아니다

링크 철회는 미래의 접근만 차단한다 — 링크가 유효했던 동안 수신자가 보거나
복사한 것을 지우지는 못한다.
