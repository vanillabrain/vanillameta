# 유스케이스: 스냅샷 에디션 발행

## 개요

**유스케이스 ID:** UC-003  
**유스케이스명:** Publish Snapshot Edition  
**주 액터:** 리포트 작성자  
**목표:** 데이터 소스를 건드리지 않고 선택한 동결 버전을 서빙하는 공유 링크를 발행한다  
**시작 이벤트:** 리포트 작성자가 리포트를 스냅샷 에디션으로 공유하기를 요청한다  
**상태:** Draft

**Requirements:** [FR-003, FR-004, FR-014, NFR-001, NFR-005, C-004](../requirements.md)

## 사전 조건

- 리포트 작성자가 로그인한 상태다
- 리포트가 존재한다

## 주 성공 시나리오

1. 작성자가 리포트의 공유 설정을 연다.
2. 작성자가 스냅샷 에디션을 선택한다.
3. 시스템이 리포트의 스냅샷 버전 목록을 보여준다.
4. 작성자가 판본(기본: 최신), 공개 범위(Public 또는 Authenticated), 리믹스 허용 여부, 선택적 만료일을 고른다 — 스냅샷 에디션의 역할은 항상 뷰어다.
5. 시스템이 선택된 판본에 고정된 공유 링크를 발급한다.
6. 작성자가 링크를 복사해 수신자에게 전달한다.

## 대안 흐름

### A1: 스냅샷이 없음

**트리거:** 리포트에 스냅샷 버전이 없다 (3단계)  
**흐름:**

1. 시스템이 스냅샷이 필요함을 알리고 캡처를 제안한다.
2. 작성자가 거절하면 유스케이스 종료.
3. 작성자가 수락하면 시스템이 스냅샷 캡처를 수행한다(UC-002 참조).
4. 캡처가 성공하면 3단계에서 계속 — 캡처가 실패하면 시스템이 사유를 알리고 유스케이스 종료.

### A2: 만료일이 유효하지 않음

**트리거:** 작성자가 과거 날짜를 만료일로 입력한다 (4단계)  
**흐름:**

1. 시스템이 날짜를 거부하고 요구 조건을 설명한다.
2. 작성자가 만료일을 수정하거나 지운다.
3. 5단계에서 계속.

## 사후 조건

### 성공 사후 조건

- 특정 스냅샷 판본에 고정된 활성 공유 링크가 존재한다
- 링크를 열면 저장된 결과만 렌더링하고 데이터 소스에는 전혀 접근하지 않는다
- 공개 범위가 Public인 링크는 익명 접근을 허용한다 — Public은 스냅샷 에디션의 뷰어 역할에만 가능하다

### 실패 사후 조건

- 공유 링크가 생성되거나 변경되지 않는다
- 기존 공유 링크와 스냅샷 버전은 변하지 않는다

## 비즈니스 규칙

### BR-001: 익명 접근은 스냅샷뿐

공개 범위가 Public인 링크는 스냅샷 에디션의 뷰어 역할에만 허용되고
로그인 없이 열 수 있다. 그 외 모든 권한 — 에디터, 라이브 에디션,
Authenticated — 은 식별된 수신자를 요구한다.

### BR-002: 링크는 하나의 판본에 영구 고정

각 스냅샷 링크는 발급 시 선택된 정확히 하나의 판본을 영구히 서빙한다 —
발급 후 재지정되지 않는다. 더 새로운 판본을 공유하려면 새 링크를 발급한다 —
서빙 중인 에디션이 독자 아래서 바뀌는 일은 없다.
