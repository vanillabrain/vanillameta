# VanillaMeta 프로젝트 분석 보고서

## 📊 프로젝트 개요

**VanillaMeta**는 최신 엔터프라이즈용 비즈니스 인텔리전스(BI) 웹 애플리케이션으로, 데이터 탐색적 분석 및 시각화 솔루션을 제공합니다.

### 주요 특징

- 코딩 없이 차트 위젯 제작 가능
- 50개 이상의 다양한 차트 타입 지원
- 사용자 맞춤형 대시보드 편집 및 공유
- 10종 이상의 데이터베이스 연결 지원

## 🛠️ 기술 스택

### Backend (backend-api/)

- **프레임워크**: NestJS (Node.js)
- **ORM**: TypeORM
- **쿼리 빌더**: Knex.js (다중 DB 연결용)
- **인증**: Passport.js (JWT, Local Strategy)
- **API 문서화**: Swagger
- **배포**: AWS Lambda + Serverless Framework
- **데이터베이스**:
  - 개발: SQLite
  - 프로덕션: MySQL

### Frontend (frontend-web/)

- **프레임워크**: React 18 (Create React App + Craco)
- **UI 라이브러리**: Material-UI (MUI)
- **상태 관리**: React Context API
- **차트 라이브러리**: ECharts, ECharts-GL
- **스타일링**: Emotion, Styled Components
- **라우팅**: React Router v6
- **배포**: AWS S3 + CloudFront (Serverless)

### 지원 데이터베이스

- PostgreSQL, MariaDB, MySQL, SQL Server
- SQLite, Oracle, Amazon Redshift
- BigQuery, CockroachDB, Snowflake

## 🏗️ 백엔드 아키텍처 상세 분석

### 1. 모듈 구조

백엔드는 NestJS의 모듈 시스템을 활용한 도메인 중심 설계:

- **DatabaseModule**: 데이터 소스 관리
- **DatasetModule**: 데이터셋 생성 및 관리
- **WidgetModule**: 위젯(차트) 생성 및 관리
- **DashboardModule**: 대시보드 관리
- **TemplateModule**: 템플릿 시스템
- **ComponentModule**: 컴포넌트 관리
- **ConnectionModule**: 다중 데이터베이스 연결 관리
- **AuthModule**: 인증 처리
- **UserModule**: 사용자 관리
- **LoginModule**: 로그인 처리
- **ShareUrlModule**: 공유 URL 관리

### 2. 데이터베이스 연결 관리

#### TypeORM 설정

- 환경별 데이터베이스 타입 분기 처리
- 개발 환경에서는 SQLite, 프로덕션에서는 MySQL 사용

#### 다중 데이터베이스 지원 (ConnectionService)

- Knex.js를 사용한 동적 데이터베이스 연결
- 연결 풀 관리: `Map<number, Knex>` 구조로 연결 캐싱
- 각 데이터베이스 타입별 커스텀 dialect 구현

### 3. 인증 시스템

#### JWT 기반 인증

- **Access Token**: 6시간 유효 (21600초)
- **Refresh Token**: 12시간 유효 (43200초)
- Refresh Token은 데이터베이스에 저장하여 관리
- Passport.js의 JWT Strategy와 Local Strategy 활용

### 4. 주요 아키텍처 패턴

- **Repository 패턴**: TypeORM Repository를 통한 데이터 접근
- **Service-Controller 분리**: 비즈니스 로직과 HTTP 레이어 분리
- **DTO 패턴**: 요청/응답 데이터 검증 및 변환
- **BaseEntity 상속**: 공통 필드 관리 (id, createdAt, updatedAt)

### 5. 특별 기능

#### 동적 쿼리 실행

- 사용자가 직접 SQL 쿼리 작성 및 실행 가능
- 각 데이터베이스 타입별 결과 파싱 로직 구현
- 필드 타입 자동 감지 기능 (FieldTypeUtil)

## 🎨 프론트엔드 아키텍처 상세 분석

### 1. React 애플리케이션 구조

#### Provider 계층 구조

```
HelmetProvider (SEO)
└── LayoutProvider (레이아웃 상태)
    └── LoadingProvider (로딩 상태)
        └── BrowserRouter (라우팅)
            └── AuthProvider (인증 상태)
                └── ThemeProvider (MUI 테마)
                    └── AlertProvider (알림)
                        └── App
```

### 2. 상태 관리 전략

Context API 기반의 도메인별 상태 관리:

- **AuthContext**: 사용자 인증 상태
- **LoadingContext**: 전역 로딩 상태
- **AlertContext**: 알림 시스템
- **LayoutContext**: UI 레이아웃 상태

### 3. 라우팅 구조

- Protected Routes로 인증이 필요한 페이지 보호
- 중첩 라우팅으로 계층적 페이지 구조 구현
- 주요 경로: /dashboard/_, /widget/_, /data/_, /share/_

### 4. API 서비스 레이어

- 도메인별 서비스 파일 분리
- Axios 인터셉터로 자동 토큰 관리
- 토큰 만료 시 자동 갱신 메커니즘

### 5. 위젯/차트 시스템

3계층 구조:

1. **modules/**: 실제 차트 컴포넌트
2. **settings/**: 차트별 설정 UI
3. **wrapper/**: 데이터 연결 및 상태 관리

동적 차트 렌더링을 위한 룩업 테이블 방식 사용

## 🔍 프로젝트 현황 평가

### 강점

1. **잘 구조화된 아키텍처**: 모듈화되고 확장 가능한 구조
2. **다양한 데이터베이스 지원**: 엔터프라이즈 환경에 적합
3. **풍부한 시각화 옵션**: 50개 이상의 차트 타입
4. **기본적인 보안 구현**: JWT 인증, CORS 설정

### 개선이 필요한 영역

1. **TypeScript 일관성**: 프론트엔드 JS/TS 혼재
2. **테스트 커버리지**: 단위/통합 테스트 부족
3. **성능 최적화**: 대용량 데이터 처리 고려 필요
4. **보안 강화**: 추가적인 보안 레이어 필요
5. **개발자 경험**: 문서화 및 개발 도구 개선 필요

## 🚀 개선 제안 사항

### 1. 단기 개선 사항 (1-2주)

#### 코드 품질

- TypeScript 전환 (프론트엔드 JS 파일)
- ESLint/Prettier 규칙 강화
- 코드 리뷰 프로세스 도입

#### 테스트

- 핵심 비즈니스 로직 단위 테스트
- 주요 사용자 플로우 E2E 테스트
- 테스트 커버리지 목표 설정 (80%)

#### 보안

- SQL Injection 방지 코드 검토
- 입력 값 검증 강화
- API Rate Limiting 구현

### 2. 중기 개선 사항 (1-2개월)

#### 성능 최적화

- 쿼리 최적화 및 인덱싱
- 프론트엔드 번들 최적화
- 캐싱 전략 수립 (Redis 도입 검토)

#### 개발자 경험

- Docker 환경 개선
- CI/CD 파이프라인 구축
- 개발 문서 보강

#### 모니터링

- APM 도구 도입 (예: Datadog, New Relic)
- 구조화된 로깅 시스템
- 에러 트래킹 (예: Sentry)

### 3. 장기 개선 사항 (3-6개월)

#### 기능 확장

- 실시간 대시보드 (WebSocket)
- 협업 기능 (동시 편집)
- 데이터 파이프라인 기능

#### 아키텍처 개선

- 마이크로서비스 전환 검토
- 이벤트 기반 아키텍처 도입
- GraphQL API 도입 검토

## 📝 결론

VanillaMeta는 잘 설계된 BI 플랫폼으로, 기본적인 기능들이 안정적으로 구현되어 있습니다. 그러나 엔터프라이즈 환경에서의 확장성과 유지보수성을 높이기 위해서는 위에서 제안한 개선 사항들을 단계적으로 적용할 필요가 있습니다.

특히 TypeScript 전환, 테스트 커버리지 향상, 보안 강화는 즉시 착수해야 할 우선순위가 높은 작업들입니다. 이러한 개선을 통해 더욱 안정적이고 확장 가능한 플랫폼으로 발전할 수 있을 것입니다.
