# UC-005 구현 계획과 검증 매핑

이 문서는 최초 목표/단계 계획과 후속 이력을 보존한다. 최신 전체 여정 실행은 맨 아래 UC023 통합 증빙을 따른다. 최상위 순서는 P1→P2→P3→P4→P5이며 [제품 계약](../strategy/prompt-to-dashboard.md)을 따른다.

| 단계/BR               | 코드 경계                                                                         | 검증 / 종료 조건                                                                                          |
| --------------------- | --------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| P1 / BR-003           | dashboard-draft, ai-dashboard.save, bi.compileEditor, DashboardModify/readLayouts | 안정적 ID adapter·기존 데이터 호환 → 직접 이동/resize 후 AI 수정·reload에서 비대상 불변.390/768/1440 편집 |
| P2 / BR-002           | source profile, Metric.definition, BI compiler, AI draft                          | explicit Dimension 정의, 지표 재사용/신규 정의 공동 저장·rollback. 계산/분모 독립 정답                    |

각 단계 시작 전 기존 API/테스트와 버전 계약을 확인해 좁은 하위 UC/TC를 작성한다. DB migration/새 의존성은 확정된 코드 부족점이 있을 때만 검토하며 일괄 선행 작업으로 추가하지 않는다.

검증: BE 관련 npm test 및 build, FE 관련 vitest/tsc/eslint, 기능 완료 시 사용자 지정 Ego 실제 화면/XHR·캡처, 통합 시 핵심 E2E와 TC-005. 기존 skills/vanillameta-verify와 UI Kit를 적용한다. 기능/디자인/승인/운영 배포는 별도 기록한다.

문서 설정 검증은 strict spec lint 및 pin/check, 링크/의미 대조만 실행한다. 새 기능·TC-005 runtime은 미실행이다. 관련 변경 없는 기존170BE/41FE 결과를 새 목표 완료 근거로 재집계하지 않는다.

P1 첫 단위 UC-006의 안정적 ID/선택 AI 수정/배치 보존·표시 검증은 [실행 기록](../testing/block-layout-continuity.md)을 따른다. 전체 TC-005는 계속 not_run이며 다음은 P1 모바일 편집·블록 작업·undo다.

## P3/P4 질문 연결 — UC-019

[질문 저장→게시 준비 설계](../architecture/prompt-publication.md)와 [실행 증거](../testing/prompt-publication.md)에 따라 명시 저장+게시 질문을 같은 저장 revision의 게시 미리보기로 연결한다. 링크 공개는 별도 버튼으로 실행한다. 실제 Ego 질문·저장·미리보기·링크 게시·새로고침, 게시 부정 질문의 저장만 실행, 버전 불일치 차단과 폭별 UI를 확인했다. 임시 분석 12는 원복하고 게시를 중지했다. 계정 수신자·생성 화면 질문·전체 P3/P4/TC005 수용은 Open이다. 다음 범위는 P4/P5 복제·소스 교체·재사용의 부족점 확인이다.

## P5 소유 대시보드 재사용 — UC-020

[설계](../architecture/dashboard-reuse.md)·[실행 증거](../testing/dashboard-reuse.md): 소유 저장본의 복제→다른 DuckDB 파일 소스/열 연결→전체 미리보기→원자 저장→새로고침을 구현했다. 원본·지표·게시 상태를 유지하고 새 대시보드/블록 ID·비공개 복사본을 생성한다. Ego 분석12→23, 새 소스 oracle·동일 요청 재확인·390/768/1440 크기/정렬을 검증했다. 공유 수신자 remix·질문 복제·운영 DB·실휴대폰·전체 P5/TC005는 Open이다. 다음은 공유/게시본을 통한 재사용 범위와 권한 경계를 좁게 설계하는 작업이다.

## P5 공유·게시 재사용 — UC-021

[설계](../architecture/shared-dashboard-reuse.md)·[검증](../testing/shared-dashboard-reuse.md): 소유자 opt-in과 로그인 수신자의 내 소스 연결/전체 미리보기/원자 저장을 추가했다. 공유 현재본·게시 고정본, 원본 권한 비복사·링크 중지/버전 guard·동일 요청 영수증을 확인했다. Ego 두 계정 복사본25/26→reload와390/768/1440을 검증하고 임시 링크를 중지했다. 운영/실기기·질문 remix·전체P5/TC005는 Open이다. 다음은 복사본 AI 편집→게시를 포함한 전체 제품 여정의 부족점을 점검한다.

## P3/P4/P5 복사본 AI 편집·재게시 — UC-022

[설계](../architecture/copy-ai-publication.md)·[검증](../testing/copy-ai-publication.md): 수신자 복사본26/source27의 저장 지표 링크 없는 계산을 실제 AI 질문으로2배 수정하고 전체 미리보기→명시 저장/게시 준비→버전1→제목 AI 변경/저장→같은 링크 버전2 재게시→소유/익명 새로고침을 확인했다. 원본23·다른 복사본25·비대상/ID/폭별 배치는 유지됐고 임시 링크는 중지했다. 신규 제품 코드 없이 통합 회귀를 추가했다. 실제 타 계정 GET403/익명401·서버 변경 거절 회귀와 UI 대표 폭을 확인했으며, 타 계정 변경 POST 실제 실행은 자동 승인 검토 거절로 NOT_RUN이다. 운영/실기기·모든 AI식 게시 복구·전체TC005는 Open이다. 다음은 최신 UI에서 TC005 전체 여정과 남은 복구/권한 gate를 묶는 검증이다.

## TC005 통합·생성 연결 — UC023

[통합 실행 증빙](../testing/dashboard-lifecycle.md): 전체 canonical 파일과 새 수신자 계정으로 주 여정9단계·선택 오류를 묶었다. 생성 후 저장/게시 준비 질문을 기존 proposal/digest에 연결하는 공백을 먼저 AIWF 설계한 뒤 보완했다. 새 저장 revision과 영수증 재생 범위를 구분한다. 전체 단위/루트 빌드·격리 core8개와 Ego 실제 화면/폭별 UI를 검증했다. 제품 전체 수용·운영/실기기·모든 자연어/경합·타 계정 변경 POST 실제 실행은 별도 Open이다. 과거 not_run 이력은 최신 증빙을 덮어쓰지 않는다.
