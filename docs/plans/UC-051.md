# UC051 조직·직원 및 자원 권한

## 첫 단위: 조직·직원 수명주기

FR016·NFR005/007·UC051 BR01/02의 첫 단위다. 인증 계정은 기존 User를 사용한다. 한 계정은 한 조직에 소속되고 미소속 계정은 기존 개인 데이터 동작을 유지한다. 본인이 새 격리 조직을 만들면 그 조직의 admin이 되며 타 조직/데이터를 획득하지 않는다. 기존 가입 계정을 정확한 userId와 본인이 발급해 전달한 일회용 조직 연결 코드로 추가한다. ID만으로 등록하면 타인이 계정을 조직에 편입해 비활성화할 수 있으므로 금지한다. 디렉터리 전체 검색/초대 이메일/SSO·다중 조직/조직 이동은 후속이다. 역할은 첫 단위 admin/member이며 데이터 관리자/세부 자원 권한은 다음 단위로 분리한다.

## 모델·보안

EnterpriseOrganization(id,name,version), EnterpriseMembership(userId PK,organizationId,role,team), EnterpriseAuditEvent(id,organizationId,actorId,action,resourceId,version,createdAt)를 추가한다. EnterpriseEnrollment(userId PK,organizationId,codeHash,expiresAt)는 SHA256 해시만15분 유효하고 직원 등록 트랜잭션에서 단 한 번 소비한다. 재발급은 이전 코드를 무효화하며 소속 계정은 발급할 수 없다. 코드는 지정한 조직ID에 묶이며 그 조직의 관리자만 소비한다. 본인은 DELETE /enterprise/enrollment로 취소할 수 있다. 코드는 초대받을 조직을 확인한 뒤 직원 본인이 명시 전달하며 서버 로그/감사에는 남기지 않는다. User active(boolean default true)/authVersion(integer default0)를 더한다. 기존 데이터/계정의 소유권·토큰은 epoch0에서 호환한다. 명시 비활성/재활성 때 authVersion을 증가시켜 과거 access/refresh를 영구 거절하고 jwtId를 지운다. 로그인/refresh와 JWT guard는 현재 active/epoch를 검사한다. 이미 실행 중인 모든 장기 작업 취소는 이 단위의 보장이 아니다.

SQLite에서는 같은 DataSource의 조직 변경 요청을 큐로 직렬화하고 실패한 요청 뒤에도 계속 처리한다. 조직 생성/멤버 변경은 DB transaction·조직 version CAS와 감사 삽입으로 원자화한다. userId 전역 PK가 동시 중복 소속을 막는다. actor는 요청 JWT에서만 가져오고 현재 같은 조직의 active admin을 확인한다. 타 조직 계정 추가/변경 거절·자기 비활성/자기 역할 하향 거절, admin 요청도 stale version409/쓰기0이다. CAS는 동시 admin 상호 회수도 한 버전만 성공시킨다. 오류 메시지에 타 조직/비밀번호/토큰/이메일을 반환하지 않는다. 감사는 ID/동작/버전만 저장하며 원문/필드값·비밀은 비보관이다. 조직 역할은 이 첫 단위에서 소유 데이터 권한을 확장하지 않는다.

## HTTP 계약 (raw JSON)

- JWT 보호 `GET /enterprise/context`: `{organization:null,membership:null}` 또는 `{organization:{id,name,version},membership:{userId,role,team}}`.
- `POST /enterprise/organizations` `{name}`: 같은 context. 미소속 active 본인만 생성.
- `DELETE /enterprise/enrollment`: 본인의 미사용 코드를 명시 취소하고 `{revoked:true}`. 반복 요청도 같은 결과.
- admin `GET /enterprise/members?afterId=positiveInteger`: `{organizationVersion,entries:[{id,userId,team,role,active}],nextAfterId:number|null}`, ID오름차순20+1. 자신의 조직만 조회하고 민감한 User 필드는 select하지 않는다.
- 미소속 `POST /enterprise/enrollment` `{organizationId}`: 본인에게 `{enrollmentCode,expiresAt,organization:{id,name}}` 1회 반환. 자동 발급/원문 보관 없음.
- admin `POST /enterprise/members` `{userId,team,role,expectedVersion,enrollmentCode}`: 기존 정확한 계정을 추가하고 `{organizationVersion,member}` 반환. 계정 신규 발급은 아님.
- admin `PATCH /enterprise/members/:id` `{team,role,active,expectedVersion}`: 같은 응답. 요청 key/타입/길이/enum/version을 엄격 검증하고 부분쓰기 없음.

새 마이그레이션은 SQLite/MySQL용 추가 테이블/컬럼만 만들고 파괴적 down은 거절한다. 기존 개인 계정/리소스를 자동 조직 이전하지 않는다. resource grant는 다음 별도 단위이며 UC051/FR016 전체 수용을 이 첫 단위로 선언하지 않는다.

## UI·검증

`/organization`은 기존 보호 Layout·프로필 메뉴에서 진입한다. 미소속은 명시 조직 생성 또는 참여할 조직 번호 입력→본인 연결 코드 발급/조직 이름 확인→명시 전달·취소, member는 소속 안내만, admin은20개 페이지 직원목록/기존계정 추가·팀/역할/활성 변경이다. 변경 요약/명시 확인 후 전송하며 입력수정은 동의를 해제한다.409/통신 실패는 초안 보존·최신조회 안내, 권한거절은 목록 비노출, 자동 재전송/권한 승격은 없다. 긴 이름/좁은 폭 공통36px 입력/32px 도구·줄바꿈과 초점/상태를 확인한다. 실제 Ego 제어권 반환이 없으면 미실행으로 기록한다.

SQLite 실제 트랜잭션/CAS/감사/권한/동시소속/다른조직·자기잠금/비활성·epoch/migration을 검증한다. 기존 auth/guard·사용자 회귀와 FE 생성/수정/실패/재조회·type/lint/build·core8을 영향 범위로 실행한다. 실제 HTTP/조직 역할별 TC050/모바일/운영MySQL·실휴대폰은 별도 증거가 있어야 통과다.

계정 일반 삭제는 조직 소속이면409로 차단해 마지막 관리자/소속 고아 행을 만들지 않는다. 조직 탈퇴·이관은 후속 설계이며 자동 소속 제거를 하지 않는다. 잘못된 연결 코드는 계정 존재/소속 여부를 구별할 수 없는 동일400이며 코드/hash·조직·유효기한을 먼저 확인한 뒤 계정과 바인딩한다.
