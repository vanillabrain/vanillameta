# UC051 퇴사·탈퇴 전 영향 확인과 업무 인계

Status: Draft

## 목표

FR016/FR017/NFR005/NFR007·TC050 E02/E03 후속이다. 직원 개인 소유 자산을 조직 소유로 오해해 자동 삭제하거나 관리자에게 공개하지 않는다. 퇴사 처리, 조직 탈퇴, 계정 삭제, 업무 자료 인계는 별개의 명시 동작으로 설계한다.

## 전체 인계 계약과 단계

1. 현재 조직 admin이 같은 조직 직원의 자료·관계 건수를 읽기 전용으로 확인한다. 이번 구현 단위다.
2. 소유자/조직의 업무 자료 선택과 수신자 수락, 소스·지표·대시보드 의존성 및 파일 보관 주체를 고정한다. 개인 자료를 자동 인계하지 않는다. 독립 복제로 충분한 업무와 소유권 이전이 필요한 업무를 구분하며 이 단계는 후속 설계·구현이다.
3. 최종 인계는 최신 계정/조직/소유/자료 버전·수신자 수락을 재검사한다. 참조와 게시·출력·영수증의 과거 actor를 소급 변경하지 않는다. 불완전 의존성·다중 소유·충돌이면 쓰기 없이 중단한다.
4. 탈퇴/퇴사 확정은 인계와 분리해 세션 epoch 및 직접/그룹/전달 관계를 회수하고 지속 영수증으로 재시도를 확인한다. 원본과 독립 사본은 보존한다. 단순 비활성화는 탈퇴 완료가 아니며 재활성화가 종전 권한을 자동 부활시키지 않도록 별도 계약이 필요하다.
5. 계정 삭제는 탈퇴·자료 보존 의무/인계 정리가 완료되기 전 기존409 보호를 유지한다. 조직 자동 삭제, 소유권 일괄 이전, 파일 자동 정리는 하지 않는다.

## 이번 읽기 전용 단위

`GET /enterprise/members/:id/departure-impact`: 현재 활성·JWT epoch가 맞는 admin만 같은 조직의 직원(비활성 포함)을 확인한다. 자기 조회도 읽기만 허용한다. 소스/대시보드의 내용 접근권을 부여하지 않는다. 응답은 organizationId/organizationVersion/targetId/targetActive/observedAt 및 아래 고정11종 counts뿐이다. 이름·SQL·열·원본 경로·토큰·질문·파일·게시 링크·상대 계정 목록은 반환하지 않는다.

| key                  | 계산 기준                                                                                                        |
| -------------------- | ---------------------------------------------------------------------------------------------------------------- |
| sources              | Database.ownerId=직원인 전체 소스 행, 비활성 포함                                                                |
| metrics              | 위 소스에 연결된 전체 Metric 행, 비활성 포함                                                                     |
| soleDashboards       | 존재하는 Dashboard에 연결된 전체 UserMapping이 정확히1행이고 그 계정이 직원인 대시보드 수, 삭제 표시/비활성 포함 |
| ambiguousDashboards  | 직원 mapping이 있고 전체 mapping이2행 이상인 존재하는 대시보드 수. 동일 계정 중복도 포함, 자동 인계 불가         |
| directGrants         | 현재 조직에서 ownerId 또는 recipientId=직원인 저장 grant 행, 회수된 행 포함                                      |
| personalDeliveries   | 현재 조직에서 ownerId 또는 recipientId=직원인 저장 개인 전달 행, 회수 포함                                       |
| groupMemberships     | 현재 조직의 존재하는 그룹에 대한 직원 가입 행, 비활성 그룹 포함                                                  |
| ownedGroupGrants     | 현재 조직에서 직원이 소유자인 저장 그룹 grant 행, 회수 포함                                                      |
| ownedGroupDeliveries | 현재 조직에서 직원이 소유자인 저장 그룹 전달 행, 회수 포함                                                       |

| exportJobs           | 현재 조직에서 ownerId 또는 sourceOwnerId=직원인 전체 출력 작업 행. 중복 합산 없이 종료 상태 포함                 |

개인 자산은 조직 귀속 열이 없으므로 전체 계정 소유 건수이며 조직 소유 목록이 아니다. 지표/게시/출력은 다른 건수와 겹칠 수 있어 총합을 표시하지 않는다. 관계 건수는 현재 유효 접근권이 아니다. 고아 mapping·소스 없는 지표·개인 저장 보기·기존 DashboardPublication/DashboardShare·별도 BI 조직/정책·외부 원본·파일 크기/전역 사용처는 이번 집계에 포함되지 않는다. 전체 인계 영향 분석으로 표현하지 않는다.

SQLite 공통 metadata 큐, MySQL REPEATABLE READ transaction으로 건수의 동일 snapshot을 얻는다. snapshot 후 최신 계정/소속/조직 기준을 다시 읽어 actor epoch/활성/admin·대상 소속/활성/역할/팀·조직 버전 변경을 거절한다. 이 응답은 실행 가능한 승인 기준이 아니며 자료 변경·새 탭 동작을 동결하지 않는다. 확정 작업은 반드시 별도 최신 검토가 필요하다. 조회는 audit 포함 쓰기0이다.

## 화면·검증·종료

직원 관리의 접힌 ‘퇴사·인계 전 확인’에서 명시 직원 선택→조회→재조회한다. 열기/선택/접기/조직 reload는 자동 요청하지 않으며 오래된 성공 응답·실패 후 이전 건수를 숨긴다. 요청 도중 대상/조직 변경과 unmount는 늦은 응답을 버린다. 관리자 이외에는 표시하지 않는다. 기본36px/도구32px·입력 모바일16px/큰 화면14px 및 줄바꿈/정렬을 기존 UI Kit로 유지한다.

서비스/보호 HTTP와 FE 테스트로 권한·격리·비밀 비노출·중복/비활성·실패/늦은 응답·쓰기0을 확인하고 실제 Docker MySQL에서 같은 집계를 검증한다. type/lint/build, 독립 검토, AIWF 문서 동기화 후 현재 브랜치 commit/push한다. 실제 Ego/실휴대폰/운영/전체 인계·전체16개 수용은 실행한 증빙과 분리한다.
