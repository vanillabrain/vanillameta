# UC046 — 다른 탭 변경 후 Studio 보관 초안 병합

Status: Draft · P1/P3 · TC-005 중단 후 편집 · UC045 후속.

## 목표와 규칙

같은 로그인/탭/대시보드에서 보관한 블록 초안을 다른 탭의 저장 뒤에도 복구한다. 현재 편집을 덮지 않으며 자동 저장/게시/AI 실행은 없다. 기존 소스 버전이 같을 때만 지원한다.

- BR1: 새 보관 형식 v2에 SQL 없는 saved baseline을 포함하고 전체24h/256KiB를 유지한다. 기존 v1 기록은 같은 revision 복구만 지원하고 기준 없는 병합을 추측하지 않는다.
- BR2: revision이 다르면 명시 최신본 조회→기준/초안/최신본의3방향 비교→전체 병합 미리보기다. 비대상 최신 변경은 유지한다. 질문은 UC043 별도 보관이다.
- BR3: 제목/설명/표시 항목·공통 필터/기간·폭별 블록 좌표는 실제 로컬 변경만 반영한다. 양쪽의 같은 항목 변경은 원문 비교와 명시 '충돌 항목에 내 초안 사용' 동의를 요구한다. 기본 선택 없음.
- BR4: 원격 삭제/정의 교체로 적용할 수 없는 로컬 수정·소스 버전 변경·6블록 초과·배치 겹침/경계 오류는 보존형 차단이다. 좌표를 조용히 바꾸거나 블록을 생략하지 않는다.
- BR5: GET/미리보기 실패·새409·대기 중 새 편집/경로 이탈은 기록과 현재 편집을 유지한다.409는 최신본 재조회/재비교를 요구한다. 성공하면 최신본을 saved baseline으로, 검증된 병합을 dirty 문서로 seed한다. 이후 명시 저장/reload에서 기록을 정리한다.

## 변경과 검증

storage helper/테스트(v2호환/손상/한도), 순수3방향 병합/회귀(비대상/동일항목/구조/배치), Editor 비교 안내/선택/지연응답 회귀를 구현한다. 기존409 편집 재적용은 변경하지 않는다. 새 의존성/범용 프레임워크는 도입하지 않는다.

Ego 한 공간에서46/source34 두 탭: 첫 탭 제목·복제/배치·질문 보관→둘째 탭 같은 제목+비대상 제목 저장→첫 탭reload→최신본 확인/충돌 명시 선택→전체 미리보기→저장/reload를 검증한다. 원본45 불변·비대상 보존·390/768/1440 크기/정렬을 확인하고46 변경은 정상 UI로 원복한다. 관련 FE·type/lint/build와 실제 요청/문서 대조·AIWF 검사 후 commit/push한다. 게시·실기기/운영·모든 구조 병합은 별도다.

## A3 실제 장애·재충돌 후속 — 2026-10-17

같은46/source34와 Ego 한 공간 두 탭을 사용한다. 첫 탭 초안·질문을 보관하고 둘째 탭 저장 후 reload한다. 명시 비교의 GET 한 건만 별도4901 fault endpoint로 보내503을 반환한다(기존4899 proxy/서버는 교체·종료하지 않는다). 같은 보관 기록/질문과 DB 무변경을 확인하고 정상 비교로 재시도한다. 동의 후 둘째 탭이 다시 저장한 상태에서 실제 preview409를 받는다. 기록/질문 보존·동의 초기화·자동 쓰기0을 확인한 뒤 최신 재조회/재동의→preview201→save201→reload를 수행한다. 비대상 최신 제목·모든 폭 배치·10%/300을 대조하고 원본45 보존·46 정상 원복을 확인한다.390/768/1440 오류/충돌/완료 상태 크기·정렬을 확인한다. 새 제품 코드가 필요하지 않으면 검증·회귀·문서만 변경하고 기존 빌드 증빙을 재사용한다.
