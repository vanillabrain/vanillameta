# UC047 — Studio 저장 응답 유실 후 새로고침 복구

Status: Draft · P3/FR009 · TC005 중단 후 편집 지원.

## 계약

- BR1: 네트워크 저장 전 동일 로그인/탭/대시보드의 문서 초안(v2)과 정확한 requestId/expectedRevision/expectedSourceRevision/document를 보관한다. 기존 auth scope를 재사용하고 요청·초안 합계256KiB/24h이며 SQL/catalog/결과/토큰은 넣지 않는다. 보관 실패 시 전송하지 않고 현재 편집을 유지한다.
- BR2: reload 후 권한 GET이 성공한 다음 미확인 저장을 우선 표시한다. 자동 POST/AI/게시0. 확인 전 편집/새 저장 ID 생성을 막는다. 버튼은 같은 요청을 명시 재확인하며 미전달이면 저장을 완료할 수 있음을 안내한다. 기존 영수증 replay 계약을 사용한다.
- BR3: 성공 영수증을 옛 최신본으로 적용하지 않는다. 확인된 상태를 보관하고 최신 GET→정리→현재 저장본으로 진입한다. 최신 조회 실패면 요청 보존·재시도는 GET만 한다. 저장확정/최신조회를 게시 승인으로 사용하지 않는다.
- BR4: 서버409 거절은 기록을 유지하며 명시 '보관 초안으로 돌아가기'를 제공한다. 전송 중 해제/새 요청으로 중복 저장하지 않는다. 다른 인증/대시보드·손상/만료는 연결하지 않는다. 요청 대기 중 이탈/늦은 결과가 다른 화면을 덮지 않게 한다.

## 구현/검증

보관 helper+회귀·별도 확인 화면+API 회귀를 추가하고 기존 Editor 저장/초기 권한 조회에 연결한다. 기존 BE receipt/CAS를 그대로 사용하며 새 BE DB/의존성은 도입하지 않는다. 기존 저장 재시도 취소는 결과 확인 화면으로 연결해 미확인 요청을 덮지 않는다.

Ego 한 공간의46/source34에서 제목/복제·질문→저장 commit 뒤503 응답 치환→reload/자동POST0→동일 요청 명시 확인/기존 영수증→최신GET→키정리/저장본reload를 확인한다. 미전달503도 같은 요청 최초저장으로 이어지는지 선택 검증한다. 원본45 불변·46 내용 원복·영수증/새블록 증가와390/768/1440 크기·정렬을 대조한다. 관련 FE/type/lint/build·AIWF 검사와 증빙 후 commit/push. 모든 장애/운영/실기기/제품 전체 수용은 별도다.

## 신규 블록 ID 복구 후속

임시 ID의 복제 블록과 모든 폭 배치를 포함해 저장하고 commit 후 응답만503으로 치환한다. reload 후 자동 POST0, 명시 동일 요청의 임시 ID/requestId 보존, 영수증 idMap의 같은 서버 ID, 최신 GET의 블록4개/배치 일치, 영수증·revision 추가 증가0을 확인한다. 질문 보존과390/768/1440 정렬을 확인한 뒤 추가 블록만 정상 편집으로 제거해 원복한다. 원본45·게시 상태는 불변이어야 한다. 임시 ID 회귀를 추가하며 제품 코드 변경이 없으면 직전 build 증빙을 재사용한다.

## 저장 확정 후 조회 실패/reload 후속

저장 응답 유실→reload/명시 동일 요청 확인은 서버201을 반환하고, 바로 뒤 최신 GET 한 건만503으로 치환한다. confirmed 기록·질문·문서 보존을 확인한 뒤 reload의 권한 GET 성공 후에도 명시 조회만 제공해야 한다. 버튼 실행은 GET만이며 영수증·블록·revision 추가 증가0, 질문 복구·원본45 불변·46 정상 원복을 대조한다.390/768/1440에서 오류/확정/편집 화면을 확인한다. confirmed 안내도 실제 동작처럼 저장 재실행 없이 최신 조회만 설명한다. 재마운트 confirmed 회귀와 해당 UI 문구 회귀를 추가하고 작은 제품 변경에 필요한 FE/type/lint/build를 실행한다.
