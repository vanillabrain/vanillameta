# develop → main 기능 보존 통합

2026-10-20 · VERIFIED (로컬 명시 범위). 사용자 선택: main 고유 기능도 보존하며 충돌 해결·기능 이식·검증한다. main `552b06f8`과 develop `b0239e8b`의 양쪽 이력을 유지하는 일반 merge이며 단일 브랜치 tree로 덮어쓰지 않는다. 원격 반영 전 검증을 완료한다.

## 통합 기준

- develop의 현재 인증 epoch/소유권·소스/대시보드 독립 권한·회수·Studio/AI·DuckDB·반응형/shadcn UI를 유지한다.
- main의 캐시/Redis·대시보드 캐시, 배치·장시간 작업/큐, 성능/DB 최적화·제한시간, 로그/관측, 이용 분석, 스트리밍/가상 표·지연 로딩·서비스 워커와 언어 UI를 보존한다. 파일 존재·빌드만으로 실행 기능 보존을 선언하지 않는다.
- 인증·소유권 경계를 통과하기 전에 legacy 캐시·큐가 SQL/원본을 반환하지 않는다. 조직 권한을 legacy owner ID로 대체하지 않는다. 관리/진단 엔드포인트를 무인증으로 새로 노출하지 않는다.
- Redis 등 외부 의존성이 없는 기존 로컬 실행을 보존하고 필요한 기능의 선택 구성·실패 상태를 분명히 한다. 실제 Redis 검증과 fallback/mock 검증을 구분한다.
- backend는 main 모듈의 Nest10/Bull/cache-manager/schedule 계열을 맞추고 develop의 TS5.9/native DuckDB·파일 업로드/보안 패치·migration 계약을 유지한다. frontend는 최신 Vite/Vitest/Studio를 기본으로 하고 기존 컴포넌트의 의존성을 함께 유지한다.
- 실제 사용자의 DB·업로드·Aside/Ego 프로필을 정리하지 않는다. 검증 자원은 새 소유 fixture만 사용한다. 기업 식별 원문·비밀·경로를 새 공개 변경에 추가하지 않는다.

## 실행 순서

1. 140개 충돌을 config/백엔드/프런트엔드로 분리하고 main-only 파일과 기능 목록을 대조한다.
2. 패키지/lock·핵심 모듈/호출부를 통합하며 빌드의 실제 오류를 수정한다. 서로의 수정 범위를 침범하지 않는다.
3. 독립 리뷰·관련 회귀·실제 로컬 앱/필요 서비스 검증을 수행하고 실패·미실행을 구분해 증빙한다.
4. 기능 보존 대조표와 테스트 결과·남은 운영 gate를 문서화한다. 양쪽 커밋 부모·미추적 사용자 파일 보존을 확인한 뒤 merge commit/push하고 원격 SHA를 재확인한다.

증빙은 Git 제외 `.aiwf/evidence/main-preserving-merge/`에 보존한다. 운영 배포·고객 수용은 이 Git 통합과 별개다. Redis/외부 서비스 미검증이나 기능 연결 공백을 성공으로 치환하지 않는다.

## 실제 MySQL에서 확인한 테이블 충돌 보완

전체 entity glob이 활성 여부와 무관하게 두 종류의 `job_results` 및 `analytics_events`를 같은 물리 테이블로 합쳐 작업 결과 저장이 실패했다. 기존 공유 테이블을 변경/삭제하지 않는 추가 방식으로 네 계열을 분리한다.

- `background_job_results`, `queued_job_results`, `analytics_collected_events`, `client_analytics_events`를 서로 다른 매핑으로 사용한다. 비활성 JobQueue를 새로 실행하지 않는다.
- 별도 migration은 식별 가능한 부모·필수 값·자료형을 만족하는 과거 행만 같은 ID로 복사한다. 기존 대상 ID는 덮어쓰지 않는다. 원본 공유 테이블·모호한 행은 보존해 별도 검토 대상으로 남긴다.
- 되돌리기가 새 이력을 지우지 않도록 자동 drop/down을 차단한다. 기존 운영 DB의 적용은 별도 보존 검토·실행 gate이며 이 QA는 새 소유 DB에서만 수행한다.
- 실제 MySQL의 별도 임시 schema에서 원본 hash·유효/모호 이력·재실행을 검증하고, 전체 Nest/MySQL/Redis의 새 작업/이벤트 수집을 다시 확인한다.

최종 검증 결과와 미실행/경고는 [증빙](../testing/main-preserving-integration.md)을 따른다. 이 상태는 운영 migration·배포·전체 16개 수용 완료를 의미하지 않는다.
