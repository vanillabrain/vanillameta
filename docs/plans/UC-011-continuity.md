# UC-007/008/011 — 연속 편집 회귀

P1 / FR-009·010. 이미 구현한 복제·직접 편집·내용 AI·배치 AI의 연결을 새 비공개 Rill fixture에서 검증한다. 기능을 더 추가하지 않고 확인된 결함만 최소 수정한다.

시나리오: OS 차트·요청 수·평균 Bid Floor 3블록으로 시작 → 요청 수 복제 → 복사본 제목 직접 편집 → 같은 복사본 내용 AI로 소수 자릿수 변경 → 배치 AI로 desktop y=30 지정(다른 블록과 겹치지 않음) → undo/redo → 미리보기→저장→브라우저 새로고침. 원본 분석18, 원본 요청 수·평균·OS, 다른 화면 폭·수치·계산식·저장 ID 연속성을 대조한다. 요청 중 UI 비활성·대표 모바일 컨트롤과 KPI/추세도 확인한다.

UC-007/008/011의 기존 BR과 TC를 재사용하며 새 업무 목표/DB/의존성은 없다. 실패하면 최초 증거·원인·수정·같은 경로 재검증을 기록한다. 기존 단위 통과는 코드/환경 불변 범위에서 재사용하고 변경이 있으면 관련 검사만 다시 실행한다. 포인터·터치·익명 공유·다중 블록 자동 의도 분류는 이 시나리오가 증명하지 않는다. 증빙과 다음 작업을 기록하고 commit/push한다.

내용 AI는 소수1자리·기존 제목/SQL/종류/축약 표시 유지로 고정한다. Rill과의 전체 기간 KPI 비교는 기존635M/$5.57 증빙을 재사용한다. 소수1자리 복사본은634.5M으로 표시되며 정확한 값634513000은 동일해야 한다. 제목·레이아웃·표시만 변경하는 테스트를 계산식 변경 완료로 해석하지 않는다.
