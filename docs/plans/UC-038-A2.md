# UC038 A2 repeated publication conflict verification

Status: Draft. P4/FR009·011/NFR003·004. [UC038](../use_cases/UC-038-publication-conflict.md#alternative-flows) · [TC038](../test_cases/TC-038-publication-conflict.md).

## Goal and stop condition

활성 게시본이 있는 상태에서 첫409→최신 저장본 확인→다른 탭의 추가 저장→게시 직전 두 번째409→최신본 확인→명시 재게시/reload/중지를 Ego에서 확인한다. 두409는 실제 서버 CAS이며 자동 갱신/쓰기나 기존 게시본 변경이 없어야 한다. 공개 합성 source32/원본39/저장45만 사용하고 검증 제목을 복원한다.

## Changes and validation

1. 기존 계약을 유지하고 계획/TC에 A2 실행을 연결한 뒤 strict/pin한다. 새 UC/요구사항/엔티티를 추가하지 않는다.
2. 활성 게시본·기존 URL/버전·설정이 두409 동안 보존되고 새 revision에서도 명시 동작 전 게시0인 컴포넌트 회귀를 추가한다. 실패를 발견하면 해당 최소 구현만 수정한다.
3. Ego 하나에서 활성 게시1→예전 영수증409→최신 R0 조회→별도 탭 제목 저장R1→최신 화면의409→더 최신R1 조회/미리보기→같은 URL 재게시2→익명/reload→중지/제목 원복을 확인한다.
4. 원본39 정의/게시 불변,45 정의/배치/수치와 복원 결과, 이전 두 창의 잠금,390/768/1440 크기·정렬을 확인한다.
5. 제품 구현이 바뀌지 않으면 기존 type/build/core 증빙을 재사용하고 변경 테스트의 실행/타입/린트를 수행한다. 실제 새 브라우저/UI 증빙은 이 실행으로 보완한다.
6. AGENTS/TC/기존 증빙·packet을 동기화하고 develop-v2 commit/push한다. 실휴대폰/운영MySQL/모든 경합/사람 수용은 별도다.
