# UC050 첫 구현: 소유 소스 업무 메타데이터

## 범위와 종료 조건

FR014/015·BR050-01/02의 첫 단위다. 기존 소유 DuckDB 소스에 표시명·설명과 실제 열별 표시명·설명·단위를 읽고 명시 저장한다. 원본 이름/유형·SQL·지표·대시보드는 변경하지 않는다. 조직 승인 카탈로그/관리자 역할/활성 상태/분류/날짜 형식 변경은 후속이다.

## 계약

- `POST /bi/source-catalog/read`: sourceId만 받으며 매번 기존 소유권을 검사한다. 실제 열 이름/타입만 반환하고 원본 행·연결정보는 반환하지 않는다.
- `POST /bi/source-catalog/save`: sourceId, sourceRevision, version, label, description, columns를 검증한다. sourceRevision은 실제 데이터 프로파일 버전이다. columns는 실제 전체 열과 일치하며 열 이름/타입은 수정할 수 없다. 표시명은 소스 안에서 정규화 후 중복 불가다.
- append-only `(sourceId, version)` 고유키로 저장하고 actorId·시각을 기록한다. 이전 version/바뀐 데이터는409·쓰기0이다. 새 저장 버전은 다시 읽을 수 있고 기존 분석에는 자동 전파하지 않는다.
- 기존 메타데이터와 실제 열 구조가 다르면 읽기는 차이를 알리고 저장은 차단한다. 구조 변경 재연결/영향 확인은 별도 설계한다.
- Explore의 접힌 업무 설명 편집기를 사용한다. 읽기 실패는 명시 재시도, 저장 실패는 입력 보존,409는 최신본 재조회 안내다. 재조회로 초안을 대체할 때 명시 동작이 필요하다.

## 변경 및 검증

BE source-catalog service/controller/entity·migration·BiModule/AppModule, FE SourceCatalogEditor/SourceExplore에 연결한다. SQLite 실DB 테스트로 권한·버전 경합·스키마/길이/중복 검증·쓰기 불변·이력과 migration을 확인한다. FE 테스트로 접기/읽기/수정/저장/재마운트·오류 보존·소스 전환을 검증한다. FE type/lint/build·BE build/lint와 strict 문서 검사를 실행한다. Ego 실제 화면은 기존 공간의 인증 상태에 따라 검증하며 차단은 BLOCKED로 남긴다. 실제 화면 미확인 상태를 디자인 PASS로 보고하지 않는다. 기업/고객 식별 문구·원본 경로를 공개 변경에 넣지 않는다.

## 후속 단위: 저장 이력·설명 비교

현재 저장 설명의 이력을 명시 조회하고 두 저장 버전의 소스/열 표시명·설명·단위를 비교한다. 원본 데이터·계산식·미저장 편집을 변경하거나 이전 버전을 복원하지 않는다. `history`는 소유권 검사 후 최신순20건·beforeVersion 커서로 읽으며 원본 행/연결정보/전체 metadata JSON을 반환하지 않는다. 손상 버전은 목록에 `unreadable`로 표시하고 다른 정상 버전의 조회를 막지 않는다. `compare`는 같은 소스의 양의 정수 fromVersion<toVersion만 허용하고 두 저장본을 명시 읽어 whitelist 차이만 반환한다. 버전0(미등록 기본값)은 비교 대상이 아니다. 삭제된/타인 소스는 기존 권한 검사로 거절한다. 실제 소스의 프로파일/행 조회는 이력 읽기에 필요하지 않다. 존재하지 않는 버전은404·손상된 선택 버전은409·쓰기0이다.

UI는 편집기 안의 별도 접힌 이력 영역을 사용한다. 저장 이력 없음/한 버전·두 버전·페이지 추가·오류/재시도·구조 변경/변경 없음과 소스 전환 늦은 응답을 확인한다. 버전 선택/오류는 현재 편집 입력을 바꾸지 않는다. 저장 후 이력 뷰는 새 버전 기준으로 초기화한다. 공통 small 버튼/입력·1열→2열 반응형 비교를 재사용하고 실제 UI는 사용자 제어 중인 Ego 공간 경계를 유지한다. 새 DB 스키마/의존성은 추가하지 않는다. 테스트는 실제 SQLite 이력·권한/잘못된 입력/페이지 고정 경계와 FE 요청/초안 보존을 검증한다. 전체 조직 승인/사용처 영향 검토와는 구분한다.
