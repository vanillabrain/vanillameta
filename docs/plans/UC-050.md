# UC050 첫 구현: 소유 소스 업무 메타데이터

## 범위와 종료 조건

FR014/015·BR050-01/02의 첫 단위다. 기존 소유 DuckDB 소스에 표시명·설명과 실제 열별 표시명·설명·단위를 읽고 명시 저장한다. 원본 이름/유형·SQL·지표·대시보드는 변경하지 않는다. 조직 승인 카탈로그/관리자 역할/활성 상태/분류/날짜 형식 변경은 후속이다.

## 계약

- `POST /bi/source-catalog/read`: sourceId만 받으며 매번 기존 소유권을 검사한다. 실제 열 이름/타입만 반환하고 원본 행·연결정보는 반환하지 않는다.
- `POST /bi/source-catalog/save`: sourceId, sourceRevision, version, label, description, columns를 검증한다. sourceRevision은 실제 데이터 프로파일 버전이다. columns는 실제 전체 열과 일치하며 열 이름/타입은 수정할 수 없다. 표시명은 소스 안에서 정규화 후 중복 불가다.
- append-only `(sourceId, version)` 고유키로 저장하고 actorId·시각을 기록한다. 이전 version/바뀐 데이터는409·쓰기0이다. 새 저장 버전은 다시 읽을 수 있고 기존 분석에는 자동 전파하지 않는다.
- 기존 메타데이터와 실제 열 구조가 다르면 읽기는 차이를 알리고 저장은 차단한다. 구조 변경 재연결/영향 확인은 별도 설계한다.
- Explore의 접힌 업무 설명 편집기를 사용한다. 읽기 실패는 명시 재시도, 저장 실패는 입력 보존,409는 최신본 재조회 안내다. 재조회로 초안을 대체할 때 명시 동작이 필요하다.

## 변경 및 검증

BE source-catalog service/controller/entity·migration·BiModule/AppModule, FE SourceCatalogEditor/SourceExplore에 연결한다. SQLite 실DB 테스트로 권한·버전 경합·스키마/길이/중복 검증·쓰기 불변·이력과 migration을 확인한다. FE 테스트로 접기/읽기/수정/저장/재마운트·오류 보존·소스 전환을 검증한다. FE type/lint/build·BE build/lint와 strict 문서 검사를 실행한다. Ego 실제 화면은 기존 공간의 인증 상태에 따라 검증하며 차단은 BLOCKED로 남긴다. 실제 화면 미확인 상태를 디자인 PASS로 보고하지 않는다. 기업/고객 식별 문구·원본 경로를 공개 변경에 넣지 않는다.

## 후속 단위: 저장 이력·설명 비교

현재 저장 설명의 이력을 명시 조회하고 두 저장 버전의 소스/열 표시명·설명·단위를 비교한다. 원본 데이터·계산식·미저장 편집을 변경하거나 이전 버전을 복원하지 않는다. `history`는 소유권 검사 후 최신순20건·beforeVersion 커서로 읽으며 원본 행/연결정보/전체 metadata JSON을 반환하지 않는다. 손상 버전은 목록에 `unreadable`로 표시하고 다른 정상 버전의 조회를 막지 않는다. `compare`는 같은 소스의 양의 정수 fromVersion<toVersion만 허용하고 두 저장본을 명시 읽어 whitelist 차이만 반환한다. 버전0(미등록 기본값)은 비교 대상이 아니다. 삭제된/타인 소스는 기존 권한 검사로 거절한다. 실제 소스의 프로파일/행 조회는 이력 읽기에 필요하지 않다. 존재하지 않는 버전은404·손상된 선택 버전은409·쓰기0이다.

UI는 편집기 안의 별도 접힌 이력 영역을 사용한다. 저장 이력 없음/한 버전·두 버전·페이지 추가·오류/재시도·구조 변경/변경 없음과 소스 전환 늦은 응답을 확인한다. 버전 선택/오류는 현재 편집 입력을 바꾸지 않는다. 저장 후 이력 뷰는 새 버전 기준으로 초기화한다. 공통 small 버튼/입력·1열→2열 반응형 비교를 재사용하고 실제 UI는 사용자 제어 중인 Ego 공간 경계를 유지한다. 새 DB 스키마/의존성은 추가하지 않는다. 테스트는 실제 SQLite 이력·권한/잘못된 입력/페이지 고정 경계와 FE 요청/초안 보존을 검증한다. 전체 조직 승인/사용처 영향 검토와는 구분한다.

## 후속 단위: 저장 전 업무 설명 미리보기

UC050 step4의 첫 범위로 변경 입력→서버 검증/정규화·필드 전후 비교→명시 확인→같은 내용 저장을 연결한다. 기존 분석/사용처 영향 계산이나 공식 승인은 포함하지 않는다. `POST /bi/source-catalog/preview`는 기존 save 입력 계약/권한·현재 데이터/설명 버전·실제 열·길이/중복 검증을 공유하며 쓰기0이다. 정규화된 draft와 현재 저장본(최초는 실제 소스/열의 기본 표시명) 대비 업무 필드 차이를 반환한다. 기존 save API는 호환성을 유지하며 미리보기 토큰/새 스키마는 추가하지 않는다.

UI는 미리보기 결과의 정확한 draft만 저장한다. 미리보기 후 입력 변경/최신본 재조회·실패/다른 소스로 전환하면 미리보기와 동의를 해제한다. 변경0건은 저장하지 않는다. 저장 직전 서버의 기존 CAS/데이터 버전 검사를 유지해 새 변경은409로 거절하고 입력은 보존한다. 저장 결과가 불명확하면 미리보기/동의를 해제하고 최신본 조회를 안내하며 자동 재저장하지 않는다. 이력 조회와 미리보기는 현재 입력을 덮지 않는다. 기존 이력의 변경 전후 카드 표현을 공유하고 narrow1열/wide2열·공통32px 도구/기본 입력 토큰을 따른다. 실제 UI는 Ego 제어권 경계를 유지하고 자동 검사와 구분한다.

BE: preview0쓰기·정규화·초기/저장본 차이·권한/입력/버전 거절 및 preview후 다른 저장/이전 save409를 SQLite로 검증한다. FE: 미리보기전/미동의 저장 불가·동의한 payload만 저장·입력수정 동의 해제·검증400/409/통신 실패 입력보존·변경0건·기존 재조회/이력 회귀를 확인한다. 공유 변경 카드 추출은 기존 이력 회귀로 기존 출력을 유지한다.

## 후속 단위: 소스의 저장 사용처 확인

업무 설명 변경 전 현재 소스에 직접 연결된 활성 지표와 본인 저장 분석을 읽기 전용으로 확인한다. 공식 변경 영향 계산/전파·일반 위젯 대시보드/게시/독립 사본의 간접 참조는 포함하지 않는다. `POST /bi/source-catalog/usage`는 sourceId/kind(metrics 또는 analyses)/선택 afterId(양의 정수)를 받으며 첫 요청은 afterId를 생략한다. 명시0은 거절한다. 매번 소스 소유권을 확인한다. 지표는 실제 databaseId/useYn=Y, 분석은 UserMapping·delYn=N·analysisDefinition.databaseId의 정확한 연결과 기존 dashboard 권한을 확인한다. 저장 정의/SQL·행·연결정보·다른 사용자 제목을 반환하지 않는다.

쿼리는 ID 오름차순20건+다음 후보1건으로 제한한다. 지표는 소스에 직접 제한하고, 분석은 본인 소유 저장 분석 후보20개에서 소스 연결·권한을 확인한다. 분석 다음 커서는 마지막 검사 후보 ID이며 빈 결과라도 다음 후보가 있을 수 있다. UI는 후보 구간을 전부 조회하기 전 사용처가 전혀 없다는 전체 판정을 하지 않는다. 미지원/손상 정의는 건너뛰고 예상하지 않은 저장소 오류는 실패로 반환한다. 수치/계산 변경 영향의 완전한 dependency graph가 아니다.

별도 접힌 사용처 영역에서 목록 종류/명시 조회/다음 후보/새로 조회를 제공한다. 분석 링크는 기존 저장 화면을 새 탭으로 열어 현재 초안/미리보기/동의를 보존한다. 종류·소스 전환 시 이전 응답은 무시한다. 공통 small 버튼/입력·좁은 화면 줄바꿈을 사용한다. 실제 Ego는 기존 사용자 제어 경계를 유지한다. 새 DB 스키마/의존성은 없다. SQLite+실제 SourceAccessService로 두 계정/소스/삭제·비활성/잘못된 정의·페이지 경계·조회 쓰기0을 검증하고 FE는 접힘·종류 변경/늦은 응답·빈 구간/다음 후보·새 탭/초안 보존을 확인한다.

## 후속 단위: Studio 생성에서 업무 설명 확인

FR014/015·BR050-02의 업무 의미 확인을 생성/재사용 공용 StudioSourcePicker에 연결한다. 선택한 profile이 있을 때 별도 접힌 읽기 전용 영역을 제공하고 명시 펼침/재조회에서 기존 `POST /bi/source-catalog/read`만 사용한다. 미등록 version0은 안내만 표시한다. 저장 버전/소스 표시명·설명과 원본 열명/형식/업무 표시명/설명/단위를 함께 보여준다. 설명을 질문/LLM에 자동 삽입하거나 지표/차원/차트 이름·원본을 변경하지 않는다.

응답의 sourceId/sourceRevision과 선택 profile.dataVersion·열 이름/형식을 대조한다. schemaChanged 또는 버전/열 불일치는 설명을 표시하지 않고 소스 새로 확인을 안내한다. 잘못된 응답/403/503은 이전 표시를 지우고 명시 재시도한다. 소스·profile 버전/열 변경은 접힘/새 요청 경계이며 늦은 응답을 무시한다. 접기 후 다시 열 때도 재조회한다. 질문/제안/미리보기 상태와 독립이며 조회 오류로 생성 버튼을 잠그지 않는다.

기존 small32px 도구와 본문14px/보조12px·좁은 화면 한 열, 긴 텍스트 줄바꿈을 사용한다. 신규 API/DB/의존성 없이 FE 컴포넌트와 공용 StudioSourcePicker에만 연결한다. 컴포넌트 검증은 명시 읽기/업무·원본 구분/미등록/버전·구조 불일치/오류·재시도/소스·profile 전환 늦은 응답·생성 입력 보존을 포함한다. 기존 StudioCreate/대화 생성 회귀와 FE type/lint/build를 실행한다. Ego는 이전 사용자 제어권 경계를 지키며 실제 화면/390·768·1440 실측 미실행을 PASS로 표시하지 않는다. 전체 카탈로그 승인·자동 분석 적용은 후속이다.

## 후속 단위: Studio 업무 이름으로 데이터 찾기

FR014/015·BR050-01의 소스 선택을 보완한다. 기존 `GET /bi/sources`는 기본 응답을 유지하고 명시 `catalog=1`에서만 소유 소스와 최신 source_catalog_entry를 결합해 안전한 catalogLabel/catalogVersion 요약을 추가한다. actor 검증/ownerId 조건은 서버가 적용한다. 최신 이력의 표시명이 정상 문자열(공백제외1~100자)일 때만 반환하고 미등록/손상 최신 이력은 원본 이름을 유지한다. 오래된 정상 버전으로 되돌려 표시하지 않는다. SQL/설명/열/연결정보/타인 제목은 응답하지 않으며 데이터 프로파일/원본 행을 읽지 않는다. 최신 버전 join은 한 쿼리로 제한해 전체 이력을 적재하거나 소스별 조회하지 않는다.

Studio fetchStudioSources만 catalog=1을 요청한다. 공용 선택기에 접힌 데이터 검색 입력을 제공해 NFKC/소문자/앞뒤 공백 정규화한 업무 이름·원본 이름·ID 부분 검색을 한다. 선택된 소스는 검색 불일치라도 선택기에 남기며 결과 개수와 구분한다. 옵션에는 업무 이름·원본 이름·ID를 함께 보여 동명이름을 구별하고 기존 미지원 엔진 비활성은 유지한다. 검색/접기는 onSource·부모 질문/제안/소스 상태를 변경하지 않고 서버 쓰기를 실행하지 않는다. 검색 입력은 busy에 잠근다. 업무 이름은 탐색 안내이며 최신 업무 설명/열 검증은 선택 후 기존 접힌 조회를 따른다.

SQLite+실제 SourceAccessService로 두 소유자/NULL 소유·최신/손상/미등록·최소 응답·읽기 불변/쿼리 경계를 확인한다. FE 검색/동명이름/정규화/선택 유지·미지원·늦은 부모목록 변경과 기존 생성/재사용/업무설명 회귀·type/lint/build를 확인한다. 공통 입력36px/도구32px·좁은 폭 줄바꿈을 사용하며 Ego/실모바일 실측은 사용자 제어권 경계를 유지해 미실행으로 남긴다. 신규 스키마·의존성·조직 공유/공식 승인/LLM 적용은 범위 밖이다.

## 후속 단위: Studio 저장 지표 찾기와 계산 기준 확인

FR015·BR050-01/02의 재사용 지표 탐색을 보완한다. 기존 소유 소스 `/bi/metrics` 응답만 사용하며 StudioCreate의 체크 선택을 독립 컴포넌트로 옮긴다. 목록 이름/ID/정의 버전을 구분하고 접힌 검색은 이름·ID·단위·집계/열/분모/가중치에 NFKC·소문자·공백 정규화 부분검색을 적용한다. 선택된 지표는 검색 불일치에도 남기고 결과 수와 선택 수를 구분한다. 필터/접기/읽기 전용 details는 부모 콜백/질문·제안/저장 준비를 변경하지 않는다. 실제 체크 변경만 종전 invalidate+selectedMetricIds 연결을 유지한다. 소스가 바뀌면 검색 상태를 초기화한다.

각 지표의 접힌 계산 기준은 구조화 definition의 aggregation·column·denominatorColumn·weightColumn·scale·unit만 출력한다. 수식을 새로 실행/추론하거나 SQL·기타 정의를 렌더하지 않는다. 비율/가중 평균은 원본 필드 의미를 구분해 보여주며 누락된 기준은 미확인으로 안내한다. 공식 승인/현재 데이터 수치 정확성/전체 UC050 완료를 뜻하지 않는다. 미등록 단위는 미지정으로 표시한다. busy는 선택/검색을 잠그며 기존2열→599px이하1열/264px 내부스크롤·키보드 포커스를 보존하고 공통 입력36px·도구32px/본문14px·보조12px와 줄바꿈을 사용한다. 새로운 API/DB/의존성은 없다.

FE 선택기 회귀로 동명이름/검색·선택 보존/동일 입력 후 콜백0·definition 필드 표현·빈 결과/미확인·busy·다른 소스 경계를 확인한다. StudioCreate에서 실제 선택→selectedMetricIds 제안 요청→검색에도 질문/계산 미리보기·저장 버튼 유지→체크 변경 시 미리보기 해제/질문 보존을 검증한다. 기존 생성/업무설명/재사용 회귀와 type/lint/build를 실행하며 BE 수치/저장/실제 LLM은 변경 없으므로 기존 증거와 구분한다. Ego/실모바일 실측은 이전 사용자 제어권 경계를 유지해 미실행으로 남긴다.
