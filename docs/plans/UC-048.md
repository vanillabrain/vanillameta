# UC048 — 새 생성 질문·소스 새로고침 복구

P2/P3·FR009/NFR004. 저장 확인 요청이 없는 새 생성 화면의 미전송 질문·소스가 reload로 사라지는 공백을 보완한다. 기존 auth scope의 탭 저장소에 별도 suffix로 질문/소스ID만24h/8KiB/2000자 보관한다. SQL/파일/미리보기/제안/토큰은 보관하지 않는다. 목록 권한 조회 후 복구/폐기만 제안하고 명시 복구에서 소스 구조를 다시 확인한다. 저장 확인UC032가 우선하며 proposal/source 지정 링크의 문맥은 덮지 않는다. 실패·늦은 응답·새 로그인은 기존 세대 경계를 따른다. 자동AI/업로드/저장0·저장 성공 정리·기록손상/한도/보관불가 회귀를 확인한다. 기존 Notice/32px 버튼을 재사용한다. 기존 로그인 차단으로 실제Ego/3폭 검증은 별도BLOCKED로 유지하며 회귀/type/lint/build와 명세증빙 후 commit/push한다. 고객파일럿·실기기수용은 별도다.

## A3 — 다른 소스에서 질문 이어가기

원래 소스에 접근할 수 없을 때도 사용자가 본인 목록의 다른 소스를 선택한 뒤 별도 버튼으로 질문만 복구한다. 선택만으로 원래 기록을 바꾸지 않는다. 버튼은 현재 소스 profile이 확인되고 원래 소스와 다르며 입력이 비어 있을 때 제공한다. 명시 복구에서 새 소스를 다시 검증하고 성공한 경우에만 질문·새 sourceId를 보관한다. 실패는 원래 기록/빈 입력 유지·자동POST0이다. 이전 지표/제안/계산을 새 소스에 재사용하지 않는다. 회귀로 성공/실패 재시도/현재 입력 우선을 확인하며 실제UI는 기존 로그인 gate를 유지한다.

## A3 후속 — 제안·저장 연결 검증

다른 소스로 질문 복구 후 재마운트→명시 원질문 복구→새 소스 제안/미리보기→비공개 저장을 컴포넌트 통합 회귀로 확인한다. 저장503/재마운트는 UC032 확인 우선→자동POST0→같은 request body 재확인→기록 정리를 검증한다. 이전 소스 미리보기 응답은 차단하고 질문을 보존한다. 실제 서버/모델/DB 영수증·브라우저reload가 아닌 mock API 회귀임을 구분한다. 실패 없으면 제품 코드 변경 없이 기존 타입/빌드를 재사용하고 변경 린트·회귀·명세 검사만 수행한다.
