# UC051 직원 검색·조직 이동

Status: Draft

## 목표와 범위

FR016/FR017/NFR005/NFR007·TC050 E02/E03 후속이다. 현재 조직 admin은 로그인 ID·팀·내부 직원 번호를 검색한다. 다른 조직/이메일/비밀정보는 검색하지 않는다. 검색은 읽기 전용·20명 cursor·100자 제한이며 %, \_도 문자 그대로 검색한다.

조직 이동은 직원 본인 동의 → 대상 조직 admin 수락 → 현재 조직의 다른 admin 최종 이동이다. 두 관리자는 코드를 명시 조회해 대상 직원·소속·팀·양쪽 버전을 확인한다. 15분 무작위 코드의 hash만 저장하고 발급 당시 계정 epoch·현재 소속을 고정한다. 수락 시 대상 팀(100자)과 역할 member를 고정한다. 관리자가 읽은 수락자/epoch/팀/대상 버전의 reviewBasis를 최종 요청에 연결하며 재수락 내용이 달라지면 조직 버전이 같아도409다. 관리자 승격은 별도 기존 관리 흐름이다. 발급/철회는 본인만, 수락은 대상 조직 admin만, 최종 이동은 현재 조직의 다른 admin만 가능하다. 코드/승인·양쪽 조직 version·현재 계정/JWT epoch가 달라지면 쓰기 없이 거절한다. 수락은 권한을 주지 않고 최종 이동만 원자적으로 수행한다.

## 보존·회수 계약

자료 소유 ID·원본 파일·소스/지표/대시보드·Studio 문서·독립 사본·공개 게시 snapshot·과거 영수증/감사는 수정하거나 삭제하지 않는다. 게시/대시보드 가용성은 현재 소스·게시 권한에 따라 달라지며 보존이 계속 열람을 보장하지 않는다. 현 구조의 조직은 소유자의 현재 소속에서 계산되며 자원 자체를 특정 조직에 귀속시키는 기능은 없다. 이동한 직원의 소유권은 개인 계정에 남고 대상 조직 구성원/admin에게 자동 공개·이관되지 않는다. 이전 조직이 직원 소유 자료를 계속 이용해야 하는 업무 이관은 이번 범위에서 자동 수행하지 않는다.

최종 이동은 이전/새 조직의 버전을 CAS 증가시키고 소속을 대상 조직/member/수락 팀으로 바꾼다. 계정은 활성 유지, authVersion 증가·jwtId 제거로 종전 access/refresh를 회수한다. 이전·대상·과거 조직을 포함한 대상 계정 관련 직접 grant는 read/edit/publish/export=false 및 version 증가, 개인 delivery는 active/allowCopy=false 및 version 증가, 소유자의 group grant/delivery도 회수한다. 직원의 모든 명시 그룹 가입(비활성·과거 조직 포함)을 해제하고 관련 그룹 version을 증가시킨다. 관계의 과거 영수증은 현재 권한으로 재사용하지 않는다. 조직을 되돌아와도 종전 권한을 자동 복구하지 않는다. 같은 팀명은 자동 그룹 가입이 아니다.

## 구현·검증 계획

- 별도 staff controller/service·hash 동의 행과 additive migration. 기존 enrollment와 분리한다.
- 직원 목록 서버 검색, 별도 접힌 조직 이동 화면. 수정 중 질문/기존 UI를 건드리지 않는다. 코드의 브라우저 영속 저장은 하지 않는다.
- SQLite 서비스/HTTP/컴포넌트: 격리 검색/문자 escape·권한·자기 이동 금지·만료/epoch/조직 version 충돌·취소·자료 보존·반복 요청.
- 로컬 Docker MySQL: 기존 소유 fixture gate를 사용한 별도 staff lane에서 실제 서비스·보호 HTTP, 양쪽 조직 CAS·동시 finalize·오래된 직접 권한/그룹 writer·강제 rollback·토큰 회수·그룹/직접 권한·자료/게시 보존 확인. 운영 DB에는 적용하지 않는다.
- full TC050·운영 migration·실기기·사람 업무 수용은 별도이며 선택 검증을 전체 완료로 계산하지 않는다.

## 종료 조건

설계/UC/TC/증빙 동기화, 선택 MySQL·SQLite·FE 검증과 type/lint/build, 독립 검토, 민감정보 제외 확인 후 기존 작업 브랜치 commit/push다. 응답 유실은 현재 소속/요청 상태 조회로 확인하며 자동 중복 이동하지 않는다.

## 실제 화면 후속 — 2026-10-19

Ego 단일 공간101에서 격리 QA 환경의 본인/양쪽 admin 로그인과 검색→동의→수락→최종 이동→재로그인을 검증한다. 실제 UI/XHR·390/768/1440의 컨트롤 높이/폰트/정렬·넘침을 기록하며 기존 MySQL 선택 검증을 UI MySQL 증거로 혼동하지 않는다. 발견한 검색 입력/버튼 top 차이28px는 설명문을 컨트롤 행 밖으로 분리해 수정한다. 취소·수락 변경409 후 재검토와 비대상 자료 보존은 추가 검증 범위를 명시한다.

실제 HTTP에서 미등록 상태 null의 Nest 기본 처리가200/빈 본문이 되는 공백을 발견했다. 상태 GET은 JSON content-type/명시 null 또는 상태 object 계약을 지키며 비어 있는 응답을 FE가 임의 성공 처리하지 않는다. 보호 HTTP의 초기 상태·발급·철회 후 null을 회귀 검증한다.

운영과 같은 HttpExceptionFilter의 data.message를 직원 오류 도움에서 읽도록 연결한다. 테스트 앱에도 같은 필터를 등록하고400/403/409의 구조화 사유를 검증하며 임의 객체의 본문/내부 필드를 오류 문자열로 노출하지 않는다.

명시4xx 거절은 이동 없음/재검토 안내, 통신 유실·5xx·성공 응답 shape 미확정은 현재 상태 확인 안내로 구별한다. 두 경우 모두 자동 재전송하지 않고 기존 조직/수락 기준을 다시 확인한다.
