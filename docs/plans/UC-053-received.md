# UC053 받은 자료 목록과 열기

## 목표·범위

FR021/022/NFR005/008의 수신자 도착점이다. 직원 조회 공유를 받은 본인이 현재 열람 가능한 대시보드를 발견하고 기존 보호 경로로 연다. [조회 공유](UC-053-deliveries.md)의 직접 권한 독립/read-only 계약을 유지한다. 독립 사본 전달·동적 그룹/일반 소유 member 공유·export는 후속이며 전체 FR021 완료로 축소하지 않는다.

## 서버 계약

GET `/enterprise/deliveries/dashboard/received?afterId=...`는 JWT의 본인 actor만 사용한다. 양의 정수 cursor를 검증하고 active User/현재 Membership를 재조회한다. 현재 조직·active delivery·양쪽 활성/현재 조직·현재 유일 소유권 binding을 query로 대조한다. dashboardId 오름차순으로21개 후보를 읽어20개 구간만 처리한다.

각 후보는 기존 SourceAccess.dashboard(read)로 모든 소스/자원 권한을 다시 검증하고 성공한 행에만 최신 제목(최대300 UTF16 units)·dashboardId·공유 version을 투영한다. source 거절은 항목을 숨기며 DB/다른 오류는 전체 요청을 실패시킨다. SQL·정의·소스 정보·송신자 식별값·익명 링크/토큰·연결 정보는 반환하지 않는다. 읽기·페이지 이동은 쓰기0다.

`nextAfterId`는 마지막 표시 행이 아니라 마지막 검사 후보의 번호다. 모두 숨겨진20행 뒤에도 cursor가 진행하며 후보를 건너뛴 제목/내용은 공개하지 않는다. 동시 공유·회수는 최신 조회/열 때 다시 반영하며 목록을 현재 권한의 영구 증명으로 쓰지 않는다.

## 화면·복구

기존 조직 화면의 admin/member 공용 접힌 ‘받은 자료’를 추가한다. 열기→GET·명시 다시 읽기/다음 구간→기존 `/dashboard/:id` 열기다. 링크는 받은 ID에서만 구성하며 대상 화면의 기존 서버 권한 검사를 따른다. 새로운 공유 쓰기/알림 읽음/복제를 자동 실행하지 않는다.

32px 도구·14px 제목·12px 보조·flex-wrap/min-w-0/break-words를 적용한다. 페이지 읽기 실패는 낡은 목록/다음 cursor를 숨기고 첫 구간 재조회를 제공한다. 닫기·조직/계정 변경·unmount 뒤 늦은 응답을 무시한다. 새로고침 후 서버 목록을 읽고 데이터 목록을 브라우저에 영구 저장하지 않는다. 빈 구간+다음 cursor와 최종 빈 목록을 구분한다.

## 검증·종료 기준

SQLite 실제 공유→받은 목록→회수/직접 grant/소스 회수·active/조직/소유권 변화·제목/정의 응답 경계·읽기 쓰기0·숨겨진20행 다음 구간·잘못된 cursor·JWT static route 우선순위를 검증한다. FE 명시 열기/페이지·오류 후 첫 구간·빈 구간·불완전 응답·닫기/계정 변경 늦은 응답·안전한 기존 링크를 확인하고 type/lint/build/기존 core를 실행한다. 실제 Ego96은 사용자 제어권 대기 중이므로 새 UI/390·768·1440 실측·MySQL/운영·실휴대폰/사람 수용은 NOT_RUN이다.
