# Studio 미저장 제안 후속 질문

## 범위와 순서

1. 만료 제안 저장 거절 수정/기록을 develop-v2에 push(ca8305ae).
2. 생성 화면의 제안을 기준으로 선택 블록 수정 또는 새 블록 추가 → 전체 미리보기 → 명시 비공개 저장.
3. 첫 화면의 Studio 진입을 데이터 선택과 질문 중심으로 연결. 파일/샘플/기존 소스는 동일 생성 화면 사용.
4. 신규 조건만 실제 브라우저/모바일/키보드 검증. 기존 통과 조건 재사용. gpt-6-luna 유지, VoiceOver BLOCKED.

## 계약

- 기존 POST /studio/proposals에 parentProposalId, targetBlockIndex(0-based 또는 'append')를 선택적으로 추가한다. 둘은 함께 필요하다.
- 부모는 서버 캐시에서 소유자/소스/만료/소스 revision을 확인한다. 클라이언트 정의/SQL을 신뢰하지 않는다.
- 모델에는 서버 부모 정의와 대상 블록을 전달하고 변경 블록 하나만 반환받는다. 서버가 나머지 블록/순서/대시보드 제목을 그대로 합친다. 추가는 끝에 1개, 전체 최대 6개.
- 새 proposalId로 별도 불변 제안을 만들며 기존 부모는 수정하지 않는다. 미리보기는 합친 전체 블록을 기존 서버 컴파일러/DuckDB로 계산한다.
- 실패/취소 시 이전 성공 미리보기 유지. 저장 도중/결과 불명확 재시도 중에는 변경 요청을 차단한다. 소스/지표 선택 변경은 제안을 무효화한다.
- 저장은 최신 확인 제안 ID로 기존 원자 저장/같은 requestId 재시도 경로를 재사용한다. 미리보기는 메타데이터를 쓰지 않는다.
- 편집기 안 run-bound 생성은 동일 서버 제안의 후속 생성 화면으로 연결한다. 원래 run의 저장 대상을 조용히 교체하지 않는다. 만료/권한 거절 시 안내하고 새 요청을 요구한다.
