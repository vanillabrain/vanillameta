# UC054 출력 결과 본인 알림

## 목표와 경계

FR022/023·NFR005/007/008: 원자 저장한 출력 작업의 완료/실패/취소 사건을 기존 조직 본인 알림함에 연결한다. 작업 접수/진행 중은 별도 알림으로 반복하지 않는다. 전체16개 요건·비교 리포트·보관/복원·운영 수용은 계속 열린다.

## 설계

- 기존 `export.ready/failed/cancelled` 감사 사건을 읽기 투영한다. `resourceId`는 export 작업 ID이고 `version`은 그 사건의 작업 버전이다. 별도 알림 쓰기/worker/외부 발송 없이 원자 완료/실패 저장 결과만 목록에 나타난다.
- 현재 활성 계정·현재 조직에 속한 본인 subject와 actor가 모두 일치해야 한다. 과거 조직/타인·그룹 subject 오인 사건을 노출하지 않는다. 새 읽음/목록 제거는 기존 단방향 state만 변경한다. 감사/작업/파일을 지우거나 다시 실행하지 않는다.
- 응답은 기존 공통 최소 필드와 `resourceKind: export`, `eventType: ready|failed|cancelled`다. 소스명/CSV/SQL/고정 조건/오류 상세/게시 링크를 포함하지 않는다. 알림은 과거 사건이며 현재 작업 상태·파일 유효성·권한을 증명하지 않는다. 실제 작업/파일 API는 현재 권한·인증·만료를 다시 검사한다.
- 실패 상태 저장 자체가 실패하면 확정 실패 사건도 없으므로 알림을 만들어 성공으로 추정하지 않는다. lease 중단 복구는 기존 작업 조회/명시 실행을 따른다. 중복 실행/반복 취소의 무전이에는 새 감사/알림이 없다.
- UI는 접힌 기존 본인 알림함의 파일 작업 번호/과거 결과/버전만 추가한다. 일반32px 도구·14px 본문·wrap/min-w-0을 유지하며 자동 실행/다운로드는 없다.

## 검증·종료 조건

실제 SQLite/JWT 알림 수신자/조직/읽음·목록 제거와 실제 DuckDB 출력 완료/실패/취소→원장 투영, 실패 rollback·중복 요청·알림 조회 실패 뒤 파일 보존·현재 export 회수 후 파일 차단을 검사한다. FE 최소 응답·유형 경계/표시·기존 알림 회귀와 type/lint/build를 확인한다. 실제 Ego96 사용자 제어권/새 모바일 실측·MySQL/실휴대폰/운영·사람 수용은 미실행을 유지한다.

알림 API도 JWT epoch를 큐 진입 후 재검사하고 no-store로 응답한다. 오래된 epoch의 조회/읽음은 상태 쓰기0·401이며 새 epoch는 정상 조회된다. 실제 JWT HTTP의 export 사건 조회/읽음/제거와 no-store도 선택 검증한다.
