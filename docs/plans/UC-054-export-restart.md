# UC054 — 출력 작업 프로세스 재시작 복구

상태: Draft. FR023·NFR005~008의 제한된 실행 검증이며 전체16개/TC050 수용은 Open이다.

## 목표와 현재 차이

기존 영속 집계 CSV는 UUID 접수·CAS/5분 실행 임대·원자 부분 저장·현재 접근권 검사를 구현했다. 종전 재시작 검증은 같은 SQLite 연결의 서비스 재생성이므로 실제 프로세스 종료를 증명하지 않는다. 이번에는 격리 Docker MySQL에서 실제 별도 프로세스 종료와 새 프로세스의 동일 작업 재조회를 확인한다. 전체 앱 화면은 별도 로컬 런타임에서 확인하고 DB/실행 범위를 구분한다.

## 계약

- 접수/완료 작업과 고정 CSV는 프로세스 교체로 새 작업이 되거나 사라지지 않는다.
- 실행 중 프로세스가 종료되어도 GET은 SQL 재실행이나 상태 쓰기를 하지 않는다. 살아 있는 임대에서는 재실행하지 않으며 만료 후 명시 실행만 새 시도를 얻는다.
- 같은 버전의 동시 실행은 한 시도만 차지한다. 이전 시도는 새 시도의 부분 파일/완료를 덮거나 삭제하지 못한다.
- CSV 부분/체크섬/완료 감사는 같은 확정 결과에 속한다. 실패한 저장의 일부만 노출하지 않는다.
- 재시작 후에도 현재 조직·소스 export 권한·요청 인증 세대를 검사한다. 고정 결과 보존과 다운로드 허용은 별도다.
- 5분 임대를 시험에서 가속하거나 집계 실행을 제어하면 그 방법을 증빙에 밝힌다. 운영 코드에 테스트용 우회나 자동 실행을 추가하지 않는다.

## 변경과 검증

1. 소유가 확인된 임시 MySQL 전용 lane과 자식 프로세스 시험을 추가한다. 실제 PID 교체·메타데이터/파일 영속성·동시 실행·실패/권한 경계를 검사한다.
2. 기존 화면의 이전 작업 읽기→상태 확인→명시 실행→CSV 다운로드를 Ego에서 확인한다. 전체 API 프로세스 재시작도 로컬 소유 런타임으로 확인하되 MySQL 자식 프로세스 시험과 혼합 집계하지 않는다.
3. 390/768/1440px 화면에서 줄바꿈·넘침·버튼 크기/정렬을 측정하고 화면을 확인한다. 확인된 결함만 수정한다.
4. UC054/A1·BR054-01/02, TC050, 수용 잔여표와 실행 증빙을 동기화하고 별도 검토 후 commit/push한다.

대상: `scripts/verify-semantic-mysql.cjs`, export job 시험/전용 fixture, 필요 시 `ExportJobs`와 관련 시험. 실제 휴대폰·운영 migration/장애 복구·전체 리포트 정답/역할 행렬·사람 수용은 이 단위의 종료 조건에 포함하지 않는다.

## 실행 중 확인한 최소 보완

실제 전체 API 재시작에서 가입 후 detached 샘플 생성과 큐 밖 LoginHistory 자동 transaction이 겹쳐 후속 접수까지 SAVEPOINT 안에 남는 소실을 확인했다. 로그인/사용자 조회/공유 기록 저장을 같은 큐에 참여시켜 성공 응답 전 commit 경계를 복원한다. 별도 검토에서 확인한 최종 부분 저장 중 TTL 경과와 그룹 권한 회수 경합은 최종 expiresAt CAS와 Source/Metric 잠금 후 접근권 재조회로 막는다. 화면의 최신 상태 조회 실패도 이전 버전 재실행/다운로드가 가능하지 않게 보완한다.
