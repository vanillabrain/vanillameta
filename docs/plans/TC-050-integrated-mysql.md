# TC050 — 최신 완료 기준과 MySQL 전체 앱 통합

상태: Draft. FR014~025/NFR005~008의 전체 수용은 Open이다. MK AI 연동·기업 식별 자료·운영 배포는 제외한다.

## 목표와 종료 범위

누적 후속 문단으로 해결한 작업이 잔여표에 남는 문제를 정리한다. 구현·선택 검증·실제 업무/운영 수용을 나누며, 새로운 기능 수나 테스트 수로 전체 완료율을 만들지 않는다. 이어서 격리 Docker MySQL의 실제 Nest HTTP 앱과 화면으로 같은 데이터의 연결→질문/제안→저장→직접 공유→독립 복제→출력→개인 보관/복원을 연결한다. 통합에서 확인한 결함만 수정한다.

## 고정 계약

- 컨테이너·DB·파일·계정은 새로 만든 합성 fixture에 한정하며 사용자 환경을 재사용/정리하지 않는다. 랜덤 소유 표식 확인 후 본 실행 자원만 정리한다.
- 전체 HTTP 앱이 실제 MySQL metadata와 native DuckDB를 사용해야 한다. service-only 시험이나 SQLite 화면으로 이 기준을 대체하지 않는다.
- 동일한 source/metric/조건을 고정하고 숫자·CSV는 별도 원본 합계와 대조한다. 수신자 독립 사본은 자기 소스의 정답과 일치하고 원본·권한은 보존한다.
- 공유는 같은 조직의 명시 수신자에 한정한다. 익명 공개를 만들지 않는다. 타 조직/회수 경계와 현재 source 권한을 검사한다.
- 실LLM을 호출하지 않는 saved metric fast path/모델 fixture는 그 한계를 명시한다. 고객 업무 정답·실LLM 전체 수용·실휴대폰/운영을 자동 통과시키지 않는다.
- 대표 Ego 화면과390/768/1440의 크기·정렬·넘침을 확인하고, 서버 재시작 후 저장본/작업과 원본 보존을 재확인한다.

## 작업

1. `enterprise-completion`과 `enterprise-acceptance-audit`의 현재 잔여표를 최신 인계/탈퇴·공유/복제 복구·export 재시작 증빙에 맞춘다. 역사 기록과 현재 표를 구분한다.
2. 기존 소유 Docker 검증 방식을 재사용해 실제 HTTP/프런트용 전용 MySQL 실행기를 준비한다. 초기 schema/synchronize와 운영 migration을 구분한다.
3. HTTP 전체 여정·Ego 대표 실제 화면을 실행하고 원본/사본·파일/감사를 검증한다. 실패가 있으면 최초 증거를 보존하고 해당 경로만 수정/재검증한다.
4. 실행 범위/미실행·최신 TC050 표·수용 잔여를 동기화하고 별도 검토 후 commit/push한다.

종료 조건은 이 통합 slice의 증빙과 최신 잔여표다. 정책 미확정·고객 입력 부재·운영/기기 수용을 임의 완료로 바꾸지 않는다.
