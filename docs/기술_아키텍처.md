## 🔧 백엔드 아키텍처 상세

### 1. 계층 구조

```
src/
├── main.ts                 # 애플리케이션 진입점
├── app.module.ts           # 루트 모듈
├── common/                 # 공통 기능
│   ├── entities/          # Base Entity
│   ├── enum/              # 공통 열거형
│   └── transformers/      # TypeORM 변환기
├── auth/                   # 인증 모듈
│   ├── strategies/        # Passport 전략
│   └── guards/            # 인증 가드
├── connection/             # DB 연결 관리
│   └── knex-dialects/     # 커스텀 DB 방언
└── [domain]/               # 도메인별 모듈
    ├── entities/          # 엔티티
    ├── dto/               # DTO
    ├── *.controller.ts    # 컨트롤러
    └── *.service.ts       # 서비스
```

### 2. 데이터베이스 연결 아키텍처

#### 이중 연결 시스템

1. **TypeORM**: 애플리케이션 메타데이터 관리

   - User, Dashboard, Widget 등 애플리케이션 데이터
   - 마이그레이션 및 스키마 동기화

2. **Knex.js**: 사용자 데이터베이스 동적 연결
   - 런타임 DB 연결 생성
   - 다양한 DB 타입 지원
   - SQL 쿼리 빌더

### 3. 인증 및 보안

#### JWT 토큰 구조

```json
{
  "userId": 1,
  "userEmail": "user@example.com",
  "iat": 1234567890,
  "exp": 1234567890
}
```

#### 인증 플로우

1. 로그인 요청 → LocalStrategy 검증
2. JWT 토큰 발급 (Access + Refresh)
3. 요청 시 JwtAuthGuard로 검증
4. 만료 시 Refresh Token으로 갱신

### 4. API 설계 패턴

#### RESTful 엔드포인트

```
GET    /api/widgets          # 목록 조회
GET    /api/widgets/:id      # 단일 조회
POST   /api/widgets          # 생성
PATCH  /api/widgets/:id      # 수정
DELETE /api/widgets/:id      # 삭제
```

#### DTO 검증

## 🎨 프론트엔드 아키텍처 상세

### 1. 디렉토리 구조

```
src/
├── api/                    # API 서비스 레이어
├── components/             # 재사용 컴포넌트
├── contexts/               # React Context
├── pages/                  # 페이지 컴포넌트
├── router/                 # 라우팅 설정
├── widget/                 # 위젯 시스템
│   ├── modules/           # 차트 컴포넌트
│   ├── settings/          # 설정 UI
│   └── wrapper/           # 래퍼 컴포넌트
└── utils/                  # 유틸리티 함수
```

### 2. 상태 관리 아키텍처

#### Context 계층 구조

```
Application State
├── AuthContext         # 인증 상태
├── LoadingContext      # 로딩 상태
├── AlertContext        # 알림 상태
└── LayoutContext       # 레이아웃 상태
```

#### 상태 흐름

1. **전역 상태**: Context API
2. **컴포넌트 상태**: useState/useReducer
3. **서버 상태**: API 호출 후 로컬 상태로 관리

### 3. 위젯 시스템 아키텍처

#### 위젯 생명주기

   ├── 데이터 페칭

2. WidgetViewer
   ├── 차트 타입 결정

## 🚀 배포 아키텍처

### AWS 인프라 구조

```
┌─────────────────────────────────────────┐
│           CloudFront CDN                │
└────────────────┬───────────────────────┘
                 │
    ┌────────────┴────────────┐
    │      S3 Bucket          │
    │  (Frontend Assets)      │
    └─────────────────────────┘

┌─────────────────────────────────────────┐
│          API Gateway                    │
└────────────────┬───────────────────────┘
                 │
    ┌────────────┴────────────┐
    │    Lambda Functions     │
    │    (NestJS Backend)     │
    └────────────┬────────────┘
                 │
    ┌────────────┴────────────┐
    │      RDS MySQL          │
    └─────────────────────────┘
```

### Serverless 설정

- **Frontend**: S3 정적 호스팅 + CloudFront
- **Backend**: Lambda + API Gateway
- **데이터베이스**: RDS MySQL (프로덕션)

## 🔒 보안 아키텍처

### 1. 인증/인가

- JWT 기반 상태 비저장 인증
- Role 기반 접근 제어 (추후 구현 예정)
- Refresh Token으로 세션 연장

### 2. 데이터 보안

- HTTPS 통신 필수
- 민감한 정보 환경변수 관리
- SQL Injection 방지 (파라미터 바인딩)

### 3. API 보안

- CORS 정책 설정
- Rate Limiting (구현 예정)
- 입력 값 검증 (class-validator)
