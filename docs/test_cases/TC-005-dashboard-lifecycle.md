# Test Case: Dashboard Lifecycle

## Overview

**ID:** TC-005
**Goal:** 운영 담당자가 한 대화에서 제작·블록 편집·게시하고 수신자가 새 데이터로 복제한다.
**Priority:** Critical
**Status:** Reviewed

## Roles

- 운영 담당자: 제작·직접/AI 편집·저장·게시·공유 중지.
- 공유 수신자: 게시 조회·복제·자신의 소스 매핑.

## Preconditions

- Rill 공식 auction sample manifest와 독립 정답을 사용한다. 요청634513000/평균 Bid Floor5.571238676526892.
- 다른 계정과 열 이름을 바꾼 동일 값의 새 소스, 필수 열 누락 파일을 준비한다. 실행 전 실제 fixture ID를 증빙에 기록한다.
- 기존 환경·로그인·데이터와 지정 LLM을 유지한다. 인증 값을 문서에 기록하지 않는다.

## Validation

1. BR-001/002: 실LLM 요청·원본 조건·canonical 지표/차원과 저장 정의 대조. 모호한 계산식 A1은 질문 전 저장/게시 없음.
2. BR-003: 직접 편집→AI 수정→reload에서 대상 외 ID/배치 동일. 모바일 이동/resize 수행, 가로 넘침0px, 긴 제목/로딩/오류 상태의 크기·정렬 확인.
3. BR-004/005: 게시 버전/데이터 모드 명시, 원본 초안·게시·복제본을 각각 비교. 타인 원본 소스 및 인증 비밀 반환 없음, 누락 매핑 A4 차단, 중지 링크 A5 거절.
4. BR-006/A2/A3: 저장 경합·제한시간·미지원 모델·게시 실패를 주입해 이전 결과 보존과 재시도 중복0개를 확인한다.
5. Rill: 같은 조건의 계산/필터/OS28 결과 비교. Rill과 VM의 시간 이동 차이는 별도로 기록한다. Rill은 대화/게시/복제 전체 여정의 증거가 아니다.

## Postconditions

- 검증 정의·게시/복제 fixture와 캡처는 증빙으로 보존한다. 사용자 데이터 삭제는 하지 않는다.
- 전체 여정의 현재 실행 상태는 not_run이다. 관련 UC-001~004 통과는 이 TC 전체 통과를 뜻하지 않는다.
