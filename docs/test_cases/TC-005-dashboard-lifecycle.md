# Test Case: Dashboard Lifecycle

## Overview

**ID:** TC-005
**Goal:** 운영 담당자가 한 대화에서 제작·블록 편집·게시하고 수신자가 새 데이터로 복제한다.
**Priority:** Critical
**Status:** Reviewed

## Roles

- 운영 담당자: 제작·직접/AI 편집·저장·게시·공유 중지.
- 공유 수신자: 게시 조회·복제·자신의 소스 매핑.

## Preconditions

- Rill 공식 auction sample manifest와 독립 정답을 사용한다. 요청634513000/평균 Bid Floor5.571238676526892.
- 다른 계정과 열 이름을 바꾼 동일 값의 새 소스, 필수 열 누락 파일을 준비한다. 실행 전 실제 fixture ID를 증빙에 기록한다.
- 기존 환경·로그인·데이터와 지정 LLM을 유지한다. 인증 값을 문서에 기록하지 않는다.

## Validation

1. BR-001/002: 실LLM 요청·원본 조건·canonical 지표/차원과 저장 정의 대조. 모호한 계산식 A1은 질문 전 저장/게시 없음.
2. BR-003: 직접 편집→AI 수정→reload에서 대상 외 ID/배치 동일. 모바일 이동/resize 수행, 가로 넘침0px, 긴 제목/로딩/오류 상태의 크기·정렬 확인.
3. BR-004/005: 게시 버전/데이터 모드 명시, 원본 초안·게시·복제본을 각각 비교. 타인 원본 소스 및 인증 비밀 반환 없음, 누락 매핑 A4 차단, 중지 링크 A5 거절.
4. BR-006/A2/A3: 저장 경합·제한시간·미지원 모델·게시 실패를 주입해 이전 결과 보존과 재시도 중복0개를 확인한다.
5. Rill: 같은 조건의 계산/필터/OS28 결과 비교. Rill과 VM의 시간 이동 차이는 별도로 기록한다. Rill은 대화/게시/복제 전체 여정의 증거가 아니다.

## Postconditions

- 검증 정의·게시/복제 fixture와 캡처는 증빙으로 보존한다. 사용자 데이터 삭제는 하지 않는다.
- 최신 주 여정·선택 오류 실행은 [2026-10-16 통합 증빙](../testing/dashboard-lifecycle.md)을 따른다. 운영/실기기·모든 경합/자연어·타 계정 변경 POST 실제 실행·제품 수용은 별도 Open이다. 관련 UC 단위 통과만으로 전체 수용을 선언하지 않는다.

## Studio 병행 흐름의 단계별 증빙

아래 PARTIAL 판정은 Studio 개별 실행 당시의 범위다. 분석 편집 흐름의 최신 UC023 증빙은 위 링크를 따르며, 서로 다른 UI의 통과를 합쳐 전체 수용을 주장하지 않는다.

- 2026-10-15 T10 핵심 연결 흐름 step1–9는 PASS_SELECTED다. 실제 gpt-6-luna 지정 생성/선택 수정, 직접 편집, 저장·게시·재게시·다른 계정의 명시 UI 복제, 링크 중지와 복제본 유지까지 연결했다. 근거: [T10 기록](../testing/dashboard-studio.md#t10--전체-연결-흐름최종-디자인-회귀--2026-10-15).
- **전체 TC-005는 PARTIAL**이다. T11에서 자연어 복제 준비→명시 매핑 화면 연결을 추가했다. 대화 안에서 매핑·복제 저장까지 끝내는 자동 dispatch는 미지원이며 생성은 별도 `/studio/new` 진입이다. Studio 범주·날짜 공통 범위는 T12/T13의 선택 조건을 확인했으며, 실제 VoiceOver는 BLOCKED다. 목표/기대 결과를 축소해 전체 통과로 처리하지 않는다.
- A1~A4의 기존 하위 실패/복구 변형은 T6~T9 근거와 변경 diff에 따라 재사용했다. 새 전체 실패 주입·live Rill UX 재실행·운영 부하는 NOT_RUN이다.
